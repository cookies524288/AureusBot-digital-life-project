# 09 · 术语表

> 用大白话解释本项目里出现的词。

---

## 1. 项目里的名字

| 名称 | 代码名 | 解释 |
|---|---|---|
| AureusBot | `aureus` | 项目的对外名称（D47）。代码里的包名、命令和环境变量仍用 `aureus`，暂不改 |
| 核心 | `core` | 常驻运行的主程序，持有它的全部状态。只能有一个 |
| 身份 | `identity` | 它是谁、想成为谁：身份事实和四层人设 |
| 身份事实 | `facts` | 给程序用的结构化信息：名字、性别、出生日期、用户和用户的账号 |
| 不变人格 | `immutable` | 用户写的基础人设，它自己永远不能改；注入全部器官 |
| 可变人格 | `mutable` | 它想成为的样子，随真实经历慢慢变化；注入全部器官 |
| 行为风格 | `behavior_style` | 它怎么做事：什么时候开口、怎么回应；注入规划器 |
| 表达风格 | `expression_style` | 它怎么说话：语气、句子长短、口头禅；注入规划器和回复器 |
| 注入 | — | 把人设、状态等内容拼进给某个器官的提示词里 |
| 身体 | `body` | 挂在真实信号上的身体感受 |
| 精力 | `energy` | 今日剩余预算占今日额度的比例 |
| 疲劳 | `fatigue` | 近期负荷：调用量、并发、显卡占用 |
| 压力 | `stress` | 失败、超时和积压的程度 |
| 社交需求 | `social_need` | 距离上次有效对话多久，越久越高 |
| 睡眠 | `sleep` | 停机或电脑休眠的时长；也指夜间整理的时段 |
| 激素 | `hormones` | 几分钟尺度的短期情绪：被事件触发、按半衰期消退 |
| 怒气 / 愉悦 / 低落 / 惊讶 | `anger` / `joy` / `hurt` / `surprise` | 初版的四种短期情绪 |
| 同理心 | `empathy` | 判断出别人（人或动物）的情绪后，自己也生出同样的情绪；好感越高越强。是激素的一种触发来源 |
| 好感 | `affinity` | 关系印象里的一项，0 到 1：它有多喜欢对方 |
| 半衰期 | — | 浓度降到一半所需的时间。半衰期 10 分钟，就是 10 分钟后剩一半，20 分钟后剩四分之一 |
| 心情 | `mood` | 几小时到几天的整体基调，由激素的累积、行动成败和身体状态决定 |
| 时间线 | `timeline` | 唯一一条只追加的经历记录 |
| 日记 | `diary` | 每天从时间线整理出的总结，Markdown 格式 |
| 可见范围 | `visibility` | 一条记录"谁可以知道" |
| 记忆 | `memory` | 从经历中沉淀出的长期记忆 |
| 人际 | `people` | 人物档案、账号关联和关系印象 |
| 人物档案 | `person` | 认识的每个人一份，按（平台，账号 ID）认人；用户也是其中一份 |
| 联系人 | `contact` | 除用户以外的人物档案；新账号就是新的联系人 |
| 技能 | `skills` | 学会的做事方法 |
| 心跳 | `heartbeat` | 常驻主循环，每一拍决定接下来做什么 |
| 注意力 | `attention` | 决定此刻专注哪件事、提示词里放什么 |
| 收件箱 | `inbox` | 所有待处理事项的队列 |
| 上下文 | `context` | 每次调用大模型时给它看的全部内容 |
| 日程 | `agenda` | 目标、待办、承诺和自己的项目 |
| 兴趣 | `interests` | 它对什么感兴趣：用户写的起始兴趣，加上它从和用户的聊天里按规则改的（D79）；闲时探索从这里挑题目 |
| 收获 | `findings` | 按兴趣探索时读到的一句有意思的东西，记下网页出处；主动联系时可以提起（D79） |
| 器官 | `organs` | 所有大模型调用的统一入口 |
| 规划器 | `planner` | 决定下一步做什么、预期是什么的器官（参考 MaiBot） |
| 回复器 | `replyer` | 把规划器的意图写成拟人的话的器官（参考 MaiBot） |
| 判断 | `judge` | 做分类、打分、提取的器官，比如"这条消息是不是在嘲笑我" |
| 总结 | `summarizer` | 写日记、提炼记忆、整理印象、提出人设调整建议的器官 |
| 看图 | `vision` | 看截图和图片的器官 |
| 行动 | `actions` | 把决定变成真实动作 |
| 外包 | `delegate` | 把专业工作交给其他 agent，再验收结果 |
| 反馈 | `feedback` | 预期对结果，用差距来学习 |
| 预期 | `expectation` | 行动前写下的"我预计会怎样" |
| 自信 | `confidence` | 某类事情的真实历史成功率 |
| 通道 | `channels` | 与外界接触的途径，比如终端、网页、QQ |
| 感知 | `perception` | 通道把外界消息翻译成的统一格式 |
| 安全 | `safety` | 权限、审批、审计、预算上限、急停 |
| 权限等级 | L0–L4 | 行动的风险等级，见 06-safety.md |
| 急停 | — | 立即暂停所有行动 |
| 快照 | `snapshot` | 某个时刻 `data/` 的完整备份 |
| 时间回溯 | — | 从快照恢复时，记入时间线的事件 |
| 单实例锁 | — | 保证同一时刻只有一个它在运行的机制 |
| 观察台 | `monitor` | 查看它内部状态的工具，只读 |
| 实验台 | `lab` | 做可复现开关对比实验的工具 |
| 时钟 | `clock` | 所有子系统取时间的唯一来源，实验时可以加速 |
| 假器官 | — | 实验用的替身器官：返回预设结果、报告虚拟用量，不花钱 |
| 扮演模式 | — | 对照组：关闭所有真实信号机制，只靠人设提示词让大模型自己演状态 |

## 2. 理论相关的词

| 词 | 大白话 |
|---|---|
| 认知内核 | 以持久状态和心跳循环为中心、以大模型为器官的最小认知系统，就是本项目的第一部分 |
| 自我监控 | 系统持续测量自己的真实状态：花费、负荷、故障、时间、做事的结果 |
| 反馈驱动 | 监控到的结果回过头来调节行为，形成闭环 |
| 元认知 | "对自己认知的认知"，比如知道自己对一件事有几成把握 |
| 内感受 | 对身体内部状态的感知，比如人会感觉到饿、累、心跳快 |
| 稳态调节 | 让身体状态保持在合适范围内的调节机制 |
| MAPE-K | 自主计算领域的闭环：监控、分析、计划、执行，围绕共享的知识 |
| 置信度校准 | 说"八成把握"的事，实际也应该八成能做成；越接近，越"校准" |
| ECE | 期望校准误差：衡量"说的把握"和"实际成功率"差多少，越小越好 |
| Brier 分数 | 每次预测（把握 − 实际结果）² 的平均值，越小越好 |
| Godspeed 量表 | 评估人们觉得机器人或 AI 有多"像人"的常用问卷，分拟人性、生命感、喜爱度、感知智能、感知安全五个维度 |
| 对照组 | 用来比较的"普通做法"版本，本项目里是扮演模式 |

## 3. 通用技术词

| 词 | 大白话 |
|---|---|
| API | 程序之间约定好的调用方式。"调用模型 API"就是把文字发给模型公司的服务器，拿回它写的文字 |
| token | 模型计费和计算长度的单位，大约一个汉字算一到两个 token |
| 提示词 | 发给大模型的文字指令和材料 |
| 本地模型 | 在你自己显卡上运行的模型，不花钱，但占显卡 |
| 向量 / embedding | 把一段文字变成一串数字，意思相近的文字，数字也相近。用来做"按意思搜索" |
| MCP | 让 AI 调用外部工具的通用插口，像 USB 接口：两边都支持就能插上用 |
| ACP | 让程序之间互相"派活"的通信规则 |
| Skill | 一个文件夹加一份 SKILL.md 说明书（可以附带脚本），教 agent 怎么做某件事 |
| agent | 能自己调用工具、分多步完成任务的 AI 程序 |
| 适配器 | 把某个平台的消息格式翻译成我们的格式的代码 |
| 异步 / asyncio | 一个线程里同时照看很多件事的写法，等网络的时候不干等 |
| SQLite | 一个文件就是一个数据库 |
| TOML | 一种写配置文件的格式，`名字 = 值`，比 JSON 好读，可以写注释 |
| git / 提交 / 分支 | 代码的存档系统。提交 = 存一次档；分支 = 开一条平行的线做实验，不影响主线 |
| 虚拟环境 / .venv | 项目专用的 Python 环境，装的库只给这个项目用，不影响电脑上的其他程序 |
| 虚拟机 | 在你电脑里虚拟出的另一台电脑，里面出了问题不影响外面 |
| 沙箱 | 隔离的试验环境，代码在里面跑坏了也伤不到外面 |
| 提示词注入 | 在网页、消息里藏指令，骗 AI 去执行 |
| 开关对比 / 消融 | 关掉某个部分，看行为有没有变化，用来证明它有用 |
| 熔断 | 某个东西连续出错时自动暂停它，防止越错越多 |
