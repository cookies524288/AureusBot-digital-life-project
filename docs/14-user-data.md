# 14 · 用户数据与软件分离

> 2026-11-15 新增（D28）。取代 [02-architecture.md](02-architecture.md) 第 8 节里「data/ 放在项目目录里」的做法。

---

## 1. 要解决什么

软件会不断更新，而用户的数据（它的记忆、人设、密钥、数据库）要稳定地留下来。用户还要能方便地备份、导出、导入、换电脑。所以两者必须分开放：升级软件不碰数据，备份数据不带软件。

## 2. 数据根目录

用户数据全部放在一个独立文件夹里，叫「数据根目录」。位置由命令行参数 `--home` 或环境变量 `AUREUS_HOME` 指定；在源码检出里两者都没给时，默认使用项目根目录的 `aureus_home/`（D31）。安装后的程序没有项目根目录时，回退到 platformdirs 提供的系统用户数据目录。用户可用 `--home` 或 `AUREUS_HOME` 指向其他位置。

```text
<数据根目录>/
├── config/
│   ├── aureus.toml        运行配置（不含密钥）
│   ├── identity.toml      身份事实与四层人设（网页设置页改了也会写回这里，D63）
│   └── web_password.argon2  网页口令的哈希；没有这个文件就是默认口令 admin（D63）
├── secrets.vault          加密的密钥库（D36）
├── secrets.key            主密钥，解开密钥库用（D36）
├── .env                   旧的明文密钥，最低优先级回退（D36）
├── data/
│   ├── aureus.db  diary/  memory/  skills/  snapshots/  logs/  experiments/（实验台的结果，每个实验留最近 20 次，不进导出包，D82）
└── manifest.json          记录数据格式版本，升级和导入时用来判断
```

仓库里只放配置示例。初始化命令创建目录，身份和模型条目按需填写。运行配置可以省略，程序启动时读取当前版本默认值。运行配置和模型配置里的有效显式值作为覆盖。设置页仅为有系统默认的运行设置提供“恢复默认”，只移除选中的覆盖。自建供应商、模型和器官模型绑定没有恢复入口；更新程序不会改写这些条目。旧 `[heartbeat] plan_organ` 和 `reply_organ` 仍可读取但不生效，运行固定使用 `models.toml` 的 `[organs.planner]`、`[organs.replyer]` 绑定。

在源码检出中，数据根目录默认位于项目根目录的 `aureus_home/`，已写入 `.gitignore`，个人设定、数据库和密钥不会进 Git。需要把它移到其他盘时，可设置 `AUREUS_HOME` 或使用 `--home`。测试一律用临时目录；不要把真实的 `aureus_home/` 路径改指向系统用户目录。

**聊天受托素材（D147）：** 若要允许小豆给某个 QQ 会话发指定文件，把愿意对该会话公开的副本放入 `data/chat_assets/<机器人账号>/<group 或 private>/<群号或好友号>/`。例如某群的 `集合说明.txt` 不会成为其他群的候选；模型只能按文件名选择，不接受任意本机路径、网址或目录链接。支持 UTF-8 文本与 PNG、JPEG、GIF、WebP 图片，每件不超过 700 KiB。移走文件即可撤销该素材授权；关闭 `[heartbeat] chat_assets_enabled` 可停用此功能。它与已登记表情库和读取来信附件是三套不同的授权。

**聊天开关：** 在 `aureus.toml` 的 `[heartbeat]` 区可分别调整正文后补表情、斗图与复读、等待与续话、定时提醒、主人叮嘱、群名单及通用梗查询。`reply_split_mode = "explicit"` 表示只在正文明确写出 `<n>` 时分气泡；关闭 `split_reply_enabled` 则整条发送。`chat_meme_glossary` 是维护者自定的可公开词条，不是私聊记忆。`[qq] follow_recall_enabled` 默认关闭；打开后也只对平台已通知、与原件直接相关的己方已送达消息跟撤。不支持的平台动作不会改成发送一句「已完成」。完整键名与默认值见 `config/aureus.example.toml`。

**收到的附件：** 小豆可以读同会话文本文档和 DOCX、XLSX、PPTX 的正文。读有文本层的 PDF 需要本机能找到 `pdftotext`，最多读前八页，不做 OCR；视频定点取帧、音频片段截取需要 `ffmpeg`。文档摘录最多 2,000 字；不运行宏、不追外链，解码失败就不拿文件名冒充内容。合并转发、分享卡片里的话只作引文，不自动获取网页或视频字幕。若要基于引文建提醒、留叮嘱或发受托素材，单独发自己的文字请求（可以引用原消息）。

## 3. 更新软件

- 数据库的格式版本号暂未加入（见 D45 第 5 条），第一次需要迁移时再加。加入后，启动时发现数据比软件旧，先自动备份到 `snapshots/`，再按编号顺序执行迁移脚本。发现数据比软件新（降级），拒绝启动并说明原因，不硬读。
- 配置文件有 `config_version`；新增字段必须有默认值，旧配置照样能读。
- 时间线只追加：迁移脚本也不修改、不删除已有记录，需要改格式时追加新列或新表。

## 4. 导出与导入

- **导出**：`aureus export 文件名.zip`。SQLite 用它自带的在线备份接口取得一致的副本，不直接复制正在写的文件。永远不含密钥（`secrets.vault`、`secrets.key` 和 `.env`，见 D36）；日志默认不含，用户可以选择包含。
- **导入**：`aureus import 文件名.zip`。要求没有实例在运行（用单实例锁判断）；目标数据根目录非空时拒绝覆盖，除非用户明确确认，并先自动备份旧数据；导入后核对 manifest 里的版本。
- 导出包的内容、manifest、覆盖前备份和防路径穿越的具体做法见 [10-decisions.md](10-decisions.md) 的 D45。
- **导入包的可信度**：manifest 和 sha256 都在包里，只能发现传输损坏，不能证明包来自谁、有没有被人改过。请只导入自己导出的包；要接收别人给的包，需要另做签名（尚未决定）。
- **导入的资源上限**（`aureus/core/portability.py`）：最多 10000 个文件，单个文件 2 GiB，总共 4 GiB，manifest 16 MiB。超过就在解压前拒绝，不读内容。核对和解压都是分块进行的，内存里同时只放 1 MiB。
- **导入是全有或全无**：文件先解到数据根目录下的 `data/.import-*` 暂存目录并再核对一遍，覆盖前先备份（文件名精确到微秒，重名加序号，不覆盖旧备份），再把目标已有的文件挪到暂存目录、放入新文件。任何一步失败都会把已放好的文件删掉、旧文件放回去。只有回滚也失败时才留下暂存目录，错误信息里写明旧文件在哪。
- 「唯一」的含义不变：同一份数据不能同时被两个实例运行。导入是复制到新位置，导入之后旧实例应停用。

## 6. 可移植、易安装、能更新（D38）

> 2026-11-16 新增（D38），强化 D28。

目标：软件能方便地安装、更新、搬家，用户数据自成一体，会持续增长的东西不挤占用户的 C 盘。

### 6.1 程序主体集中在一处

- 程序（代码、依赖、模板）只放在一个安装目录里，整个目录可以整体搬走、删除或重装，不往系统的其他地方散落文件。
- 软件目录里运行时不写任何东西（见第 2 节）。

### 6.2 路径可移植

- 代码里不写死盘符和绝对路径；所有路径都从数据根目录或安装目录派生（pathlib），不依赖当前工作目录。
- 配置和数据库里存相对于数据根目录的路径，整个数据根目录搬到另一块盘、另一台电脑后照样能用。
- 兼顾 Windows、Linux、macOS：不用只有某个系统才有的写法，非用不可时放在 common 里并写明原因。

### 6.3 增长的数据不占 C 盘

- 会持续增长的东西：数据库、日记、记忆索引、快照、日志，以及以后可能出现的下载的模型文件和各种缓存。它们都放在数据根目录之下，或放在由配置指定的位置，用户能指到任何一块盘。
- 源码检出默认使用项目根目录的 `aureus_home/`，避免开发数据落在系统盘。安装后的程序若回退到系统用户数据目录，`aureus init` 会先提示用户确认或选择位置。
- 第三方库默认会把缓存写到用户目录（比如模型文件的缓存）：用到时，通过环境变量或参数把它们指到数据根目录之下。
- 初始化命令 `aureus init` 和快照的大小上限见 D46。
- 只追加的时间线会一直变大，这是有意的，但要能看到它占了多大；日志、快照、缓存必须有保留期限或大小上限，不能无限增长。日记每天一篇、最多约 1500 字，和时间线一样长期保留；记忆简易版的全文索引从时间线派生，删掉能重建，大小跟着时间线走（D80）。
- 身体信号样本表 `body_samples` 默认只留 30 天（`[body] sample_retention_days`），启动时清理更早的行（D64）。样本只是读数、不是经历，所以不受时间线只追加的规则约束，这是有意的例外。

### 6.4 安装和更新

- 依赖用 uv 锁定版本（uv.lock），在新机器上运行 `uv sync` 装好依赖，再用初始化命令建好数据根目录。
- Windows 下双击项目根目录的 `Aureus.exe`，网页开始监听后会打开浏览器。登录本机网页后，可从侧栏打开 CLI。关闭 CLI 窗口后网页继续运行，在 CLI 里输入 `/quit` 可关闭 Aureus。详见 [Windows 启动器](tasks/supplemental.md#windows-launcher)。
- 更新软件按第 3 节：不碰数据根目录，数据版本落后就先备份再迁移。
- 导出、导入按第 4 节：数据根目录自成一体，导出的文件在新机器上导入后就能继续运行。

### 6.5 验收

- 自动测试：所有写入都落在数据根目录之内；整个数据根目录搬到另一个位置后仍能读取；扫描代码，不出现写死的盘符。
- 每个阶段结束的架构检查（11 号文档 2.6 节）加一条：有没有往数据根目录之外写东西，有没有无上限增长的数据。
