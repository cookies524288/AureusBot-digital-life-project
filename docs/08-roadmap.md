# 08 · 路线图

> 分两部分、若干阶段推进。每个阶段都交付一个能跑起来的东西，验收通过再进入下一阶段。
> 不设固定工期，以验收为准。

---

## 总览

### 第一部分：认知内核

| 阶段 | 名称 | 一句话 |
|---|---|---|
| Phase 0 | 地基 | 只有一个、一直在、重启不失忆的最小核心，自带实验能力和四层人设 |
| Phase 1 | 自我监控 | 身体信号上线，真实地调节行为；规划器和回复器分层；网页通道和观察台 |
| Phase 2 | 反馈驱动 | 预期对结果；自信、激素、心情和自主行为由反馈驱动；人设开始成长 |
| 延后 | 内核验证 | Phase 3 结束时复议，可延至 Phase 4 之后；E1–E7 通过后再定版 v1.0 |

### 第二部分：扩展

| 阶段 | 名称 | 一句话 |
|---|---|---|
| Phase 3 | 记忆与人际 | 长期记忆；接入 QQ；跨平台认人；信息边界完整 |
| Phase 4 | 双手 | 在自己的电脑上动手做事 |
| Phase 5 | 外包与成长 | 把专业工作交给其他 agent；自己写技能 |
| Phase 6 | 互联网生活 | 一起玩游戏；自己的账号；自己的项目 |

**MVP = 第一部分**：一个独立、连续、唯一、会自己行动、身体感受真实的认知内核，能在终端和网页上与人相处，并有一套可复现的实验证明它的机制有效。

---

## 工作方式

- 每个阶段开始前，先把这个阶段要做的事和验收方法写清楚；
- 代码主要由 AI 编写，维护者负责构思、设计取舍和验收（见 D27）；
- 每完成一个能运行的小步，就提交一次 git，方便回退；
- 遵守 [11-dev-guide.md](11-dev-guide.md) 的开发守则；新的决定记进 [10-decisions.md](10-decisions.md)。

## 第一部分：认知内核

### Phase 0 · 地基

**目标**：一个只有一个、一直在、重启不失忆的最小核心，从一开始就自带实验能力和四层人设。

**交付**：

- 项目初始化：git 仓库、uv 环境、目录结构、`.gitignore`、`.env` 模板
- 开发工具：ruff、pyright、import-linter、pytest，一条命令全部检查
- 可注入的时钟；器官接口和假器官；机制开关的配置框架
- 身份：身份事实和四层人设（仓库里放模板，用户的个人设定放在不进 git 的本地文件）；单实例锁
- 时间线：SQLite 只追加表，每条记录带序号、来源、可见范围
- 心跳循环：有事件立即跳，没有就定时跳
- 终端通道：在命令行里和它聊天
- 一个真实器官：调用一个云端模型，同时承担规划和回复，注入全部四层人设
- 账本：记录每次调用的 token 和费用；月度预算硬上限
- 命令行观察：查看时间线、今日花费

### Phase 1 · 自我监控

**目标**：身体信号上线，并真实地调节行为；规划器和回复器分层；有网页通道和观察台。

**交付**：

- 身体信号：精力、疲劳、压力、睡眠，以及各自的行为影响和开关（社交需求移到 Phase 2，和主动社交一起做，D53）
- 器官：规划器、回复器；按人设注入规则拼提示词；按精力自动选档（判断器官移到 Phase 2，D53）
- 状态呈现：把身体状态以事实摘要的形式放进上下文，让它能如实说出来
- 说话方式：借鉴 MaiBot 的拟人表达（口语、短句、分条）
- 注意力：收件箱、优先级、上下文组装（按可见范围过滤）
- 人际：按账号建档；识别用户
- 网页通道：用户的主通道，需要登录；默认只有本机能打开，局域网手动打开后手机可用；带人设设置页（D63）
- 观察台（网页版，Streamlit）：身体信号曲线、焦点、收件箱、花费、人设的历史版本
- 安全：权限等级的检查框架；急停
- 扮演模式（实验对照组）
