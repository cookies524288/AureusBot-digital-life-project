# 01 · 架构

> 本文描述 Aureus 的分层结构、认知循环与数据流。

## 2. 分层职责

### 2.1 Sensory 层

**职责**：把外部世界归一化为内部可处理的事件。

```text
输入：平台消息、文件变更、定时器、工具回调、设备事件
输出：Percept
```

Percept 必须包含：

```text
来源（source）
类型（kind）
时间（timestamp）
内容（payload）
可信度（trust）
是否指向自我（self_reference）
```

**原则**：Sensory 层不做判断，只做归一化。

### 2.2 Core 层

Core 是 Aureus 的本体。它持有全部状态，并驱动认知循环。

#### MirrorSelf（自我模型）

结构化、持久、带不可变层的自我状态。

```text
不可变层（Immutable）
  名字、自称、核心价值观、安全边界、身份不变量
可变层（Mutable）
  当前目标、当前注意力、当前情绪、置信度、
  能力边界、关系模型、当前叙事位置
```

规则：

```text
LLM 可读，不可写不可变层
可变层写入必须经过 Warden 审计
每次变更记录 diff 与理由
```

#### MindDome（全局工作空间）

容量有限的"当前意识内容"。

```text
容量：K 个槽位（建议 5–9）
候选来源：感知、记忆召回、内感受、目标、自我模型
竞争机制：显著性评分
胜出者：广播给所有器官
落选者：进入后台缓存，可被重新激活
```

工作空间不是消息列表，而是**当前被点亮的一组内容**。

#### Soma（内感受与情绪）

系统级的"身体状态"。

```text
能量（energy）
负荷（load）
疲劳（fatigue）
压力（stress）
社交需求（social_need）
唤醒度（arousal）
效价（valence）
```

规则：

```text
有基线、有衰减、有上限
受事件影响，但不会无限累积
影响显著性评分与器官温度
可被 LLM 读取，但不能被 LLM 任意改写
```

#### Spotlight（显著性）

决定什么进入 MindDome。

```text
评分 = f(新颖性, 目标相关性, 情绪强度, 社会信号, 预测误差, 自我相关性)
```

必须有：

```text
上限（防止单一信号垄断）
衰减（防止旧内容长期占位）
探索噪声（防止僵化）
```

#### Executive（执行控制）

决定做什么。

```text
输入：MindDome 当前内容 + MirrorSelf + Soma
过程：
  1. 生成候选行动
  2. 预测后果
  3. 抑制不合适选项
  4. 选择行动
  5. 记录意图
输出：Intent
```

Intent 必须包含：

```text
目标（goal）
动作（action）
预期结果（expectation）
置信度（confidence）
归因（owner = self）
```

#### OrganBus（器官总线）

所有 LLM 能力的统一入口。

```text
每个器官：
  - 有明确职责
  - 有输入输出 schema
  - 有置信度
  - 有超时与失败边界
  - 无状态或短时状态
  - 不能修改核心身份
```

器官之间不直接对话，只通过 Core 仲裁。

#### PredictionLoop（预测闭环）

```text
行动前：记录 expectation
行动后：采集 outcome
比对：计算 error
回流：
  - 更新世界模型
  - 更新自我模型（能力边界、置信度）
  - 更新情绪（成功/失败）
  - 更新技能（有效/无效）
  - 写入记忆（带误差标记）
```

没有闭环的行动视为未完成。

#### Hippo（记忆）

```text
情景记忆：发生了什么
语义记忆：世界是什么样
关系记忆：谁是谁、关系如何
技能记忆：怎么做
叙事记忆：我经历了什么
```

记忆写入必须带：

```text
来源、时间、情绪标签、置信度、误差标记
```

#### Thread（叙事）

长期自我叙事。

```text
不是聊天记录
而是"我成为谁"的时间线
按天/周/月聚合
可被 MirrorSelf 引用
```

### 2.3 Actuator 层

**职责**：把 Intent 变成真实动作。

```text
输出：聊天消息、文件操作、GUI 动作、API 调用、工具执行
```

必须支持：

```text
预演（dry-run）
审批（高风险动作）
回滚（可逆动作）
审计（全部动作）
```

### 2.4 Warden（治理）

横切所有层。

```text
身份不变量保护
权限边界
危险动作审批
写入审计
回滚
熔断
```

原则：**失败朝安全方向倒。**

## 3. 认知循环

一次完整循环：

```text
1. 感知
   Sensory 收集 Percept

2. 内感受更新
   Soma 根据事件更新能量/压力/情绪

3. 显著性竞争
   Spotlight 对所有候选评分，选出 Top-K

4. 工作空间广播
   MindDome 点亮 Top-K，广播给器官

5. 自我模型更新
   MirrorSelf 更新"我现在在做什么/我知道什么"

6. 候选行动生成
   Executive 调用器官生成候选

7. 预测
   为每个候选记录 expectation

8. 选择与抑制
   选择行动，抑制其余

9. 行动
   Actuator 执行

10. 结果采集
    收集 outcome

11. 误差计算
    比对 expectation 与 outcome

12. 回流更新
    更新自我、世界、情绪、技能、记忆

13. 叙事写入
    重要事件写入 Thread

→ 回到 1
```

---

## 4. 数据流约束

```text
感知单向进入 Core
Core 内部通过事件总线通信
行动单向离开 Core
记忆双向，但写入需审计
身份不可变层只读
```

禁止：

```text
器官直接调用其他器官
器官直接写记忆
器官直接改身份
Actuator 绕过 Executive
Sensory 直接触发行动
```

## 5. 运行形态

### 5.1 单进程

```text
Core + 器官 + 适配器 在同一进程
适合 MVP 与本地部署
```

### 5.2 内核 + 身体

```text
Core 作为独立进程/服务
身体（聊天框架、前端）通过协议接入
适合长期运行与多前端
```

### 5.3 分布式器官

```text
器官可运行在远端
通过 OrganBus 协议通信
适合重模型与 GPU 任务
```

MVP 只需支持 5.1，但协议设计要兼容 5.2 / 5.3。

---

## 6. 时间尺度

```text
快速环（毫秒–秒）
  感知 → 预测 → 行动 → 误差
  用于对话节奏、GUI、游戏

对话环（一轮–几轮）
  说话 → 反馈 → 关系/情绪更新

昼夜环（小时–天）
  经历 → 巩固 → 情绪消化 → 叙事更新

发展环（周–月）
  技能学习 → 关系变化 → 自我认同变化
```

不同环路由不同调度器驱动，但共享同一份 Self-Model。

---

## 7. 关键设计决策

| 决策 | 理由 |
|---|---|
| 身份结构化 | 避免提示词漂移 |
| 工作空间限容 | 避免上下文堆叠 |
| 器官无状态 | 便于替换与测试 |
| 闭环强制 | 避免"说了就完" |
| 治理横切 | 安全不能事后补 |
| 可观测优先 | 无法观测就无法调试 |

---

## 8. 不做什么

```text
不在 Core 里写业务逻辑
不在器官里保存长期状态
不让工作空间无限扩张
不让情绪无限累积
不让自我改进绕过审批
```
