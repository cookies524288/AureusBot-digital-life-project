## 目标和验收

目标：图片嵌入按模型配置选择输入格式，修复本机 chinese-clip 把 Jina 对象当文本导致的 500。

1. 默认行为不变：没配置格式时仍发 Jina 对象 `{"image": "<base64>"}`。`tests/organs/test_llm_adapter.py` 现有图片嵌入用例全部通过。
2. 模型 `extra_params.image_embedding_input = "{data_uri}"` 时，改为发 OpenAI 兼容的字符串数组 `input: ["data:image/png;base64,..."]`，不带 `embedding_type`。新增测试断言 payload 形状。
3. GIF/WebP 仍先按 D143 取第一帧转 PNG，data URI 的 MIME 为 `image/png`；PNG 原样发 `image/png`；JPEG 原样发 `image/jpeg`。
4. 配置校验：`image_embedding_input` 只能出现在 `kind = "image_embedding"` 的模型上，值只能是 `"{data_uri}"`；其它情况报中文配置错误。
5. 模型测速展示的输入与实际发送一致：data URI 配置显示字符串数组，默认显示 Jina 对象。
6. 图片索引回填遇到服务商熔断时停止本批，不再逐张尝试并刷警告；不改熔断阈值、冷却、网关和账本。
7. 全部用 `httpx.MockTransport` 和假时钟；不访问 127.0.0.1:9988，不调用真实模型。

## 接口

- 无新增公开 API。
- 私有函数：`_embedding_image_data(value: bytes) -> tuple[bytes, str]`；`_embedding_images(inputs: Sequence[bytes], *, data_uri: bool) -> tuple[str, ...]`。
- 配置键：模型 `extra_params.image_embedding_input`，唯一值 `"{data_uri}"`。该键只影响图片嵌入的请求体，不进入请求参数。

## 配置

`models.toml` 示例：

```toml
[[models]]
name = "[local_embedding]chinese-clip"
identifier = "chinese-clip"
provider = "local_embedding"
kind = "image_embedding"
vision = false
reasoning_levels = []

[models.extra_params]
image_embedding_input = "{data_uri}"
```

- 值缺失：保持 Jina 对象。
- 值不是 `"{data_uri}"`：保存和启动时拒绝，报中文错误。
- 键写在非 `image_embedding` 模型上：同样拒绝。
- 不改 `docs/15` 已有的服务商、超时、预算、权限字段。

## 行为细则和边界情况

1. 转换顺序不变：先按 D143 得到可发送字节和 MIME，再按所选格式编码。GIF/WebP/其它格式转 RGB PNG；PNG/JPEG 的 RGB/RGBA/L 原样。
2. data URI 负载格式固定为 `data:<mime>;base64,<base64>`，MIME 只可能是 `image/png` 或 `image/jpeg`。
3. 多图顺序保持；每张图各自转换和编码。
4. 损坏图片仍不发请求，按「图片格式不支持」失败，器官继续尝试下一条路线。
5. data URI 模式下请求体是 `{"model": ..., "input": [...]}`；Jina 模式保持 `{"model": ..., "embedding_type": "float", "input": [{"image": ...}]}`。
6. `local`（回环不走代理）与格式选择互不影响；非回环也可以显式配置 data URI。
7. 回填遇到熔断：本批立即停止；已写入的向量保留；下一轮心跳再试。只有一次熔断跳过警告，不再为剩余每张图各记一条。
8. 账本 usage 仍按原始输入字节估算（图片嵌入本地免费，cost 0）；不改记账语义。
