# 路线图 3.6 · QQ 通道

状态：待实现

先读 D89、[部署基线](../13-references-and-migration.md)、现有 channels、注意力队列、人物账号与安全网关。部署使用 snowluma-adapter 1.1.8（清单 GPL-v3.0-or-later）和 SnowLuma 2.1.1。核对实际 `transport.py`、消息收发与编解码代码。只读公开源码，复用处注明原文件、函数及许可。

## 交付

1. 配置显式启用的 QQ 通道，接入正常启动和关闭。端点、账号标识从部署配置取得，凭据走既有密钥接口。默认关闭；测试使用内存或回环模拟端。依已有 transport 协议收发 JSON，动作与 echo 对应，处理失败、断连、超时和关闭。心跳不因网络停住。
2. 群聊、私聊、点名、引用、消息 ID、实际发言人与目标地址保持正确。群里多个说话人的回复回到原群与正确引用。用平台、接收账号及消息标识识别重复输入，包括断线重放；本机自己发送的回显只处理一次。回复经过正常识人、注意力、规划与安全网关。适配器不按投递地址分割小豆的记忆。
3. 网页与 QQ 的账号关联通过短时、单次、可撤销或过期的验证码及已验证用户会话完成。仅能绑定实际证实控制的账号；冲突、重放、超时皆覆盖。按现有人际接口写账号映射，避免同名合并或误授用户身份。测试使用假时钟，无需真实送达。
4. 记录外网访问网页的部署选项、鉴权及 TLS 前提，沿用既有私有绑定默认。专注判断可行部署路径，本步不发布公网服务。

## 自检

- [ ] 正常启动启停、默认关闭、假 WebSocket 收群聊和私聊并送出正确目标与引用。
- [ ] 多说话人、重连回放、回显去重、动作失败/超时和关闭时无残留等待任务。
- [ ] 登录网页及 QQ 双侧确认绑定，重启后映射有效；错误与重复验证不会改错人。
- [ ] 明确标注复用路径与许可，假服务集成和相关专项、类型、格式检查通过。

## 范围

真实群发言、源 bot 下线及生产连接切换留待 3.9，在维护者指定的群和窗口执行。此步不得连接活动 QQ 端点或发送真实消息。
