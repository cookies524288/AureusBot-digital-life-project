# 3.15a · 规划器调用工具

状态：待实现。设计：D103。先读 [总任务](3.15.md)、`aureus/organs/interface.py`、`llm_adapter.py`、`aureus/heartbeat/conversation.py`、`planning.py` 和根目录 `Planner tool prompt.txt`。

## 子步骤

1. 协议：请求带声明过的工具，响应带已解析工具名、调用 ID、参数；真实适配器透传并保留耗用和错误处理，无工具时其他器官完全不变。处理纯工具响应及分段到达的参数，不能把工具结果当普通回复。合成夹具覆盖普通和流式响应。
2. 调度：明确的 `reply` 才能调 replyer，`stop`、无调用、失败和错误参数均不发言；有界读取工具返回结果再规划，保留原资源权限、预算、再审、防抖和分段。用指定模板的结构、措辞和实际可用工具生成提示，先判断「是否在对我说话」，结论随参考回复进入 replyer。简单原因摘要用于展示，不记录隐式推理。工具表和处理器共源，无真实能力不声明；不得开放 shell、外部子代理或任意工具服务。
3. 展示：planner 配置菜单的“工具列表”使用同一服务端目录，只显示实现且可用的工具、用途及参数，沿用器官面板视觉与可访问交互。

## 自检清单

- [ ] 模拟请求可见工具 schema；纯文本、工具参数、计费和取消路径有明确契约。
- [ ] 合成一轮 `reply` 调一次回复器；`stop`、解析失败、无调用均为零，判断结论传到实际回复请求。
- [ ] 菜单与实际可用工具一致；旧流程中没有可绕过选择的聊天 fallback。

不做：改主动探索或平台接口、记录模型私有思考、用真实模型验证。独立可运行步骤各交一个提交，由主审负责发布。
