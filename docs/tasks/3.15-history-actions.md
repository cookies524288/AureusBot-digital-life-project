# 3.15 · bot 查阅与清理平台旧历史

状态：待实现。对应台账第 4、7 项。先读[原文边界](3.15-memory.md)、[平台阅读](3.15-platform.md)、`heartbeat/planner_tools.py`、`heartbeat/inbox_store.py`、`web/inbox_history.py` 与 `timeline/platform_history.py`（源码均在 `aureus/`）。复用已有 `ConversationKey` 和读取水位；不要给记忆搜索恢复“消息”结果。

## 可独立交付的两步

1. **只读查历史**：在有已核准平台路由和当前会话的 planner 轮次，提供明确区别于 `query_memory` 的 `read_platform_history` 工具。会话和账号由服务端从当前轮选择，不接受任意账号、数据库或远端地址。支持有限最近已读条数、可选关键词和继续向前的边界；保留时间、发言人、方向与平台原件键，清楚区分没有结果、没有权限和接口失败。优先读规范原件，精确路由历史遵守去重及权限；未归类迁入不向 bot 猜配。不能借查询改变未读水位、取其它会话的图片或写入长期记忆。与其它读取工具共用本轮调用次数和材料长度上限，结果为独立工具消息，遇到抢占/撤权则丢弃；追踪记录只写调用摘要，不再留一份原文。器官工具列表与真实调度共源。
2. **清理有可核对范围**：让 bot 能对当前已授权会话中截止某日期的旧已读消息提出清理，并得到真实预览；由维护者用受认证的网页确认具体范围后执行。确定性代码才删除，模型不写库。预览绑定完整会话、固定截止与服务端高水位（不是用户手填序号）；确认时重新核对账号、授权、密码、候选和水位，变化后需要重新预览。不能清未读、未送达或另一个会话，新入记录即使平台原时间很早也不受旧确认影响。原件、可关联的媒体描述和缓存向量不残留在平台查询里；对仍有其它所有者的媒体不物理删除。清理是本地保留策略，不撤回 QQ 服务器消息。既有只追加的时间线/迁入备份不可冒充已被从磁盘清除，界面要列出实际可删除的来源和只能从平台视图移除的旧来源，防止可见的旧副本在清理后又顶替原件。保留审计摘要而非正文。

## 自检

- 同一平台消息键在不同群、不同账号、临时私聊不串；切换/撤权后不返回过期结果，失败不变成 `reply`，也不让未读变已读。
- 使用合成库覆盖零候选、重复确认、密码不对、预览后迟到旧日期消息、读水位及来源改变；核对完整的清理前后范围和未改变的时间线、其它会话与事实索引。不得用正式历史做清理演练。
