## 目标和验收

目标：消息条数不再影响压力、身体摘要、自检和行为；压力只看最近调用的失败率。

1. `compute_stress` 只接收调用结果和配置，不再接收 backlog；`StressReading` 删除 `backlog` 字段。
2. `Body.read`、`Body.read_stress` 不再接收 backlog；心跳不再为压力计算排队数。
3. 身体摘要、压力自检、时间线自检详情不再出现「排队的消息/积压」；压力偏高只报告失败次数和原因。
4. 删除 `BodyConfig.stress_backlog_full` 和设置页条目；示例配置与 04 号文档同步。旧配置里写了该键时加载丢弃，不拒绝启动。
5. `BodySample` 删除 `backlog` 字段；`body_samples.backlog` 列保留给旧数据，不再写入或读取；`inbox_count` 继续记录，观察台照常显示收件箱条数。
6. 消息再多也不会单独提高压力；真实失败仍按原规则提高压力。疲劳仍按最近器官调用次数计算，不变。
7. 不真实调用模型；测试用假时钟、假账本和临时数据库。

## 接口

- `StressReading` 不再有 `backlog`。
- `compute_stress(recent_outcomes: Sequence[tuple[bool, str | None]], config: BodyConfig) -> StressReading`。
- `Body.read(last_conversation_at: datetime | None = None)`；`Body.read_stress()`。
- `BodySample` 不再有 `backlog`；数据库列保留，不读写。

## 配置

- 删除 `[body] stress_backlog_full`；示例配置和设置页同步。
- 旧配置写了该键：`BodyConfig` 在 before 校验器里丢弃，仍能启动。
- 不新增配置。

## 行为细则和边界情况

1. 压力 = 最近 `stress_window_calls` 次调用的失败率；分母至少是窗口大小；`stress_high_at`、`stress_lowers_tier` 和自检逻辑不变。
2. 消息队列长度不再进入 `Body`、`StressReading`、身体摘要或自检；`inbox_count` 只作为样本/观察台的诊断数字。
3. `body_samples` 旧行里的 `backlog` 保持原样，不删除；新行该列为 NULL。`BodySample` 不再暴露这个字段。
4. 旧时间线里的自检记录可能带 `backlog` metadata；前端不再显示该键，历史内容不改。
5. 配置兼容：旧键被丢弃；其它未知键仍按 `extra="forbid"` 报错。
6. 疲劳仍读账本里的实际器官调用次数；不因消息多而增加。
7. 不改注意力、防抖、驻留、收件箱读取上限、预算、权限和网关。
