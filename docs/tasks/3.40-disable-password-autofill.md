# 3.40 普通输入框与密钥输入框不弹浏览器密码自动填充

状态：完成
设计：维护者 2026-11-26 指令

## 问题

浏览器的密码管理器在设置搜索框、密钥输入框等位置弹出「保存的密码 / 管理密码」浮层，挡住操作；只有网页登录密码需要自动填充。

## 目标

1. 只有登录页的密码输入框参与密码自动填充；其它所有输入框（搜索、设置、密钥、Prompt 等）都不触发密码管理器浮层。
2. 密钥输入框仍保持视觉遮挡（不显示明文），但不要被浏览器当作登录密码。

## 实现

1. 登录表单保留 `autocomplete="username"` / `autocomplete="current-password"`（按现有结构）。
2. 其它输入框统一加：`autocomplete="off"`（或 `new-password`）、`data-lpignore="true"`（LastPass）、`data-1p-ignore`（1Password）、`data-bwignore`（Bitwarden）、`data-form-type="other"`。
3. 密钥输入框若使用 `type="password"`，改为 `type="text"` 并用 CSS `-webkit-text-security: disc` 遮挡（或保留 password 但加上述属性；以实测不弹浮层为准）。
4. 不改输入校验与提交逻辑。

## 实现记录

只改 `aureus/web/static/index.html`。

1. 登录页 `#password` 恢复为 `type="password" autocomplete="current-password"`；启动时给所有控件补属性的循环跳过它。
2. 其余控件统一补 `autocomplete="off"`、`data-lpignore="true"`、`data-1p-ignore`、`data-bwignore`、`data-form-type="other"`。静态控件由启动时的一次性循环处理；动态控件由 `el()` 的默认属性处理。
3. 非登录页的密码类输入框改为 `type="text"` + `.secret-input{-webkit-text-security:disc}`：改密码页旧/新密码、人设页当前密码、设置页当前密码、恢复默认设置当前密码、密钥编辑器的密钥原文和当前密码。密钥编辑器字段带 `data-secret` 和 `spellcheck="false"`，关闭编辑器时按 `[data-secret]` 清空。
4. 输入校验、提交参数和接口调用未改；改密码流程实测可用。

- 页面加载：`window.__qaErrors` 为空，`Runtime.exceptionThrown` 为 0；只有登录前 `/api/status` 返回 401 的一条网络日志，属预期。
- 登录自动填充：在临时 Chrome 配置里写入一条测试凭据后，打开登录页 `#password` 自动填入（`:autofill` 为 true，长度 17），截图 `E:/Temp/autofill-qa/login-autofilled.png`；DOM 中唯一的 `input[type=password]` 就是 `#password`。
- 非登录输入框：应用加载后 46 个静态控件中，除 `#password` 外全部带上述五个属性；设置页动态生成的 3 个控件、Prompt 页动态文本域、密钥编辑器动态控件也全部带齐。设置搜索、Prompt 搜索、模型搜索、人设密码框获得焦点时 `:autofill` 均为 false，值保持为空。模型页测试数据为空，添加/编辑按钮禁用，模型编辑器没有单独打开；其中的输入由同一个 `el()` 创建，属性机制与已测的 Prompt/密钥动态字段相同。
- 密钥遮挡：密钥编辑器的“密钥原文”和“当前密码”均为 `type=text`、`class=secret-input`，计算样式 `-webkit-text-security: disc`；浅色和深色截图 `E:/Temp/autofill-qa/key-dialog-light-2.png`、`key-dialog-dark.png` 都显示圆点。
- 改密码流程：默认密码 `admin` 登录后进入改密码页，旧/新密码框输入并提交成功，随后用新密码登录成功，说明改为 text 后校验和提交未受影响。

## 待设计问题

1. 登录表单只有一个密码框，没有用户名字段；本次只保留 `autocomplete="current-password"`。如果希望密码管理器同时保存/填充用户名，需要另行设计账号字段。
2. 现有测试需要跟着改，本次按任务范围只改 index.html、未跑 pytest：`tests/web/test_resource_browser.py:3188` 断言所有控件 `autocomplete=off`（登录密码现在是 `current-password`）；`tests/web/test_page_keys.py:58,68` 断言密钥原文是 `type=password`（现在是 `text` + CSS 遮挡）。
3. `aureus/web/static/inbox-retention.js:30` 和 `aureus/web/static/resource-management.js:969` 仍动态创建 `type=password` + `autocomplete=current-password` 的确认框，不在 index.html 的循环和 `el()` 覆盖范围内。若要覆盖「所有非登录输入框」，需要允许改这两个文件或另开任务。
4. `-webkit-text-security` 在 Chrome/Edge 实测有效；旧版浏览器若不支持会显示明文，是否需要兼容方案请维护者定。改成 text 后读屏不再有 password 语义，只有视觉遮挡，是否接受也请维护者定。
