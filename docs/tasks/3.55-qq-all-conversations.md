## 目标和验收

1. 默认不限制：`QQConfig()` 的 `allowed_group_id is None`；`QQChannel.allows_inbox_conversation` 对任意群、任意普通私聊和临时私聊返回 True。
2. 显式 `allowed_group_id` 仍然只放行该群和本人普通私聊。
3. 本机 `aureus_home/config/aureus.toml` 的 `allowed_group_id` 被注释掉，配置仍能正常加载。
4. 示例配置、13 号文档、设置页说明与 D136 一致。
5. 接收、发送、网页收件箱和学习来源共用同一套范围判断，预算、权限、急停、回复决策不变。

## 改动一览

- `aureus/common/config.py`：`allowed_group_id` 的注释改成「不写 = 所有群和私聊；填写后只允许该群和本人普通私聊（D136）」。
- `aureus/web/static/index.html`：`CFG_FIELDS['qq.allowed_group_id']` 的说明改成同样的语义。
- `config/aureus.example.toml`：`[qq]` 增加注释掉的 `# allowed_group_id = "123456789"` 和默认说明。
- `docs/13-references-and-migration.md` 第 2.6 节：改成默认不写 = 所有会话，要限制再填。
- 本机 `aureus_home/config/aureus.toml`：把 `allowed_group_id = "524789151"` 改成注释，保留原群号便于恢复；不改其它行。
- 测试：新增默认范围和显式范围的用例；必要时更新 `tests/channels` 里构造 `QQConfig` 的夹具（默认值不变，应该不用改）。

## 行为细则和边界情况

1. `allowed_group_id` 为 `None` 时，`_allows_route` 返回 True：所有群、普通私聊、临时私聊都放行。
2. 填写群号时行为不变：只放行该群和本人普通私聊；临时私聊、其它群、非本人私聊拒绝。
3. 测试群（`qq_test_group`）的限制是另一层，保持现状。
4. 桌面外发对临时私聊的拒绝是既有边界，不因本次改动放开。
5. 不新增配置字段，不改数据库，不改路由格式。
6. 本机配置只注释 `allowed_group_id`，不删除原值；重启后生效。
