## 目标和验收

1. 已有实例真的在运行时，双击 `Aureus.exe` 只附着并打开它的网页；共享内存里的地址如果已经无响应，不再被当成活实例。
2. 旧实例正常关闭期间，新启动器最多等 180 秒（原 30 秒），期间不另起内核；旧实例释放锁后新实例正常启动/附着。
3. 旧实例真正挂住、锁一直不放时，维护者可以确认后结束它并重新启动：只结束核对通过的、本项目的 `aureus.cli.windows_launcher` 进程树；核对不通过或维护者取消时不杀任何进程，报原来的单实例锁错误。
4. C# 启动器在托盘重启/退出时对子进程设看门狗：重启 180 秒、退出 30 秒内没退出就结束子进程树；主动结束不算启动失败。
5. 不改数据根目录内容、预算、权限、急停和单实例锁语义；不绕过锁；不在未确认时结束进程。
6. 不真实调用模型；单元测试不弹 MessageBox、不杀真实进程。

## 改动一览

- `aureus/cli/windows_launcher.py`：
  - `_open_running_web` 在打开/附着前用 `httpx.get(url, trust_env=False, timeout=1)` 检查根地址 200；不通过就当没有实例。
  - `_STARTUP_WAIT_SECONDS` 30 → 180。
  - `_launch` 在等待超时后调用 `_takeover_stale_instance(paths)`；成功则继续循环，失败则抛出原来的 `SingleInstanceLockError`。
  - 新增 `_takeover_stale_instance(paths)`：读 `paths.home / "aureus.lock.pid"`；PowerShell `Get-CimInstance Win32_Process` 核对 PID、CommandLine 含 `-m aureus.cli.windows_launcher`、CreationDate 早于 pid 文件；MessageBox Yes/No；Yes 后 `taskkill /T /F /PID <pid>`，等待并返回 True；No/核对失败返回 False。
- `aureus/identity/service.py`：`_LockContextManager.__enter__` 成功后写 `aureus.lock.pid`（内容为 `os.getpid()`），`__exit__` 删除；写失败只记日志，不影响锁。
- `aureus/core/portability.py`：导出包排除 `aureus.lock.pid`（与 `aureus.lock` 同处）。
- `scripts/WindowsLauncher.cs`：
  - `ChildStatus` 增加 `KilledForRestart` / `KilledForExit`。
  - `RunTray` 的 200ms 计时器记录 restart/exit 请求时间；超过 `RestartGraceSeconds=180` / `ExitGraceSeconds=30` 且子进程未退出时 `taskkill /T /F /PID` 结束子进程树，置对应标志。
  - `Launch` 对主动结束不显示失败：restart 标记继续循环启动 `--restarted`，exit 标记返回 0。
  - 不改启动参数、托盘菜单和网页等待页。
- 测试：`tests/cli/test_windows_launcher.py`、`tests/identity/test_service.py`（或现有锁测试）、`tests/core/test_portability.py`；C# 只构建临时 exe 手测，不跑 pytest。

## 接口

- `_STARTUP_WAIT_SECONDS = 180.0`。
- `_takeover_stale_instance(paths: AureusPaths) -> bool`：核对通过且维护者确认并结束成功返回 True；其余 False。
- 单实例锁 pid 文件：`<数据根目录>/aureus.lock.pid`，内容为持有者 PID 的十进制文本。
- C# `ChildStatus.KilledForRestart` / `KilledForExit`；`RestartGraceSeconds` / `ExitGraceSeconds` 常量。

## 行为细则和边界情况

1. 健康检查失败（超时、连接拒绝、非 200）不附着；继续尝试单实例锁/启动。健康检查不改共享内存，不删除地址。
2. 等待 180 秒期间每隔 0.1 秒重试：先附着（健康），再启动（锁释放），再等到下一轮；不另起内核。
3. pid 文件不存在、PID 不是正整数、进程不存在、命令行不是本项目、CreationDate 不早于 pid 文件修改时间：一律不杀，报原来的单实例锁错误；错误文字里提示用任务管理器确认。
4. MessageBox 使用 Yes/No + 问号图标；No 或关闭窗口按取消处理；不读密码、不碰数据。
5. `taskkill` 只结束核对通过的 PID 树；命令用参数数组、`CREATE_NO_WINDOW`，超时 10 秒；失败不重试、报错。
6. 锁释放时删除 pid 文件；进程异常退出留下的 pid 文件由下一次成功持锁覆盖；导出包不带它。
7. C# 看门狗只在 restart/exit 菜单动作后计时；普通子进程崩溃仍走原来的失败页；主动结束后 restart 继续、exit 返回 0。
8. 正式实例运行中不能覆盖根目录 `Aureus.exe`；C# 改动先构建临时 exe（如 `Aureus-361-test.exe`）在隔离数据根验证，根 exe 重建留给维护者停实例后执行。
9. 不真实调用模型；不访问用户数据以外的文件；不结束非本项目进程。

## 实现备注

- 接管成功并结束旧进程树后，`_launch` 重新给一轮 180 秒等待：`taskkill` 返回时旧进程可能
  还没完全退出，这样不会在几秒内再次弹确认框（D144 的「重试」）。
- 工作区里 `service.py`、`WindowsLauncher.cs` 原本是 LF；按任务要求统一为 CRLF 后提交，
  git 存储仍按 `core.autocrlf=true` 规范化为 LF。

## 坑

- 正式实例当前正在运行（`Aureus.exe` + `pythonw -m aureus.cli.windows_launcher`），不要停止、不要覆盖根目录 `Aureus.exe`、不要操作 `aureus_home/`；用临时数据根/端口/临时 exe 测试。
- 根目录 `Aureus.exe` 是受版本控制的构建产物；C# 改动后需要维护者停实例再 `scripts/build-launcher.ps1`。
- `windows_launcher.py`、`service.py`、`portability.py`、`WindowsLauncher.cs` 是 CRLF；新测试 LF。
- MessageBox/taskkill/PowerShell 在单元测试里必须 monkeypatch，不能真弹/真杀。
