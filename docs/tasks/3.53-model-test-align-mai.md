# 3.53 模型测速对齐 MaiBot：测试形式、提示词、测试图片与独立限流

状态：待评审
设计：维护者 2026-11-26 拍板（3.52 建议 1 + 拷贝 MaiBot 测试形式）

## 目标

模型测速不再因限流、判定过严而大面积失败：测试形式、提示词与测试图片对齐 MaiBot；模型测试使用独立许可与限流，不挤占回复。

## 实现

1. 从 MaiBot 公开源码固定提交 `062d45c`（GitHub raw 走代理 `127.0.0.1:7897`）找出模型测试使用的提示词、测试图片与判定方式，移植到 `aureus/organs/llm_adapter.py` 的探测逻辑；图片等资源登记 THIRD_PARTY.md（GPL-3.0，注明来源与改动）。
2. 测试形式对齐 MaiBot：文本、视觉、工具、思考的提示词与期望输出按其做法；不再用 1×1 红图与恰好 `red` 的严格判定。
3. `model_test` 使用独立许可（建议 2）与独立限流（建议 60 次/分钟），不占用回复的 5 个许可；仍记账、受预算约束。
4. 保留现有失败原因映射与用量记账；不真实调用模型，测试用假客户端与固定图片字节。

## 实现说明

- MaiBot 的模型测试是一次请求：测试提示词 + 测试工具 +（可选）测试图片，成功标准是出现名为 `maibot_model_test_report` 的工具调用。Aureus 仍按能力分项探测：
  - `text`：同一提示词并声明测试工具，接受任意非空正文、工具调用或推理内容，用来测首包延迟；
  - `tools`：同一请求，必须出现测试工具调用（不校验参数）；
  - `vision`：提示词带图片说明并附 32×32 测试图片，必须出现测试工具调用；
  - `reasoning/<等级>`：同一请求并带 `reasoning_effort`，必须出现测试工具调用。
- 视觉探测不再要求回答恰好 `red`；图片嵌入探测也改用同一张 MaiBot 测试图片，替换原来的 1×1 红图。
- `_MODEL_TEST_MAX_TOKENS` 从 32 提到 512，与 MaiBot 的测试预算一致；失败原因映射和账本记账不变。
- 思考探测只返回推理内容、没有测试工具调用时按 MaiBot 判定失败；D127 的「只返回推理也算可用」仍用于 `text` 探测。
- 独立许可 2、独立限流 60 次/分钟写成安全模块常量（任务建议值），没有新增 `SafetyConfig` 字段。
