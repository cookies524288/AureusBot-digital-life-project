# 3.57 防抖最多等待上限，避免人多的群一直不回复

状态：待评审
设计：D138（docs/10-decisions.md）

## 先读

- `aureus/common/config.py`：`HeartbeatConfig.inbox_debounce_enabled`、`inbox_debounce_seconds`、`inbox_debounce_max_restarts`。
- `aureus/heartbeat/main_loop.py`：`_debounce_remaining`、`_take_inbox_followups`、`_restart_planner`、`_interrupt_inbox`、`_collect_finished_thought`。
- `docs/10-decisions.md` 的 D116、D138。
- 测试：`tests/heartbeat/test_inbox_attention.py`、`tests/heartbeat/test_inbox_reply_review.py`、`tests/common/test_config.py`。

## 目标和验收

1. 人多的群里每 2 秒来一条消息时，planner 最迟在 20 秒（默认上限）后启动并至少回复一次，不再无限等待安静窗口。
2. 防抖窗口仍保留：短时间内连续来信继续合并；上限只决定最晚什么时候开始，不改变合并内容。
3. `inbox_debounce_max_restarts` 的单轮四次上限不变；到了上限后 planner 不再被新消息打断，正常完成并投递。
4. 中断当前会话时不再清空该会话的重开计数；只有正常完成一轮才清零。
5. 预算、权限、急停、收件箱范围、回复内容不变。
6. 新配置项在示例配置和设置页有中文说明。

## 改动一览

- `aureus/common/config.py`（CRLF）：`HeartbeatConfig` 新增 `inbox_debounce_max_wait_seconds: float = Field(default=20.0, ge=1, le=120, allow_inf_nan=False)`；不写时如果 `inbox_debounce_seconds` 更大，自动取窗口本身（旧配置照常读取）；显式写时不得小于 `inbox_debounce_seconds`。
- `aureus/heartbeat/main_loop.py`（CRLF）：
  - `_debounce_remaining` 取「最近一条 + `inbox_debounce_seconds`」和「最早一条 + `inbox_debounce_max_wait_seconds`」的较小值。
  - `_interrupt_inbox` 不再 `pop` 该会话的 `_planner_restarts`。
- `config/aureus.example.toml`（CRLF）：`[heartbeat]` 增加注释掉的 `# inbox_debounce_max_wait_seconds = 20.0` 和说明。
- `aureus/web/static/index.html`（CRLF）：`CFG_FIELDS` 增加 `heartbeat.inbox_debounce_max_wait_seconds` 的中文说明。
- 测试：`tests/common/test_config.py` 默认值/显式值/校验；`tests/heartbeat/test_busy_group_debounce.py` 人多的群回归用例。

## 接口

- `HeartbeatConfig.inbox_debounce_max_wait_seconds: float = 20.0`，`ge=1, le=120, allow_inf_nan=False`。
- `_debounce_remaining(batch) -> float`：返回剩余秒数；上限到了返回 0。
- 无新公开接口。

## 行为细则和边界情况

1. `inbox_debounce_enabled=False` 时 `_debounce_remaining` 仍返回 0，行为不变。
2. 不写 `inbox_debounce_max_wait_seconds` 且 `inbox_debounce_seconds` 大于 20 秒时，自动取防抖窗口本身，旧配置照常启动；显式写了一个更小的值才报中文错误。
3. 一批消息的最早时间和最近时间都从消息记录的时间取；时钟由 `ManualClock` 驱动。
4. 到了上限后 planner 启动；新消息仍可在 `inbox_debounce_max_restarts` 内打断，但计数不再被 `_interrupt_inbox` 清零，最多四次后必须完成。
5. 正常完成一轮（`_collect_finished_thought` 的非中断路径）仍清零计数，下一轮重新计算。
6. 不改防抖的合并范围、读取水位、优先级和抢占规则。

## 测试

- `tests/heartbeat/test_inbox_reply_review.py`：现有中断/重开用例复跑，确认计数不再被中断清零不会破坏原语义。
