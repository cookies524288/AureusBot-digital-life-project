## 目标和验收

目标：被取消的模型调用仍然记账（可能已花 token），但不再算失败，也不提升压力。

1. `LLMOrgan` 在 `CancelledError` 时生成的 `CallAttempt` 为 `succeeded=True`，`failure_reason` 保留「本轮生成已取消」作为说明。
2. 网关的 `OrganCallCancelled` 路径照常记录用量，不写 `organ_call_failed` 时间线；`RunawayGuard` 不把取消算作连续失败（现状保持）。
3. `Body.read_stress` 只按账本 `succeeded` 统计，因此新取消调用不进入 `failed_calls`，不触发压力自检。
4. 新增测试证明：取消的 organ 尝试是 succeeded；取消写入账本后压力失败数为 0；真实失败仍照常计入。
5. 不改账本结构和历史记录；历史里已有的取消记录保持原样，不迁移、不改写。
6. 不真实调用模型。

## 行为细则和边界情况

1. 取消发生在请求已经发出之后：仍然估算用量并记账，费用按现有规则计算；不丢账。
2. `OrganCallCancelled` 只记录用量，不写失败时间线；与急停/关闭时的行为一致。
3. 真实超时、断线、服务商错误仍为 `succeeded=False`，压力照常上升；本任务只改取消。
4. 历史账本不可更新；旧的取消记录会留在压力窗口里，直到被新记录挤出。不删除、不改写。
5. 取消仍会让正在进行的生成停止；不改变打断、重规划、投递和分段行为。
6. 模型测速等其它调用路径不受影响；它们不使用取消分支。
