## 目标和验收

一句话：**在保持单意识体、串行思考、状态写入走子系统接口的前提下，用滑动驻留和提及拉注意力减少同群重复选会话的等待；把同步数据库、首包等待和任务级无上限等待移出回复主链路；把前端从“事件后整页重取”改成增量更新；借鉴 MaiBot 的运行时治理与前端工程，但不引入多会话并行、插件运行时或 Electron。**

验收标准按批次列出，每条对应后面的测试。

### A. 驻留与注意力

1. 进入一个平台会话后开始滑动驻留窗口，默认 300 秒；该会话每来一条新消息、每成功排队/投递一段回复、或规划器明确 `stay_in_conversation=true`，窗口从当前时刻重新计时。
2. 活跃交谈期间窗口不会到期；窗口到期只在“当前没有在途 thought、该会话没有待投递分段”时生效；到期后允许立即重新选择收件箱，不再额外等 5 分钟空闲。
3. 规划器仍可用 `stay_in_conversation=false` 主动离开；离开在当轮结束后生效，有待投递分段时先发完。
4. 其他群出现 @/提及且当前处于驻留时，规划器上下文里出现一条**不含原文**的摘要（会话名、提及条数、当前会话最近活动量）；规划器自行决定留下或离开。当前会话“交谈甚欢”时留下是默认倾向，不由代码强制。
5. 绑定用户、特别关心的来信仍按 D137/D140 立即抢占；提及不会切断正在进行的 thought。驻留到期、提及拉注意力都不产生第二个并发 thought。
6. `inbox_residence_seconds=0` 时关闭窗口，行为回到 3.65：规划器决定进出，无空闲到期；`mention_pull_enabled=false` 时不注入摘要。
7. 权限丢失、急停、路由被禁用时立即结束驻留，不等窗口；错误朝安全方向倒。

### B. 单轮链路与尾延迟

1. 回复主链路中列出的同步 SQLite 调用移出事件循环：拍内时间线查询/追加、`mark_read`、`index_more`、网页 `/api/history`、`/api/timeline`、`/api/overview`。用一个写线程串行化时间线追加，保证追加顺序和 append listener 顺序不被打乱。
2. 流式模型调用有首包超时，默认 30 秒；超时按现有器官顺延规则换下一个模型/服务商。首包超时只结束本次尝试，不伪造回复。
3. 每轮 thought 有总时限，默认 180 秒；超时取消本轮生成，记录一条“思考超时/未完成”的时间线事件，不发假回复；已排队的分段继续投递。
4. 同一服务商连续失败 3 次后熔断 60 秒，冷却后放行一次探测；成功清零。熔断只影响该服务商，不影响账本、预算、安全和其它服务商。
5. 补齐阶段计时：入队等待、防抖、组装、planner、replyer、分段、首次投递、末段投递；写入本轮 trace/日志，观察页可读。没有计时证据，不宣称“变快”。
6. 模型客户端按服务商复用；提示词稳定前缀与缓存命中作为测量项，不在本任务里盲改提示词结构。
7. 短回复跳过分段、打字速度调整只增加开关和测量，默认值不变；维护者试聊后再决定是否启用。

### C. 前端流畅性

1. 聊天页收到 WS 事件后只追加/更新变化的消息，不再调用 `loadChatHistory()` 整段重取；断线重连或发现序号缺口时才补拉一次。
2. 聊天 DOM 有上限（默认 500 条）；超过时移除最旧节点，顶部提供“更早的消息”，按 `before_id` 分页前插并保持当前滚动位置。
3. 时间线/总览按 `since_id`（`id > since_id`，现有 `TimelineQuery` 已有该字段）增量取数，不再因每条事件整页重取；筛选条件变化时才全量重载。
4. 有 WS 时不再轮询输入状态、收件箱活动和总览；保留断线后的低频回退（输入 3 秒、收件箱 15 秒、总览 10 秒），页面隐藏时暂停，恢复时只追一次。
5. 学习工作台搜索加 250 毫秒防抖；表达列表的过滤/分页放服务端；表情 10 秒、向量空间 5 秒轮询改为 30 秒或按需刷新。
6. 3.64 已测得的冷启动指标不得回退；新增“持续更新”验收：合成 1000 条历史 + 连续 20 个事件，聊天 DOM 不超过上限，更新期间不出现整表重排。

### D. 可靠性与工程门禁

1. 网页入站队列有上限（默认 500）；满了明确拒绝并提示，不静默丢弃；平台收件箱已持久化，不设丢弃上限。
2. `TimelineDatabase` 和 `InboxStore` 的跨线程使用有明确归属：每个线程用自己的连接；时间线追加由单写线程串行；append listener 回到事件循环执行。
3. 只对可安全重跑的后台任务做监督重启（索引、向量补建、可重入的维护任务）；心跳、时间线、账本、权限等状态错误仍 fail-fast，不自动重启后带着不完整状态继续跑。
4. `scripts/check.py` 全绿；学习工作台 `npm run build` 与 `tsc --noEmit` 通过；文档漂移（`aiosqlite`、`A_memorix`）修正。
5. 不新增真实模型、真实 QQ、真实网络依赖；全部用假时钟、假器官、`httpx.MockTransport`、临时 SQLite 和合成浏览器夹具。

## 接口

### 驻留

`InboxAttention` 增加以下成员；不改变 `InboxResidence` 的 `eq=False` 身份语义（续期不能替换对象，否则在途批次会失权）。

- `__init__(..., clock: Clock, residence_seconds: float, mention_pull_enabled: bool)`：新增时钟和配置；`residence_seconds=0` 表示关闭。
- `read_selection(selection: InboxSelection, *, now: datetime) -> list[InboxMessage]`：进入成功时设置 `_residence_deadline = now + residence_seconds`。
- `active_messages(*, now: datetime) -> list[InboxMessage]`：读到消息时调用 `renew(now)`。
- `apply_plan(plan: Plan, target: Perception, source: TimelineRecord, *, now: datetime) -> None`：`stay_in_conversation=true` 创建/续期；`false` 只标记离开意图，由调用方在轮末处理。
- `renew(now: datetime) -> None`：仅当 `_staying` 且 `residence` 存在时把截止时间推到 `now + residence_seconds`；窗口关闭时是空操作。
- `expire_if_due(now: datetime) -> bool`：截止时间已到且 `_staying` 时把 `_staying=False`，保留 `residence` 供在途投递；返回是否刚刚到期。窗口关闭时始终返回 `False`。
- `deadline: datetime | None`：观察页/测试用。
- `mention_pull_summary(exclude: ConversationKey | None, *, limit: int = 3) -> tuple[MentionPull, ...]`：返回其他允许会话的提及摘要；不含正文、不含发送者账号。
- `InboxStore.list_mention_conversations(limit: int = 5) -> list[tuple[ConversationKey, str, int]]`：单次 SQL 按会话统计 `mentioned=1`、`trust != UNVERIFIED`、未读条数，返回完整路由、展示名、条数；`mention_pull_summary` 只在这里返回的候选里过滤 `allows`，不逐会话扫全表。
- `MentionPull`（dataclass，frozen）：`conversation: ConversationKey`、`name: str`、`count: int`。

`InboxResidence` 不变；`permits()` 仍只检查身份和路由权限，不检查截止时间。到期由 `Heartbeat` 在安全时机调用 `expire_if_due`，避免在 thought 进行中切断。

### 心跳

- `_maybe_start_thought`：在 `self._thought is not None` 判断之后、组装 batch 之前，调用 `inbox.expire_if_due(now)`；只有 `_thought is None` 且 `not outbox.has_pending_conversation(...)` 时才让到期生效。到期后 `active_conversation` 变为 `None`，`browse` 可立即给出候选。
- `_take_in_perceptions(browsing=True, residence=...)`：整批处理完后，如果 `residence is not None` 且本批至少有一条来自该驻留会话，调用 `inbox.renew(now)` 一次（不是每条一次）。
- `_enqueue_reply` / `_deliver_due`：为当前驻留会话排队或投递一段回复后调用 `renew(now)`；失败/拒收不续期。
- `_maybe_start_thought` 组装 job 时，如果 `job.residence is not None` 且 `mention_pull_enabled`，把 `inbox.mention_pull_summary(exclude=job.residence.conversation)` 放进 `_ReplyJob.mention_pull`。
- 不新增第二个 `_thought`；所有 new task 仍受现有 `_thought`/`TaskGroup` 约束。

### 规划器

`_ReplyJob` 增加 `mention_pull: tuple[MentionPull, ...] = ()` 和 `recent_message_count: int = 0`。后者是当前会话最近 5 分钟的消息条数，由 `_reply_job` 从已经组装好的 `history`/`messages` 实算，不额外查库；窗口被截断时只保证“至少 1 条”，不把截断当成 0。

`Conversation._plan` 在规划器上下文里增加一段纯文本（不调用模型、不新增工具）：

```text
【收件箱动态】当前会话最近 5 分钟有 6 条新消息。其他会话有人点名你：群「A」2 条、群「B」1 条。
如果你觉得当前已经聊完，可以设置 stay_in_conversation=false 去回应；如果还在热聊，就留下。
```

规则：

- 只在 `job.residence is not None` 时出现；优先批次（无驻留）不出现。
- `recent_message_count=0` 时省略第一句；不要编造数字。
- 最多列 3 个会话；超过时写“另有 N 个会话”。
- 不写消息正文、不写发送者账号；会话名沿用收件箱展示名。
- `stay_in_conversation` 的 schema 和语义不变；不新增工具，不改变 planner 的其它决策。

### 数据库

在 `aureus/common/sqlite.py` 或 `aureus/timeline/database.py` 增加最小异步包装：

- `TimelineDatabase.async_append(...) -> TimelineRecord`：提交到单写线程执行；同一实例内的异步追加按提交顺序串行；append listener 通过 `loop.call_soon_threadsafe` 回到事件循环后执行。
- `TimelineDatabase.async_query(query: TimelineQuery) -> list[TimelineRecord]`：提交到有界读线程池（默认 2 个 worker）；每个线程用 `threading.local()` 自己的连接。
- `InboxStore` 的写方法提供同样的 `async_*` 包装时，必须使用同一写线程或明确锁；不要让事件循环和 `to_thread` 共享同一个 `sqlite3.Connection`。
- 同步方法保留给 CLI、测试和启动阶段；心跳/网页热路径改用 `async_*`。
- 连接工厂继续走 `open_connection`；WAL、busy_timeout、只读模式的语义不变。

### 模型

- `ProviderConfig.first_token_timeout_seconds: float = 30.0`（`0` 关闭，范围 5–120）。
- `ModelsConfig` 增加 `circuit_breaker: CircuitBreakerConfig`：默认 `enabled=true`、`failure_threshold=3`、`cooldown_seconds=60`；字段校验在模型配置加载时完成，不放进 `OrganConfig`（`[organs.*]` 是每个器官的路由，不能混入全局开关）。
- `llm_adapter`：普通流式调用把 `first_chunk_timeout` 设为 `min(provider.timeout_seconds, provider.first_token_timeout_seconds)`；非流式沿用总超时。首包超时抛出现有 `_FirstChunkTimeoutError` 同类的可重试错误，由上层顺延。
- 熔断按服务商名记录连续失败；冷却期内直接跳到下一个服务商；半开只放行一个探测。账本仍记录“被跳过”的原因，不记成功用量。

### 前端

- 新增 `loadChatSince(cursor)`：复用 `/api/history?replies_only=true&since_id=...`，只 append 新记录；`loadOlderChatHistory()` 用 `before_id` 前插。
- `chatEntries` 上限 `CHAT_MAX_ENTRIES=500`；`trimChatEntries()` 同步移除 DOM 节点和日期分隔；顶部“更早的消息”按钮。
- `handleLiveEvent`：
  - `chat` topic：如果 WS 已直接送回 `OutgoingMessage` 且 `delivery_key` 已存在，只更新状态，不重取；否则调用 `loadChatSince`。
  - `timeline` topic：调用 `loadTimelineSince(lastId)`；筛选变化才全量。
  - `inbox` topic：只刷新变化的会话摘要或调用轻量 `/api/inbox/conversations`，不重取全部消息。
  - `overview`/`round` topic：更新计数，最多 2 秒合并一次；页面隐藏时暂停。
- 轮询常量：`TYPING_REFRESH_MS` 仅在 WS 断开时启用（3000）；`INBOX_ACTIVITY_REFRESH_MS` 回退 15000；`OVERVIEW_SIGNAL_INTERVAL_MS` 回退 10000；WS 正常时不轮询。
- 学习工作台：`searchDebounceMs=250`；表达列表请求带 `page/pageSize/search/filter`，后端在 SQL 层过滤/分页；表情/向量空间轮询降到 30 秒或按需。
- `/api/timeline` 暴露 `since_id`（`id > since_id`，按 id 升序），与 `before_id` 互斥；`/api/history` 继续用现有 `since_id`。不另造 `after_id`。
- 页面启动时从现有 `/api/status` 读取 `incremental_updates` 布尔值（缺省 true）；服务端在设置可用时返回。关闭时页面走 3.64 的整页刷新路径，作为对照和排障开关。

## 行为细则和边界情况

### 驻留

1. **进入**：`read_selection` 成功读到消息并占用会话时开始计时；`apply_plan` 在规划器对尚未驻留的会话说 `stay_in_conversation=true` 时也可以开始计时。普通优先来信只回复、不自动驻留；是否留下由规划器当轮决定。
2. **续期**：该会话新消息入时间线、成功排队/投递一段回复、规划器 `stay=true`，三者任一发生都续期。其他会话的消息不续期。
3. **到期**：只在没有在途 thought、且该会话没有待投递分段时生效；有在途 thought 或 outbox 时推迟到下一次安全时机。到期不取消已经在生成的回复，也不丢已排队的分段。
4. **到期后的重新选择**：`expire_if_due` 把 `_idle_since` 设为 `now - _IDLE_BEFORE_READING`，使 `browse` 不用再等 5 分钟；但 `browse` 仍受 `can_browse`（精力、权限、安全）约束。
5. **规划器主动离开**：`stay_in_conversation=false` 在当轮结束后生效；如果 outbox 还有该会话的分段，先发完再切换（沿用 D140）。如果当轮是最后一段，直接结束驻留。离开后不再从该会话读取新批次；已读但尚未开始的批次不再启动新 thought，按 D145 在下次进入时重新读最新，避免离开后又被旧批次拉回去。
6. **抢占**：绑定用户/特别关心仍通过 `_interrupt_inbox` 立即结束驻留；提及只进队列并出现在摘要里，不切断当前 thought。紧急停止、权限丢失、路由禁用立即结束，不看窗口。
7. **窗口关闭**：`inbox_residence_seconds=0` 时不设置截止时间，`expire_if_due` 永远返回 `False`；其余逻辑（规划器 leave、抢占、提及摘要）仍按配置生效。
8. **重启**：驻留状态不持久化；重启后没有驻留，按现有收件箱/优先消息流程重新进入。这是有意为之，避免重启后凭空占住一个会话。
9. **单意识**：不新增 `_thought` 之外的回复任务；提及摘要只是 planner 输入，不是第二个规划器。判断、表情等并行调用仍受现有网关许可约束。

### 提及摘要

1. 只统计 `mentioned=1`、`trust != UNVERIFIED`、路由 `allows` 的未读；与 D137 的唤醒范围一致。
2. 排除当前驻留会话；没有其他会话时返回空，不注入提示。
3. 每个会话只取条数，不取正文；最多 3 个会话，按未读数从多到少。
4. 摘要每轮都可以出现；规划器选择留下时，下一轮仍会出现，直到提及被处理或驻留结束。
5. 摘要不改变优先级队列；即使规划器留下，提及仍在 `_unanswered` 里按 `Priority.MENTION` 排队，不会丢失。
6. 当前会话最近活动量只数 `_ReplyJob.history` + `messages` 里时间戳在最近 5 分钟内的记录；不额外查库，不读正文。历史窗口被截断时只写“有新消息”，不把截断当 0。

### 延迟与超时

1. **数据库**：时间线追加必须保持顺序；异步追加用单写线程，不能用普通 `to_thread` 并发写。读线程池默认 2 个 worker，队列满时等待，不丢查询。
2. **append listener**：现在监听器在追加线程里同步调用；改为异步追加后，监听器必须回到创建 `TimelineDatabase` 的事件循环执行，避免 `LiveEventHub` 队列被跨线程写坏。
3. **首包超时**：只对 `request.stream=True` 的调用生效；非流式仍用服务商总超时。超时后关闭流、记失败、按现有 `OrganCallError`/顺延路径处理；不把半截文本当回复。
4. **thought 时限**：从 `_think` 开始计时；超时取消生成任务，写 `EVENT_THOUGHT_TIMEOUT`（新事件类型）或复用现有中断事件并在 metadata 标 `reason=deadline`；不写 `reply_delivered`。已排队分段继续投递；未生成的部分不补。
5. **熔断**：按服务商名统计连续失败；成功一次清零。被熔断跳过时记日志/账本原因，不消耗 token。冷却结束只放行一个探测，探测失败重新计时。熔断跳过不记作一次器官失败，避免误触发全局 `RunawayGuard`；后者仍按真实调用失败计数。
6. **重试层级**：确认 `num_retries=0` 或只有一层重试；首包超时和 thought 时限由 Aureus 控制，避免 SDK 重试把最坏时长再乘一次。
7. **测量**：阶段计时至少包含 `inbox_wait_ms`、`debounce_ms`、`context_ms`、`planner_ms`、`replyer_ms`、`split_ms`、`first_delivery_ms`、`last_delivery_ms`；用单调时钟，不用系统时间。观察页只读展示，不新增写接口。

### 前端

1. 聊天增量：以 `delivery_key`（`timeline_id:segment`）去重；没有 `id` 的消息不进增量路径，退回一次补拉。
2. 上限：超过 500 条时从最旧开始删；删除时保留当天日期分隔的正确性；只删 DOM 和内存，不删后端时间线。
3. 前插旧消息：记录插入前的 `scrollHeight/scrollTop`，插入后按高度差修正；用户不在底部时不要强制滚到底。
4. 断线：重连后先 `catchUp` 一次；如果 `since_id` 缺口超过 200 条，整段重载一次，避免逐页补。
5. 轮询回退：WS `open` 后清掉回退定时器；WS `close` 后按上述低频恢复；页面 `hidden` 时暂停，恢复时只追一次。
6. 学习工作台：搜索防抖只影响请求，不改变已选过滤；服务端分页保持 `keepPreviousData`，避免翻页闪烁；轮询降低后仍支持手动刷新。
7. 3.64 的 `timelineGeneration`/请求交错保护保留；增量更新不能回填旧快照。

### 可靠性

1. 网页入站队列满时，`WebChannel.send` 返回明确错误，WS 向用户回一条“当前太忙，请稍后再发”；消息不写入时间线，避免“看起来发了但没处理”。
2. 时间线/收件箱连接按线程归属；跨线程共享 `sqlite3.Connection` 视为 bug，测试要能发现。
3. 后台任务监督只覆盖白名单：索引、向量补建、可重入的维护任务；每个任务最多重启 3 次，间隔 1/5/30 秒，日志写明原因。心跳、账本、时间线、权限相关任务不自动重启。
4. 优雅停机保持现有顺序，新增的写线程/读线程在 `shut_down` 里排空并关闭；不留下挂起线程。
5. 任何新开关都能单独关闭；关闭后行为回到 3.65，不需要回滚代码。

## 坑

1. **`InboxResidence` 身份**：`permits()` 用 `is` 比较；续期不能替换对象。截止时间放在 `InboxAttention` 的独立字段，不要塞进 frozen dataclass 后重建。
2. **`browse()` 的 5 分钟**：`_IDLE_BEFORE_READING` 是“空闲多久才允许主动翻阅”，不是驻留窗口。驻留到期后要显式让它立即有资格，否则会出现“5 分钟驻留 + 5 分钟空闲”叠成 10 分钟。
3. **D140 的在途投递**：到期/切换前必须检查 `ReplyOutbox.has_pending_conversation`；不要为了“准时离开”丢分段。
4. **单 thought**：`_maybe_start_thought` 的 `if self._thought is not None: return` 是单意识体的核心约束；任何新逻辑不能绕过它。不要在 `InboxAttention` 里创建任务。
5. **同步 SQLite 连接**：`TimelineDatabase` 现在持有一个 `check_same_thread=False` 的连接；`to_thread` 共享它会踩并发。每个线程一个连接；写用单线程；listener 回事件循环。
6. **append listener 顺序**：网页实时事件依赖追加顺序；异步追加不能让 listener 在写线程里直接 `put_nowait` 到 asyncio 队列。
7. **测试基线**：仓库全量 pytest 有既有失败（3.65 记录 12/6 等分组基线）；比较失败 ID，不要用“全绿”当结论。
8. **Windows/编码**：新 Python 文件 LF、UTF-8；`docs/10-decisions.md` 是 CRLF，追加时保持；路径用 `Path`，不写死盘符。
9. **无根 conftest**：fixture 在各测试文件里；新测试自包含，不要假设全局 fixture。
10. **前端缓存/交错**：3.64 的 `timelineGeneration`、`inFlightGets`、页面缓存 TTL 都要保留；增量路径不能回填旧快照。
11. **WS 双通道**：聊天页同时收 `OutgoingMessage` 和 live event；同一 `delivery_key` 不能重复插入，事件不应触发整段重取。
12. **配置文件位置**：示例配置进 `config/aureus.example.toml`；不要改 `aureus_home/`、不要读 `identity.toml`/密钥。
13. **提交**：只用 `git add` 指定文件，不用 `git add -A`；不 push；不代重启。
