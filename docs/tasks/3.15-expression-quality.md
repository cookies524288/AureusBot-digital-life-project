# 3.15 · 表达质检与人工挽回

状态：实现中。对应[学习工作台](3.15-resource-console.md)。先读 `heartbeat/language_runner.py`、`heartbeat/language_requests.py`、`memory/language.py`、`web/resource_api.py`、`web/static/resource-management.js`（均在 `aureus/`）和固定版 MaiBot `expression_learner.py::_check_expression_before_upsert`、`expression_utils.py::check_expression_suitability` 与 `ExpressionReviewLogPanel.tsx`。

1. **独立质检。** 已有 `learn_language` 按会话和来源分别抽取表达与黑话，不能将 `observe_extraction` 的一次提交拆成裸写。先用同一套确定性规则挑出合法情境和说法，再以可选的独立质检调用核对是否匹配、是否过于特指；允许口语、省略，不带整段私聊或其它候选。以 `language` 的独立开关和器官路由配置这一步；默认不替已有用户新增付费调用，关闭维持现流程。走既有可选调用的预算、安全网关、取消和 Prompt 预览；开着而路由缺失、错误或预算拒绝时不采纳，不能改用廉价的固定结论。每批数量沿用表达候选上限；不影响黑话的独立消费。设置新增字段也须有中文名称、帮助与搜索。
2. **证据及挽回。** 将去重后的稳定来源键、受限的情境/说法、时间、通过/拒绝/错误及短理由与该次消费结果一起写入；不保存完整请求、原始返回、对话原文或凭据。模型通过仍为人工待审。按日期、来源/状态筛选质检记录并可直接跳页；在表达工作区与人工审核日志明确区分。维护者从已拒条目预览并挽回时重新核对来源、范围、移除状态与条目版本；重复、撤权、篡改或撤回都不得扩大可用范围。保留原判断与后续操作，不因载入面板调用模型。原有人工审核/移除/范围规则继续约束真正的回复候选。
3. **表达向量运维。** 核对已有 `ExpressionVectorIndex` 与簇浏览。列出实际向量空间、来源候选与完成数；允许对所选可用空间发起有限、可取消且有费用说明的补建，复用网关及原写入器，不顺带重建全库。独立登录授权后方可展示簇成员；真实写入或有据可查的失败才更新状态。仅安装模型、存在缓存或页面刷新都不是已建完的证据。

自检：相同材料在关闭、拒绝、异常、合法通过时，核对调用数量、真实库及回复请求；重复源、同名不同群、模型通过未人工审、拒绝后挽回及取消、无效来源与已移除条目均用合成库覆盖。向量行为用假器官，校验实际补建、取消及未授权簇零披露。不改正式路由、不发收费请求。
