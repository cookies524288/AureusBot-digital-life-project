## 目标和验收

独立页面管理密码、API key、其他类型秘密；保存后只列名称与类型，可以改名和删除，模型通过名称选择 API key。改名不破坏引用。

## 接口与配置

- SecretVault 继续使用现有随机主密钥和 Fernet 容器，启动自动解锁；登录密码只管理网页权限，不保存登录明文。
- 容器 v2 的密文中保存稳定 id、name、kind、value 及旧环境变量兼容名；兼容读取 v1，首次成功修改时升级，不另存明文。
- 新增 VaultEntry、load_entries/create/rename/remove_entry；原 load/set/remove 与 CLI 兼容。类型为 password/api_key/other，名称 1–128 字、不可含控制字符，名称唯一。密码与其他类型保留空格及换行，API key 去除首尾空白。
- ProviderConfig 新增 api_key_ref（库内稳定 id），与 api_key_env 互斥；旧环境变量配置仍有效。仅 API key 类型可提供给模型；显式库内引用不回退到环境变量。旧名字改名保留旧配置兼容映射。
- GET /api/keys 返回 vault/names/entries，entries 仅 id/name/kind；POST /api/keys 新建，POST /api/keys/rename 改名，POST /api/keys/remove 支持 id；保留旧 PUT 与按 name 删除。所有写操作继续本机限制、登录、确认当前密码和限流。
- 网页修改后刷新运行中 resolver 的内存快照；新增值先加入日志过滤，删除后的旧值仍过滤到进程结束，保护在途请求。过滤器可以通过 shutdown_logging 清空。文件写失败不替换内存。CLI 跨进程修改仍需重启。

## 行为细则和边界情况

- 原文不返回 HTTP、不进入保存后的 DOM、日志、错误；录入框为密码框，提交后清空，关闭编辑也清空。
- 重复名称拒绝覆盖；改名不变更类型或原文；删除被引用 API key 后显示缺失，调用在本地失败。
- 坏库、缺主密钥、未知版本继续拒绝读写，不回退、不覆盖。原子写与进程文件锁继续使用。
- 服务商敏感引用修改继续确认密码；普通环境变量不能通过任意名称读取。
- 保留现有配色、圆角、导航、半透明提示和动效，不引入构建依赖。
