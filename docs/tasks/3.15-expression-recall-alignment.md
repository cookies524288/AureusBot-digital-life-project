## 目标和验收

表达召回的候选数、选择方式和注入格式与 MaiBot 一致。

验收：

1. 向量召回候选上限默认 50，可由 `[language] expression_vector_candidates` 配置（1–50，越界报错）。
2. 召回后调用独立的 `expression_selection` 任务，选择 0–5 条；选择失败或未配置 fast_model 时退回向量前 5，不整池注入。
3. 注入 replyer 的表达块不再按字数裁剪，选中的条目原样出现；`reference_chars` 只影响黑话块。
4. 关键词回退路径同样不按字数裁剪，仍最多 3 条。
5. 现有向量算法（簇中心加权、MMR）不变。

## 行为细则和边界情况

1. `expression_selection` 的提示词沿用现有 `_select`（候选编号 + 情景/风格 + 0–5 条 + 严格 JSON），与 MaiBot 同构。
2. 选择结果为空数组时，本轮不注入表达块（与 MaiBot 一致）。
3. 选择的编号越界、重复或非整数，按现有规则过滤；全部无效按「空数组」处理。
4. 没有配置 fast_model、安全网关拒绝或调用失败时，退回向量前 5；这一条与 MaiBot「整池注入」有意不同，避免把 40–50 条塞进提示词，任务文档与代码注释写明。
5. 表达式快照指纹复验（`_current_fingerprints`、撤权检查）保持现状：选择前后都要复验，失效的候选丢弃。
6. `reference_chars=0` 仍表示关闭黑话参考；表达召回由 `recall_enabled` 控制，不再依赖该值。
7. 不做：改变向量索引构建、改变学习写入、改变黑话召回。
