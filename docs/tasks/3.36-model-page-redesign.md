# 3.36 模型配置页按 MaiBot 布局重做

状态：待实现（2026-11-26 实现者发现后端缺字段，见「待设计问题」，暂停）
设计：维护者 2026-11-26 指令与五张 MaiBot 模型页截图；布局同款、视觉保留 Aureus 圆角风格

## 目标

模型配置页的信息结构、布局和操作逻辑与 MaiBot 的模型管理页一致，控件使用 Aureus 现有圆角与配色；后端配置格式与现有接口不变。

## 布局（参考截图）

1. **左侧厂商栏**：标题「模型厂商」，右上「+」添加厂商；第一项「全部」带数量；每个厂商显示名称、`base_url`、该厂商模型数；选中项高亮。
2. **右侧主区**：顶部搜索框（模型名称、标识符或提供商）；右上「添加」模型。
3. **模型表格**：列为「使用（启用勾选）」「模型名称」「模型标识符」「提供商」「视觉」「默认输入价」「默认输出价」「操作（测速 / 编辑 / 删除）」；价格按 ¥/M token 显示；启用状态用勾选框。
4. **编辑模型弹窗**：
   - 模型名称、API 提供商（下拉）；
   - 模型标识符：可下拉选择该厂商可用模型（带搜索与刷新按钮），也可手填；
   - 启用视觉（勾选）；
   - 默认价格：输入 / 输出 / 缓存（¥/M token）；
   - 分时价格：可添加时段（每日、服务器本地时间、价格）；
   - 启用思考（写入 `thinking.type`）+ 思考力度（低/中/高）；
   - 启用联网搜索（仅支持的协议）；
   - 自定义模型温度、自定义最大 Token（各带开关）；
   - 额外参数：显示已配置参数数量；提供「可视化编辑」（键/值/类型，支持嵌套对象与数组）和「JSON 编辑」（实时校验与预览）两种模式；
   - 底部「取消 / 保存」。
5. **添加/编辑厂商**：名称、协议、`base_url`、密钥来源，沿用现有配置字段。

## 行为与边界

1. 后端仍使用 `models.toml` 的 providers/models 结构与现有 API；不改配置格式、密钥来源与器官绑定。
2. 启用/停用、测速、删除都要落到现有接口；删除需确认；测速沿用现有模型测试。
3. 搜索与厂商筛选只影响列表展示；数量统计随筛选更新。
4. 保存后刷新列表并保留当前筛选与选中厂商；失败显示原因。
5. 窄屏：厂商栏折叠为顶部下拉或横向列表；表格改卡片；弹窗全宽。
6. 保留现有全部功能（密钥管理、器官绑定、模型目录等入口不丢）。

## 待设计问题

2026-11-26 实现者：按任务文档核对现有后端后，以下需求与「不改配置格式（models.toml 的 providers/models 结构）、不改器官绑定、不改 llm_adapter.py」冲突，暂停实现，请维护者拍板。

### 1. 表格「使用（启用勾选）」和「启用/停用」

- 现状：`aureus/organs/model_config.py` 的 `ModelConfig` 没有 `enabled` 字段；`models.toml` 里唯一能表达「这个模型是否在用」的是 `organs.*.models` 的引用。现有 `/api/models` 只读写整份配置。
- MaiBot 参考：`dashboard/src/routes/config/model/components/ModelTable.tsx` 的「使用」列是绿色圆点（按任务分配显示是否使用），不是开关；最左侧复选框是批量选择，不是启用。
- 可选做法：
  - A. 只读指示：按器官引用显示勾选/圆点，禁用勾选；不改配置。缺点：没有「停用」操作。
  - B. 新增模型级 `enabled` 字段，路由跳过停用模型；需要改配置格式、`model_config.py`、`model_runtime.py`/`llm_adapter.py`，超出本轮约束。
  - C. 勾选等同把模型加入/移出某个固定器官（如 replyer）；需要指定器官，且会改器官绑定，与本轮约束冲突。
- 请选择 A/B/C，或另开后端任务。

### 2. 分时价格

- 现状：`ModelConfig` 只有 `price_in`、`price_out`、`price_cache_in`（元/百万 token），没有 `price_periods`；`llm_usage.py` 计费只读这三个字段。
- 影响：弹窗里的「分时价格（每日、服务器本地时间、价格）」没有落盘位置，也没有计费读取方。
- 需要：新增模型字段并改计费/账本（后端任务），或本轮只显示默认价格、去掉分时价格区块。

### 3. 启用思考 + 思考力度

- 现状：`ModelConfig.reasoning_levels` 只声明「支持哪些等级」；真正选择等级的是器官的 `OrganConfig.reasoning_effort`；`llm_adapter._chat_kwargs` 只传 `reasoning_effort`，不传 `thinking.type`。
- 影响：任务要求的「启用思考（写入 thinking.type）+ 思考力度（低/中/高）」没有模型级字段；若把 `reasoning_levels` 当开关，语义变成「声明支持等级」，与「写入 thinking.type」不同。
- 需要：新增模型级思考配置并改适配器，或本轮保留现有「支持的思考等级」控件（与截图语义不同）。

### 4. 启用联网搜索

- 现状：模型配置没有联网搜索字段；`llm_adapter.py` 没有注入原生 web_search 工具的逻辑；`aureus/safety/permissions.py` 的 `web_search` 是另一套器官权限，不是模型参数。
- 影响：勾选后没有落盘位置，也不会改变请求。
- 需要：新增字段并改适配器/工具编码（后端任务），或本轮不显示该开关。

### 5. 额外参数（可视化 + JSON）

- 现状：`ModelConfig` 的 `extra="forbid"` 会拒绝任何额外字段；`llm_adapter._chat_kwargs` 只组装 `temperature`、`max_tokens`、`reasoning_effort`，不会发送额外参数。
- 影响：可视化/JSON 编辑没有保存目标，即使前端保存也会被后端 422 拒绝；强行保存到别处不会影响调用，属于装饰，违反设计原则。
- 需要：新增模型级 `extra_params` 字段并让适配器合并进请求（后端任务），或本轮不显示该区块。
