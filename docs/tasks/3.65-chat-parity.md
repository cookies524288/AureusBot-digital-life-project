# 路线图 3.65：聊天基本功与 MaiBot 插件效果

状态：**01–22、24–28 共 27 项已实现，离线验收通过（2026-11-27）；23 不做。** 设计：D147；选择依据、每项验收场景和上游源码见[对照表](../maibot-chat-parity-plan.md)。编号沿用对照表。正式 QQ 试聊与真实模型对比未进行。

## 目标与接口

1. **会话与原件**：01 选回复目标、02 点名上下文和引用唤醒、03 解引用、04 熟人和发言者归属、05 实际投递历史、06 跨轮媒体。用本轮候选的稳定消息键选人，未给目标兼容单消息；不可伪造编号、换会话或借引用升级权限。只读已获准的原件，摘要有真实来源。
2. **QQ 动作**：07 正文后补图、08 单图回复、09 斗图或复读、10 原生表情、11 贴表情、12 群内主动戳、13 被戳回应、14 撤回自己指定消息、15 撤回通知/可选跟撤、16 原生 @。模型只提出动作，运行时验证目标，通道依 SnowLuma 返回值记实；过期、重复、平台拒绝不产生虚构成功。跟撤独立开关，不另连旁路。一个动作只有一个出站路径。
3. **节奏与媒体**：17 定时回看、18 有限续话、19 按位置重发同会话旧图、20 转发与卡片、21 普通动图/视频/音频/文档、22 正文/分段/纠错。17–18 用注入时钟，不循环自启；19、21、28 区分收到、理解和允许发送。无法提取不冒充看过；22 不破坏代码、URL 与引用，纠错可复用 14，刻意制造错字不默认开启。
4. **插件能力**：24 查询实际群名单、25 通用梗词典（未知就说未知）、26 提醒的建立/查询/取消/到期判断、27 主人的限时跨会话叮嘱、28 受托发送指定文件/普通图片。24 不给普通成员整份名单。26 默认原会话，跨流须主人及获准目标；27 一次有效发言后消费，未发不算；28 只在获准的素材范围内送回授权会话，拒绝任意文件路径。

## 不做与协作

23 不做。除 27 特定叮嘱外不新增任意跨会话原文访问或转发；不改人设、不读 MaiBot 私人配置/库、不打开正式数据根。3.64 收尾后，维护者允许为聊天功能补必要前端：仅给已有设置页登记新开关、中文释义和分段选项，不改变布局或扩大配置权限；通用梗字典沿用文件配置，仅提示条数与编辑位置。保留 3.64 任务、证据、预览进程及交接段落。不启停正式实例。未安排真实平台、真实模型或花费。

21 对照文件阅读插件的公开说明：除文本附件外，补 DOCX 的段落、XLSX 的单元格、PPTX 的幻灯片以及有文本层的 PDF。只在原会话已有权限的文件流内取有界摘录，不运行宏、不访问外部引用；缺少可选本地 PDF 解码器、没有文本层或超限时不给虚构摘录。28 发送素材的授权不因此扩大。

20 的来源边界：收到转发或卡片，可以回答其中谁说了什么，也可以结合发送者的问题讨论；同一条消息不作为创建/取消提醒、留下主人叮嘱或列取/外发受托素材的授权，即使引文旁边还有「看看这个」等正文。要委托这些动作，发送者另发一条自己的文字即可，可以引用刚才的原件。

## 维护者如何试聊

以下是重启后在已授权测试群或私聊的观察点，不需要启用新群或导出私人对话。小豆仍可选择沉默，观察的重点是**一旦回应，是否答给对的人、说的是有来源的内容、动作真的出现在 QQ 上**。

- **选人和接话**：甲说「七点南门」，乙再 @ 小豆问「在哪见」。检查回复是否带对地点、引用是否指向它实际在回答的那条，而不是简单回最后发言的人。引用小豆此前的回复再问，不必另 @ 它。
- **补表情和撤回**：有已批准的图时聊一轮轻松话题，观察文字是否先发、同轮至多补一张，中途换话题不追补。引用小豆自己刚发的那条请求撤回，应只影响那一条；对方原话撤回后不应被小豆重新复述。自动跟撤是单独开关，默认关闭，且依赖平台通知。
- **提醒和文件**：先设短提醒，再查询或取消；到点只触发一次判断，不保证发消息。发一份虚构的会议安排，问其中一个具体时间；读得到时应有依据，不能仅凭文件名猜。要求发回普通文件时，只能选择已为当前会话放行的素材。

这不是与 MaiBot 的真实模型盲比。要比较日常聊天质量，可让两边面对相同的虚构对话并匿名打分，分看是否接题、认对人、不抢话及动作自然；该项需要另行安排，不以本轮假器官回放的通过率替代。
