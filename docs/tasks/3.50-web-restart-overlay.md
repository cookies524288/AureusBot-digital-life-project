# 3.50 网页重启后自动等待并重新载入

状态：完成
设计：维护者 2026-11-26 指令（3.49 的网页部分）

## 目标

在网页里点「重启」后，页面显示「正在重启…」并自动等待服务恢复，恢复后自动重新载入；超时显示重试，不留下进不去的页面。

## 实现

1. `aureus/web/static/index.html`：重启按钮触发后显示遮罩与状态文字；轮询 `/api/status`（带退避，最多约 60 秒）；恢复后 `location.reload()`；超时显示「重试」按钮，点击重新开始等待。
2. 遮罩期间禁用其它操作，避免误触；重启失败时显示原因。
3. 不改重启接口与后端行为（后端部分见 3.49）。

## 验收

- 点重启后页面进入等待状态并自动恢复；恢复后回到登录页或原页面；超时能重试；Console 无未捕获异常；窄屏与主题正常。

## 前端实测（2026-11-26）

实现：`#restart-overlay` 放在 `#app` 外，显示时给 `#app` 设 `inert`，遮罩期间不能误点
其它操作。点重启后先显示「正在重启…」，`POST /api/restart` 成功后暂停聊天连接，
用原生 `fetch('/api/status')` 按 500ms→750ms→…→3000ms 退避轮询，最多约 60 秒；
`restart_instance` 变化或 401 时 `location.reload()`。超时显示「暂未连上 Aureus」和
重试/关闭；请求失败显示后端原因和重试/关闭。重试等待只重新轮询，不重复发重启请求；
重试 POST 失败才重新请求。关闭遮罩恢复 `#app` 并重连聊天。

- 重启后自动恢复：在隔离副本上真实点重启，遮罩出现；页面在 45 秒内自动重新载入，
  新页面遮罩隐藏、回到总览，会话仍有效；`Runtime.exceptionThrown=[]`、Console 无错误。
  截图 `E:/Temp/ui-shots/343-13-restart-in-progress.png`、`343-14-after-restart.png`。
- 超时重试：用当前实例调用 `startRestartWait`，真实等待 60.9 秒后显示「暂未连上
  Aureus」、重试和关闭按钮；点关闭后遮罩消失、`#app.inert=false`、WebSocket 仍连接。
  点重试会重新进入「正在重启…」等待态（重试/关闭再次隐藏）。截图
  `E:/Temp/ui-shots/343-20-restart-timeout-real.png`、`343-12-restart-timeout.png`。
- 失败原因：用假 `fetch` 让 `/api/restart` 返回 500 和「测试失败原因」，遮罩显示
  「重启失败」和该原因，提供重试/关闭；截图 `E:/Temp/ui-shots/343-21-restart-failed.png`。
- 窄屏与主题：390×700 浅色 `E:/Temp/ui-shots/343-22-restart-narrow.png`，深色
  `343-23-restart-narrow-dark.png`；遮罩跟随主题变量，文字换行正常。等待态截图
