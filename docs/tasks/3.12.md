# 3.12 · 回复分段与打字延迟

状态：待实现

## 路线与验收

1. 规划器决定回复、回复器产生正常文本后，默认通过安全网关调用 `fast_model` 建议切点。再审驳回先回到规划器。检查流入分段器的内容及次数，验证分段器无法改写或增加原文。
2. 将 `<n>`（强制切点）和 `<!>`（保护当前段）写入实际回复器提示词。指令、长文本、代码保持完整，回复器和快速模型均收到该要求。快速模型另外收到括号、引号内部不切的要求。验证控制标记在聊天和模型可见的历史中已去除，英文和中文的段尾逗号均去除，保护段内部格式完整。
3. 第一段立即投递。从第二段开始，按下一段汉字数乘 0.4 秒、其他字符数乘 0.1 秒，加上 0.3 至 1.7 秒的均匀随机延迟。打字速度和随机范围在设置中可调。使用可控时钟和随机源验证实际发送顺序、时刻及同会话连续两次回复的排序。
4. 一次确定全部分段后，小豆在下一轮思考即可看到本次分段的完整记录。等待后续段的发送时间不会占住心跳。用两轮交错来信检查实际规划上下文，并核对正式投递时的权限、维护关机和程序退出。

## 实施和验证范围

沿用说话方式、会话及各平台公共发送入口。使用假器官和临时数据目录，只运行以上行为涉及的专项。实际提交和验证结果写入本页。
