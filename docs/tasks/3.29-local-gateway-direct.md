# 3.29 本地网关直连，测速首包超时后回退非流式

状态：待实现
设计：D131、D127、D128（docs/10-decisions.md）

## 先读

- `aureus/organs/llm_adapter.py`：`_read_stream`、`probe_model` 的流式分支、`LLMOrgan` 的普通对话调用、`local_expression_endpoint` 的本地判定、共享客户端 `close_embedding_clients`。
- `aureus/organs/model_config.py`：`ProviderConfig`、`DEFAULT_TIMEOUT_SECONDS`。
- 测试：`tests/organs/test_llm_adapter.py`。

## 目标和验收

本地 OpenAI 兼容网关（MAGPIE 等）的测速与调用不再超时、不引入额外延迟；不支持流式的网关也能测通。

验收：

1. 回环地址的 OpenAI 兼容对话服务商直接走 HTTP `/chat/completions`，不经 litellm、不走代理，复用共享客户端；远程服务商保持现状。
2. 测速的流式请求首包超时（`min(provider.timeout_seconds, 20)` 秒）且没有任何数据时，取消并按非流式重试一次；非流式成功则正常返回，失败按超时或对应原因报错。
3. 普通对话对本地网关同样直连；沿用 D127 的「流式无正文回退非流式」。
4. 直连路径支持工具调用、视觉消息与 `reasoning_effort` 等现有参数；用量与失败原因映射与 litellm 路径一致。
5. 延迟只计实际请求；预算、权限、记账不变。

## 改动一览

- `aureus/organs/llm_adapter.py`：本地对话直连、共享客户端、首包超时与回退。
- 测试：`tests/organs/test_llm_adapter.py`。

## 行为细则和边界情况

1. 本地判定沿用 `local_expression_endpoint` 的回环规则（无用户信息/查询/片段、不解析 DNS、不走代理）。
2. 首包超时只用于测速；普通对话的总超时仍按服务商配置。
3. 流式首包到达后正常继续；首包超时但已有部分数据时按已收到的数据处理，不再回退。
4. 直连请求体与 litellm 路径一致：`model`、`messages`、`max_tokens`、`tools`、`stream`、`reasoning_effort`、图片内容。
5. 用量字段解析兼容 OpenAI 格式（`usage.prompt_tokens/completion_tokens`，流式 `stream_options.include_usage` 返回的 usage）。
6. 不做：改变服务商配置、增加代理设置、改变超时默认值。
