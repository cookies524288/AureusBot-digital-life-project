## 目标与边界

1. 同一可信会话的有效入站样本按来源去重。表达和黑话分别使用上游的 `situation/style/id` 与 `content/id` 协议；每条真实样本仍作为独立的 user 消息。编号只对应实际展示的前缀，表达可以归纳观测到的句式，但必须连接有效来源；黑话须在其来源片段中命中（忽略大小写和空白差异）。不信任正文、模型输出或昵称声称的会话和真实编号。普通群聊、普通及临时私聊各自分批；可信本机用户也按通道区分。未知会话不新提取，普通表达观察不变。
2. 各抽取路独立提交，即使另一条路被拒、报错或返回无效输出也不撤销成功结果。成功且可解析的数组（包括空数组）按来源和抽取路消费一次；相同样本或相同批重投不会重复提交成功的一路。不会对失败主动重试或回放。
3. 黑话候选不写假释义。只从本会话候选证据累计，按上游 4 / 8 / 25 / 100 条不同来源门槛推断或重推：先根据证据，明确有释义才运行仅词条判断，再比较两结果；仅明确不同才以第一阶段释义晋升。信息不足则等下一门槛；失败不改变已确认判定，不让新的待定候选进入召回。若已确认的黑话在之后的完整比较中被判相似，则停止旧释义召回，历史来源与先前判定仍保留。
4. 经维护者确认，会话是学习证据及管理筛选标签，不是运行时召回门槛；获准术语和表达可跨账号和会话使用，包括私聊学到、群聊召回。习得语言块只注入词义或表达与场景，不附原文；保留安全说明，并告知器官不要泄露来源或私人细节。软提示并非对生成结果的硬保证。原有导入包的明确授权（不是来源标签）、审核、停用、移除与其他旧条目的既有行为保留。实际器官调用全部经现有网关、额度、权限和最低费用偏好；保留学习与召回开关。不新增任务槽、真实服务或网络依赖。
5. 提示词目录与网页场景复用运行构建器，使用纯模拟占位词和来源；保留已有语言提取模板覆盖键，兼作两路的共同安全指令，不沿用其旧混合输出协议。按来源指令和协议边界登记改编来源。
