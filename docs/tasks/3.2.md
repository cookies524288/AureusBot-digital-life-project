# 路线图 3.2 · MaiBot 导入基础

状态：完成

设计依据见 [D89](../10-decisions.md)、[目标部署](../13-references-and-migration.md) 和 [Phase 3](../08-roadmap.md)。

## 交付与接口

在现有 `aureus migrate-maibot` 下提供导出、预演和写入独立目标的入口。每次显式指定逻辑实例名、源库角色和单个 SQLite 源。角色区分主库、记忆库、附属人际库，同一角色的副本换路径时保持相同的来源键。CLI 帮助写清参数和运行顺序。复用 3.1 的只读连接和普通表识别。测试只用模拟数据。

1. 导出采用同一个只读事务做结构读取、计数和逐行读取，包含其开始时已提交的 WAL。每个源库独立成快照，清单标明此边界；不同库需要同一停写时点时沿用最终切换窗口。按行流式写入版本化 UTF-8 JSON Lines，完成后才发布到新的输出位置，已有用户文件不能覆盖。清单与数据一起验证，可以发现截断、缺行、重复来源键和版本不支持。
2. 以实际库的主键（保留类型及复合键顺序）标识原始行。没有可确认稳定键的表列入未映射；不以正文、昵称或行序号代替主键。私有中间文件保留所选业务数据原值、引用、删除及禁用标记。命令的终端和错误只报告类别、数量和可定位的结构化诊断，正文、账号和私有路径不出现在报告。
3. 按来源表建立明确清单。主库包括会话、人物、消息、表达、黑话、高频词、平台账号和图片元信息；记忆库包括段落、事实及证据、关联、episode、人物画像和图片记忆的基础记录；附属人际库按实际表结构处理。每张普通表都分配到导出、派生可重建、运行统计、待映射等类别之一，记录原因及条数。禁止通配符遍历导出未识别的表。外部文件、向量与插件运行状态的分类和后续处理记入对账结果。
4. 所有经历迁入统一记忆库。保留源中已有的说话人标识、平台、时间及精度、内容和引用，原本缺失的字段保留为空；来源键可区分同名人物的不同记录。导入、学习、查询均无需会话归属。后续步骤基于这些记录通过各自子系统接口发布。
5. 预演校验格式版本、清单、来源键与计数，不创建运行目标。导入写到显式目标的独立迁移暂存库，禁止覆盖源库或已有非迁移库。以实例、角色、表和原始主键保证幂等。校验失败或中断不会留下被报告为完成的一半数据。旧快照和新快照同键内容不同必须有明确处理，不得默默保留过期内容或复活删除的资料。输出逐表的源条数、接收数、已存在数、隔离或跳过数及原因。业务子系统完成发布的数量在 3.3–3.5 单独记录。

## 命令与文件

```text
aureus migrate-maibot export  --instance INSTANCE --role main SOURCE.sqlite PACKAGE.zip
aureus migrate-maibot preview --instance INSTANCE --role main PACKAGE.zip
aureus migrate-maibot import  --instance INSTANCE --role main PACKAGE.zip STAGING.sqlite
aureus migrate-maibot restore --instance INSTANCE --role main STAGING.sqlite RESTORED.sqlite
```

每个源单独执行，角色为 `main`、`memory` 或 `people`。同一实例的三种角色可以写入同一个独立暂存库。源库只读事务先固定快照，再用 SQLite backup API 生成与 WAL 脱离的备份。包内含完整 `source.sqlite3`、私有 `manifest.json` 和 `records.jsonl`。预演及导入同时验证快照摘要、逐行内容和计数。SQLite BLOB 在 JSON 中采用带类型的 Base64 对象；字段继续使用源列名，原始 JSON 字符串继续作为字符串。公开报告中的表编号可在私有清单定位。

暂存库为每个实例和角色保留一份完整快照。同一份包可重跑，有变化的快照会报告冲突。要导入更新后的完整快照，使用新的暂存库对三类源重新对账。恢复命令在校验摘要后将指定来源的备份写到新 SQLite 文件。导出、暂存和恢复文件都含私有数据，输出放在私有目录。预演会在包所在目录暂存解出的备份，导入会在目标所在目录暂存备份，处理结束会清理临时文件。新文件通过同卷硬链接发布，目录需位于支持硬链接的文件系统。

后续步骤可通过 `source_rows.source_id = sources.id` 读取暂存记录。`sources` 提供 `instance`、`role` 和私有清单，`source_rows` 提供源表名 `table_name`、原始主键 JSON 数组 `source_key` 和记录 JSON `record`。在 `record.values` 读取原列及其原值。显式媒体路径和已识别的外部引用按记录列在 `external_refs`，MaiBot 原始 MsgPack 消息通过 `deferred_media_fields` 定位，后续解析并核对其中的媒体附件。

## 自检

维护者要求小豆的群聊和私聊全部迁移。生成独立目标时，完整保留源库一致性快照（含尚未识别的表和缺少稳定键的行），同时导出可识别的业务记录。来源快照属于交付，须能由清单校验、从目标重新打开并核对；源路径之外的引用和媒体附件逐项列入后续迁移清单。逐表核对原始消息、记忆、说话人、时间及证据。无会话编号的记录与其他记录同样可发布。

- [x] 合成库覆盖群聊、私聊、缺失会话、未知业务表和无主键行。关闭源后仅从独立目标取回并核对原值、条数及引用；可从同一份数据查回同一人的群聊和私聊经历。见 `test_cli_imports_all_roles_and_recovers_independent_snapshots`。
- [x] 正常 CLI 对合成主库、记忆库和附属库各跑一次。验证 JSON 原值及证据、复合键、同号不同来源、未知表、无主键和缺字段的处理。帮助及公开报告无私人内容。见 `test_cli_imports_all_roles_and_recovers_independent_snapshots`、`test_export_and_preview_keep_typed_keys_and_private_values`、`test_migration_help_lists_order_and_parameters`。
- [x] WAL 与并发写入使用同一源快照，源文件保持原样。损坏、中断、已有输出、未知格式、重复键或截断的文件均有测试。见 `test_backup_freezes_committed_wal_and_preserves_source`、`test_export_failure_does_not_overwrite_or_publish`、`test_preview_and_import_reject_damaged_packages`、`test_snapshot_restore_streams_multiple_blocks_and_detects_damage`。
- [x] 预演无目标写入；重复、失败后重跑和版本变化用同一目标验证，逐表对账守恒。见 `test_export_and_preview_keep_typed_keys_and_private_values`、`test_cli_imports_all_roles_and_recovers_independent_snapshots`、`test_import_rolls_back_flushed_rows_and_rejects_snapshot_changes`。
- [x] 同一人的群聊、私聊、无会话编号的历史均保留说话人、时间和证据，缺失字段未被补造；模拟数据不依赖本地实例。见 `test_cli_imports_all_roles_and_recovers_independent_snapshots`。
- [x] 专项、格式、类型与依赖检查通过，提交命令和测试结果，重写交接。使用独立 `--basetemp` 运行 `uv run --offline python -m pytest -q tests/cli/test_maibot_command.py tests/cli/test_maibot_migration.py`，28 项通过。两次 `uv run --offline python scripts/check.py` 的 Ruff 格式与规范、Pyright 和 8 条架构规则均通过。导出与预演提交 `5849b5f` 对应 2357 项通过、1 项跳过。暂存导入与恢复提交 `32c4e9f` 对应 2367 项通过、1 项跳过。交接见 [handoff.md](../handoff.md)。

## 范围

本步交付私有中间文件与迁移暂存层。人际、学习与长期记忆接入在后续任务实现。Aureus 沿用已有的人格配置。本次只迁移群聊、私聊、人物关系、记忆、学到的表达与黑话等业务数据；MaiBot 的人格、昵称、别名、身份、行为和回复风格等配置排除在迁移流程之外。真实来源和目标由 Astra 在本机验证，仓库仅收录模拟数据及脱敏结构对照。
