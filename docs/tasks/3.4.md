# 路线图 3.4 · 习得表达、黑话与持续学习

状态：待实现

先读 [D89](../10-decisions.md)、[3.2](3.2.md)、[部署调用路径](../13-references-and-migration.md)及第三方清单。以本机部署 MaiBot 1.3.15 的 Python 源码为行为基线，公开可移植部分核清许可后登记到 THIRD_PARTY.md。实现与数据桥接可分步提交。

1. 复用 `jargon_context_matcher` 的文本规范化、机械匹配、近期消息位置及频率打分、限条和去重规则；识别同词多义时保留各释义及证据。接入 Planner 正常入口。当前会话号不能作为统一记忆库的查询门槛。缺词、未完成推断、标成非黑话、证据不足分别按目标源码处理。
2. 对照 `MaisakaExpressionSelector.select_for_reply` 的意图输入、候选选择和回复器使用位置。导入保留情景、表达、例句、使用次数、原始审核状态及时间。结合当时的话题、Planner 意图和说话人选取有证据的表达，把结果交给 Replyer；覆盖无命中及预算限制。与源码的差异记录理由。
3. 从 3.2 暂存发布 `expressions`、`jargons`、`high_frequency_terms`，用源键幂等处理；正常重启复用。不要导入人格配置里的回复风格。按来源逐表报告接收及待处理情况。
4. 对照上游两个 learner，给真实消息接入增量学习。只使用真实输入和能定位的证据。器官如参与提取，走项目现有网关并仅产生建议，由所有者校验并保存。学习有独立开关；启动回放及重复投递不重复计数。区分新学会的说法和仅仅再次用到已有表达。
5. 用正常入口、模拟群与假器官实测。跨群或私聊、无会话编号、同词异义、英文大小写、空结果、禁用学习、重启重复输入均需覆盖。验收要证明 Planner 或 Replyer 实际收到对应材料，以及新学候选可在另一次对话命中。输出只用合成样例。
