## 目标和验收

同样的服务商和模型在 Aureus 里能正常测速与使用；确实没有正文时给出明确原因。

验收：

1. 流式响应没有正文、没有工具调用、也没有报错时，自动用同一请求非流式重试一次；拿到 `message.content` 就按成功处理。
2. 测速时只有 `reasoning_content`/`reasoning`、没有正文，算模型可用，结果注明「只返回了推理内容，没有可见正文」。
3. 普通对话不把推理内容当正文；只有推理内容时按空回复处理，失败原因写明「只返回了推理内容，没有可见正文」。
4. 非流式重试仍为空或报错时，沿用现有失败原因；重试只发生一次，不无限循环。
5. 超时仍按服务商配置，不额外缩短；重试计入同一器官调用的用量与预算。

## 改动一览

- `aureus/organs/llm_adapter.py`：流式收集同时读取 reasoning 字段；无正文时回退非流式；测速与普通对话分别处理。
- 测试：测速与普通对话的流式/非流式/推理内容场景。

## 行为细则和边界情况

1. 回退条件：流结束、无异常、正文为空、无工具调用。有工具调用时不回退（工具调用本身是有效结果）。
2. 非流式请求参数与流式一致（模型、消息、max_tokens、工具），只去掉 `stream=True`；用量以非流式响应为准。
3. 推理内容不进入回复正文、不写入回复参考；只用于判断模型可用性与失败说明。
4. 超时、限流、认证等错误不触发回退（它们不是「空正文」）。
5. 不做：修改服务商配置、改变超时默认值、为每个模型单独写适配。
