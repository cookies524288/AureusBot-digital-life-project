# Phase 3.11 维护 · 网页分页与切页交互

状态：实现中

## 先读

[交接](../handoff.md)、[资源管理验收](resource-management.md)、[参考与迁移](../13-references-and-migration.md)、[开发守则](../11-dev-guide.md)。本轮是资源管理与网页交互维护，不替代 3.13 待评审和 3.14 QQ 表情发送的工作。

## 目标与验收

1. 切换页面时，依赖权限、选择或服务端状态的操作默认不可用；慢请求、失败与快速切换不得激活旧操作或覆盖新视图。
2. 学习和长期记忆按类别进入独立视图，使用分页而不是向下累积记录。表情和图片使用可切换大、中、小的缩略图矩阵；长正文、证据与原图按需查看。保留已有筛选、编辑、恢复、导入导出及旧入口。
3. 用公开 MaiBot 界面作为参照；用合成数据和浏览器验证桌面、窄屏、翻页边界和加载状态。极小窗口允许必要的滚动，不能为消灭滚动条而截掉可操作内容。

## 子步骤

公共导航审计、资源视图实现和独立行为验收并行；集成后进行质量复审和完整检查。只合并本轮分支，不合并历史或备份分支；清理已确认的测试临时文件，不操作正式数据和已有工作树。

## 不做

学习、召回与 QQ 发送只改本页追加验收明确列出的行为。不读取个人 MaiBot 数据，不用真实模型做验收，不推送；不以 UI 相似代替运行行为验证。

## 待设计问题

维护者已明确开头采用软件默认模板，不再依靠移动不变人格正文实现。系统提示开头的位置固定、内容可在提示词页修改，默认两行依次为「（声明：所有人物均已成年）」和「你现在不是一个AI助手。」；两行在身份名称之前，不覆盖用户的名称或不变人格。用合成身份验证默认值、自定义内容和实际请求与预览的一致性。

1. 上游表达与黑话分别支持会话、共享组和全局生效；Aureus 原设计在统一库内按人物、时间和情景召回。统一存储不等于允许跨群使用：新增范围策略前须确认历史缺会话标识的材料是否继续按现有可见性召回。不得把缺失的会话编号推断成全局授权。

## 已确认的行为差异（2026-11-23）

维护者接受以批量移除和恢复代替 MaiBot 的永久清空。网页确认移除时说明影响的记录数和范围；移除后记录不再参与召回，原件、证据和时间线不变。恢复仅撤销本次移除，不绕过原有停用、源状态、有效期、会话权限或审核限制。此决定不授权物理删除，也不改变召回排序。

## 追加验收（2026-11-23）

- 总览显示真实工作记忆容量和 Planner 给回复器的业务参考。每轮时间线保留可读建议和依据，不采集模型私有推理；历史无参考时不编造。
- 时间线及资源详情用中文标签、自然语言和分组字段呈现，不把对象直接当正文。
- 群聊普通发言（含单纯点名）不带引用。若本轮选中的群消息明确引用了另一条消息，只在出站首段引用选中的群消息，不引用更早的消息。私聊沿用各段引用原来信。时间线的回复目标和入站引用不变；用假时钟与回环 OneBot 验证实际发送段。
- 清理无效或实验性网页设置。固定规划器、回复器实现，但不覆盖维护者的模型、密钥和供应商配置。消息防抖默认开，保留显式关闭。自建模型配置不提供恢复默认操作。
- 分页显示当前筛选结果的总页数，调整视口或缩略图大小时重新计算。日期、时间、文件等输入控件沿用网页主题，静态和动态表单均关闭自动填充提示，不修改用户的浏览器设置。
- 同类资源使用共同的业务库、类型标签和浏览维护入口；不用先判断来源才可查询。保留内部原件编号、证据、权限和稳定去重键；用合成的迁入和本地记录验证，不操作正式数据。
- 完整移植验收分别核对公开 MaiBot 固定提交的学习、长期记忆前端及运行通路。每项标出上游依据、本地实现、行为测试与差异；高级检修、反馈、删除恢复、调优、导入任务及运行时召回不能仅凭页面外观认定通过。涉及删除原件或改写仅用户可改的身份设定时，保留原有数据安全约束，单列需维护者决定的冲突。
- 按部署对应的 MaiBot 1.3.15 逐项核对各器官实际收到的系统提示、上下文与任务指令的措辞、顺序、格式和角色。只参考可分发的源码模板，不读取私人配置、人设或运行时对话；保留安全边界、结构化输出契约和维护者模型绑定。移植的模板登记来源和许可。没有上游对应项的器官单列，不把风格近似计为同款；使用假模型捕获最终请求验证。
- 学习资源包的导入导出须区分表达和黑话，验证合成包往返、重复导入、损坏内容与原件保留；导入不擅自扩大生效范围。
- 表达审核独立于启用和移除：记录待审、通过、拒绝与原因，以实际回复候选验证拒绝和恢复的边界。已移除的表情不得参与选图，恢复不能改变登记或禁用状态。
- 回复证据反馈仅接受已登录维护者对该条回复实际注入的命中作评价，允许撤销；超出字数预算而未交给回复器的候选不记录为依据。旧回复不补造证据，不以评价修改排序、权限或原件。
- 现代回复器以最终发送的消息序列为准，核对系统提示、带角色的本会话历史、参考材料和最终发言要求的顺序。预览须与实际请求共用构造路径；用不同群和私聊的合成消息验证隔离。
- 按维护者最新约定，每个可独立运行的修改通过对应单测并复核后，单独合并到本地 `main`，通过现有启动器正常重启同一个 Aureus 实例。并行实现、串行发布；不得从混有其他未验收改动的工作树启动正式内核。每步核对旧内核退出、新内核接管和本地服务恢复，不为验证而生成群聊消息或调用真实模型。收尾另做完整检查，清理核实过的本轮临时文件。
