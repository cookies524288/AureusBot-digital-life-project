## 目标和验收

记忆召回的三处各用各的条数，与 MaiBot 现用值一致：自然召回 3、普通/最终 6、查询工具默认 8。

验收：

1. 默认配置：`memory.max_results=6`、`memory.heuristic_max_results=3`、`memory.query_default_limit=8`、`people.history_in_reply_limit=5`。
2. 每轮自然召回最多取 3 条；查询工具不传 `limit` 时取 8 条；传 `limit` 时按所传值（1–20）。
3. 回复上下文里的人物历史仍取 5 条，不随 `memory.max_results` 改变。
4. 超出范围的值在配置校验时报错；旧配置里显式写的 `max_results` 继续生效。
5. 工具参数 schema 里出现可选 `limit`，描述写清默认值和范围。

## 改动一览

- `aureus/common/config.py`：`MemoryConfig` 增加两个字段、修改一个默认值；`PeopleConfig` 增加 `history_in_reply_limit`。
- `aureus/heartbeat/conversation.py`：`_retrieve` 接受显式 `limit`；启发式召回传 `heuristic_max_results`；人物历史改用 `history_in_reply_limit`。
- `aureus/heartbeat/planner_tools.py`：`_QueryArguments` 增加 `limit`，处理函数把 limit 传给检索回调。
- 测试：召回流程、规划器工具、配置校验。

## 行为细则和边界情况

1. `_retrieve` 的 `limit` 参数由调用方显式给出，不再在函数内部读 `memory.max_results`；内部「有嵌入时先多取 3 倍再重排」的比例保持不变。
2. 查询工具的 `limit` 是可选整数，范围 1–20，默认 `None` 表示用 `query_default_limit`；模型传了越界值按参数校验拒绝整条调用（沿用现有工具校验语义）。
3. 关系图召回沿用同一个最终条数上限，不另加配置。
4. 不改已保存的用户配置文件，不改示例之外的地方；示例配置如需补充，写在 `aureus.example.toml` 的对应节。
5. 不做：改变召回算法、改变重排、改变摘要预算。

## 测试

- `test_memory_config_defaults_match_mai_mai_bot`：四个默认值逐项断言。
- `test_memory_limit_bounds_are_validated`：0、21 等越界值在配置校验时报错。
- `test_heuristic_recall_uses_three_hits`：假检索记录收到的 limit 为 3。
- `test_query_tool_defaults_to_eight_hits`：不传 limit 时检索收到 8。
- `test_query_tool_respects_explicit_limit`：传 2 时检索收到 2；传 0 或 21 时整条调用被拒。
- `test_people_history_keeps_five_hits`：`memory.max_results` 改为其它值时，人物历史仍为 5。
- `test_saved_max_results_still_wins`：旧配置显式写 `max_results=9` 时仍用 9。
