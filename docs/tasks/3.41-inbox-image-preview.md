# 3.41 平台会话图片预览正常加载

状态：完成
设计：维护者 2026-11-26 指令；可参考 MaiBot 公开源码（固定提交 `062d45c`，GitHub 取 raw 时走本机代理 `127.0.0.1:7897`）

## 问题

平台会话里的图片消息只显示「图片 1 / 查看描述」的占位块，实际图片没有加载出来。

## 目标

图片消息显示缩略图，点击可看大图；保留「查看描述」按钮；加载中显示占位，失败显示重试。

## 实现

1. 排查 `renderInboxImage` 与 `/api/inbox/messages/{id}/images/{position}`：请求是否发出、鉴权/同源/路由是否正确、返回是否为图片字节。
2. 缩略图用受控尺寸与懒加载；点击打开大图（沿用现有弹窗或图片查看器）。
3. 保留「查看描述」按钮与描述弹窗。
4. 加载失败显示占位与重试，不破坏消息列表布局。
5. 不改后端图片读取语义与权限；如确需后端补字段，写进「待设计问题」。

## 实现记录（2026-11-26）

- **根因（前端）**：`loadInboxImage` 把每张消息图片放进头像共用的 3 个并发槽，并一直占着槽位，直到 `<img>` 触发 `load`/`error`；同时图片带 `loading="lazy"`。长会话按旧到新渲染，最早的三张图在视口上方、浏览器不会懒加载它们，`load`/`error` 永远不触发，三个槽位被占死；后面所有图片（包括正在看的最新图片）一直留在 JS 队列里，拿不到 `src`，只显示 alt 文字「图片 N」和「查看描述」。
- **复现**：100 条合成图片消息的隔离实例里，旧代码只有前 3 张有 `src`，`naturalWidth` 全为 0；可见的第 96–100 张没有 `src`；滚到顶部后也只慢慢加载了 12 张。旧截图 `E:/Temp/ui-shots/3.41-old100-bottom.png`。
- **修复**：消息图片不再进入 3 槽队列，直接设 `src`，由浏览器按 `loading="lazy"` 决定何时取图和同源连接调度；头像的 3 槽去重保持 D121 不变。图片在加载期间用 `opacity:0` + 最小尺寸留在布局里（不能 `display:none`，否则懒加载同样不触发），占位和失败提示与图片叠在同一格，失败提示能把占位块撑到放得下「重试」。
- **交互**：加载中显示「图片加载中…」；失败显示「原图暂不可读取。」和「重试」，重试在 URL 后加 `&retry=N` 避开缓存；加载成功后图片可点击或用 Enter/空格打开大图弹窗（新增大图 `<dialog>`，沿用项目现有对话框样式）；「查看描述」仍是原来的行内切换，不改变已有描述读取和权限语义。
- **参考**：MaiBot `062d45c` 的 `dashboard/src/routes/chat/MessageRenderer.tsx` 与 `dashboard/src/components/image-gallery.tsx`：缩略图 `loading="lazy"`、受控高度、点击打开大图、失败显示文字。只借鉴做法，未复制代码；没有缩放、下载、上一张/下一张等图库功能。
- **未改后端**：图片接口、鉴权、同源和权限判断均未修改；隔离实例里用假 OneBot 适配器提供合成 PNG，走的是真实的 `read_inbox_attachment` 下载路径。

## 待设计问题

1. **「描述弹窗」的形式**：任务目标写的是「描述弹窗」，现有实现和测试是行内切换（显示描述时暂时隐藏图片，按钮变「查看原图」）。本次保留现状以免改变已有行为；如果要改成真正的弹窗，需要另开任务并同步改测试。
2. **重试只能解决暂时性失败**：图片接口依赖 QQ 连接实时下载原件；QQ 断开、文件过期或适配器不支持时，重试仍会失败。页面现在会明确显示失败和重试，不再无声空白；如果要离线可看，需要后端缓存原件（与 3.46 的图片缓存相关）。
3. **图片不再受 3 槽并发限制**：D121 只明确要求头像去重和并发上限；消息图片改为交给浏览器 `loading=lazy` 调度。如果复审认为图片也需要 JS 侧并发上限，需要再引入 IntersectionObserver 方案，本次按简单可靠优先。
4. **大图会再请求一次**：图片接口带 `Cache-Control: no-store`，点开大图时可能重新请求同一 URL；若第二次请求失败，弹窗只显示 alt 文字。本次不缓存图片字节；可在 3.46 里统一处理。
5. **图片标题固定为「图片 N」**：N 是同一消息内的附件位置，所以每条单图消息的缩略图 alt 和大图标题都是「图片 1」。是否改成带发送者或时间的标题，需要维护者定。
