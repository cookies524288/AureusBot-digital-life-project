## 接口

不新增公开类或函数。可以在 `planner_tools.py` 内加一个模块级私有函数：

```python
def _interest_only_errors(error: ValidationError) -> bool:
    """所有校验错误都落在 interest 字段内时返回 True。"""
```

- 参数：pydantic 的 `ValidationError`。
- 返回：`error.errors()` 里每一项的 `loc` 第一个元素都是 `"interest"` 时为 `True`；没有任何错误时按 `False` 处理。
- 用途：`dispatch_planner_tools` 捕获 `ValidationError` 后判断，是否去掉 `interest` 重新校验。

## 行为细则和边界情况

1. `dispatch_planner_tools` 里 `model_validate` 抛 `ValidationError` 时：
   - 若 `_interest_only_errors(error)` 为真，复制 `call.arguments`（dict）去掉 `"interest"` 键，再 `model_validate` 一次；成功就用这个结果继续执行 `tool.handle`，并在证据里保持原有 `requested`/`completed` 记录，不新增状态。
   - 第二次校验仍失败，或错误涉及其他字段，保持现状：`PlannerAction(name, "rejected", "工具参数无效")` 并 `break`。
   - `call.arguments` 不是 dict（例如列表）时，不尝试宽容处理，按现状拒绝。
2. `_reply()` 删去 `("interest" in data and plan.interest is None)` 这一条拒绝条件。`plan is None` 仍然拒绝；`resolve` 数量不一致仍然拒绝。兴趣的形状由参数模型和 `_parse_interest` 把关，任一不过就只是没有兴趣建议。
3. 丢弃兴趣不写时间线、不写日志、不新增字段（D115「不留额外痕迹」；也符合「没有装饰」）。
4. 语义不合格（重复、超过 `max_active`、当天次数超限、不在用户私聊）维持现有行为：回复照常、不写记录，不改动。
5. 不碰 `_Interest` 的字段约束本身：发给模型的工具声明不变，仍告诉它 30 字上限、只能在用户私聊提。
