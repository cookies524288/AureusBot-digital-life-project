# 3.15 · 学习、长期记忆和平台的对照基线

本页记录源码核对结果，不是实机通过清单。长期记忆管理、学习管理和平台会话是三个不同入口，不让一个入口的权限自动传到另一个。

- [SnowLuma 适配器 1.1.8](https://github.com/Mai-with-u/MaiBot-SnowLuma-Adapter/tree/54fcc7fcc4072983a1283d99fa0edd559125e1d7)：清单声明 GPL-v3.0-or-later；[SnowLuma 本体](https://github.com/XingYunStar/snowluma/tree/f8cb15c27bca3d2d1bd044a921e55bfc44bb5e60) 有非商业限制，不移植其实现，只对接协议。桥声明能力不等于本机连接已支持。
- [Lieflat Charts](https://github.com/larashero3-dotcom/lieflat-charts/tree/4b4e75bde11cbef44263de769f3705db54bbb277) 已本机安装。按其目录，大网络逐节点检查对应 B2：采用邻接聚焦、节点定位和独立详情的交互思路；小规模单跳关系不必强上力导向。原模板是 PolyForm Noncommercial，不直接分发其代码或素材。

## 管理和处理逻辑

|对象|上游可核对的入口与行为|Aureus 基线与实施差异|
|---|---|---|
|表达与黑话|`src/learners/expression_learner.py`：确定性过滤后再由 `expression.check` 评估，开启时出错不写入。`src/webui/routers/expression.py`、`ExpressionReviewLogPanel.tsx`、`ExpressionVectorSpaces.tsx`：质检结果、人工挽回、向量空间与补建；`jargon.py` 有组/会话范围与批量定性。|已有过滤、分批抽取、聚类快照、向量回复候选、逐条/批量审核。待做模型自评、质检记录与恢复、空间管理和进度；自评与用户审核分开，不能把当前过滤称为模型已批准。|
|表情和分页|表情登记、替换与回收属于资料生命周期，单图操作不应先跳出列表；对照固定版 dashboard 操作及维护者要求。|已有缩略图、逐/批操作、逐图描述和可逆移除。待做卡片角上的审批、状态回显；页码旁跳页且加载中可继续跳转，只有最后一次请求可更新列表。|
|长期事实和图谱|`src/webui/routers/memory.py` 的 facts、图写入、冻结/保护/回收、反馈校正；`knowledge-base/tabs/` 的事实、画像、图、反馈、纠错与回收。|已有资料目录、事件流、反馈记录、别名及只读授权图。需补事实详情及证据操作、纠错/回收和交互图；未授权不显示，不按昵称猜同一人。具体消息改归平台，不能继续作为普通记忆检索结果。|
|包与检索|`src/A_memorix/core/runtime/services/bundle_admin_service.py`：容器 v2 兼容 v1，支持 knowledge/full、来源范围、图片和匹配空间的向量。full 仍不等于完整实例备份。|已有 JSONL、标准 v1 知识包生成、兼容包预检和可逆安装/卸载。完整包生成、图片 v2、匹配空间向量、关系回收站尚有缺口；不覆盖非空库，不让导包替代权限判断。|
|平台|适配器 `profile.py` 区分通用发消息、独立文件上传和合转；SnowLuma `packages/onebot/src/actions/index.ts` 提供消息、联系人、群文件等接口。|Aureus 已有 QQ 路由、@/引用/图片/语音、回复回执、未读选择与驻留；仍需会话桌面、头像、通知事件两端、显式引用、上传及勾连输入状态。按连接器能力逐一接入，不以别的连接器字段猜测能力。|

## 复核方法

逐个操作核对上游页面触发条件、对应端点、持久化与读侧效果；在本项目用同一组合成来源覆盖授权/撤权、撤销和乱序返回。已有专项是起点，不是整页或固定版功能对齐的证明。
