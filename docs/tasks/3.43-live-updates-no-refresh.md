# 3.43 删除手动刷新图标，改用 WebSocket 实时同步

状态：待实现（前端待做）
设计：维护者 2026-11-26 指令（已确认用 WebSocket 推送、全删刷新图标）；可参考 MaiBot 公开源码（固定提交 `062d45c`，GitHub 取 raw 时走本机代理 `127.0.0.1:7897`）

## 目标

所有页面不再显示手动「刷新」图标；数据通过 WebSocket 推送自动更新，各处消息实时同步；刷新函数保留供内部事件调用。

## 实现

1. **后端**：扩展现有 `/ws` 通道，除聊天外推送数据变更事件（新平台消息、新时间线记录、轮次状态变化、学习/记忆资源变更）。事件只带类型与最小标识（不推聊天正文），按登录会话鉴权；实现方式可参考 MaiBot 的 WebSocket 做法，但要适配 Aureus 的事件源（心跳/收件箱/时间线）。断线自动重连，重连后补拉一次。
2. **前端**：订阅事件，按页面失效对应缓存并刷新当前页（非当前页只失效缓存，下次进入重新取）；保留现有页面缓存与预取，推送只做失效与增量刷新。
3. **刷新图标**：删除所有页面头部的「刷新」按钮；刷新函数保留（例如 `loadTimeline(false)`），由推送、写操作或内部定时调用。
4. 不推送私聊原文；权限与撤权语义不变；急停/停机时停止推送。

## 验收

- 各页面头部无刷新图标；新消息/新轮次在 1–2 秒内自动出现在对应页面；非当前页进入时数据是最新的；断线重连后自动补齐；Console 无未捕获异常。

## 后端部分已完成（2026-11-26）

前端未动（`index.html` 由后续任务改）。后端在现有 `/ws` 上增加了按需订阅的实时事件；不带订阅参数的旧页面行为不变。

### 改动

| 文件 | 作用 |
|---|---|
| `aureus/heartbeat/live.py`（新增） | 事件总线 `LiveEventHub`、轻量事件 `LiveEvent`、事件类型和资源名常量。订阅者出错只记日志；急停/停机时暂停，暂停期间的事件丢弃、不重放。 |
| `aureus/timeline/database.py` | 只读追加钩子 `add_append_listener`：记录提交后把刚写入的记录交给监听器，钩子出错不影响追加。 |
| `aureus/heartbeat/main_loop.py` | 心跳发布事件：新平台消息、轮次状态变化、学习/记忆资源变更；急停、维护暂停、关闭时暂停推送，恢复后补上当前轮次状态。 |
| `aureus/web/server.py` | `/ws?events=1` 才订阅事件；事件与聊天消息共用一个有界队列（事件最多占尾部 64 格，网页收得慢时先丢事件）；发送前照旧核对登录，急停/停机时已排队的事件也丢弃。 |
| `aureus/web/assemble.py` | 把心跳的事件总线传给网页服务。 |

### 推送格式（前端按此实现）

连接：`new WebSocket((https ? 'wss' : 'ws') + '://' + location.host + '/ws?events=1')`。不带 `events=1` 时收不到任何事件，兼容旧页面。断线重连后的补拉由前端负责，后端不重放。

事件帧：`{"type": "event", "topic": "<类型>", "data": {...}}`，只有类型和最小标识，不含聊天正文。

| topic | data | 触发 |
|---|---|---|
| `timeline` | `id`（时间线序号）、`event_type` | 时间线每追加一条记录（含消息、回复、判断、认知状态等）。 |
| `inbox` | `id`（收件箱序号） | 新的平台消息已保存，且当前登录用户有权限读这个会话。 |
| `round` | `active`；回复中另有 `web`（是否网页私聊）和 `conversation`（平台会话的 `platform`、`account_id`、`kind`、`recipient_id`、`temporary_group_id`） | 正在回复谁的状态变了。`active=false` 表示没有在回复；`active=true, web=true` 是网页私聊；`active=true, web=false` 时按 `conversation` 定位平台会话。 |
| `resources` | `resource`：`language`、`expression`、`emoji`、`images`、`memory` | 语言学习完成一批、表达/表情/图片索引建成一批、记忆整理完成一批。 |

### 实现取舍（供复审）

- 资源事件按批次发布，没有做后端合并；前端按页失效和短时去抖即可。若实测事件过密，可在总线加合并，不影响事件格式。
- 收件箱事件只带序号、不带会话键：平台页本来就要重新取会话列表，多带会话键没有用处。
- 时间线事件对所有记录发布（网页时间线接口本来就返回全部记录），仍然不带正文，权限语义不变。
- 资源事件目前来自心跳的后台工作（语言学习、建索引、记忆整理）；用户在网页上改学习/记忆资源的写操作由当前页面自己刷新，跨标签页同步不在本次后端范围，需要时在对应写接口里发布同一资源事件即可。
