状态：待评审

## 目标和验收

短暂的数据库锁等待不再导致网关永久锁死；真正写不进去时仍按 D40 停止调用。

验收：

1. 账本写入在独立连接、工作线程中执行，等锁上限 5 秒；遇到 `database is locked` 最多重试 2 次（间隔约 0.5 秒）。
2. 重试成功时网关继续工作，不置位 `_ledger_write_failed`；连续失败才置位并拒绝后续调用。
3. 账本写入等待期间事件循环不被阻塞：并发的其它协程能推进（用假账本/可控锁证明）。
4. 自动建索引与其它后台写入保持短事务，不在写事务中间 await 模型调用；若发现，修正。
5. 时间线仍记录真正的失败；不补记缺失用量。

## 改动一览

- `aureus/safety/ledger.py`：新增线程安全的重试写入入口（独立连接、较长 busy timeout），保留现有 `record` 供测试或同步场景。
- `aureus/safety/gateway.py`：`_record_usage`/`_finish` 改为异步等待重试结果；锁死条件不变。
- 必要时调整 `aureus/common/sqlite.py` 支持传入 busy timeout。
- 测试：网关与账本。

## 行为细则和边界情况

1. 独立连接只用于写入；账本的读取仍走原连接。写入成功后不需要刷新原连接（WAL 下新连接可见）。
2. 重试只针对 `sqlite3.OperationalError` 且消息含 `locked`/`busy`；其它错误（磁盘满、只读）立即按失败处理，不重试。
3. 取消：网关调用被取消时，写入重试也要能取消或尽快结束，不留孤儿线程。
4. 日志：重试成功记一条 warning（带次数）；最终失败仍记 error 并锁死。
5. 不做：补记、对账、自动清空锁死状态（重启仍是唯一的清除方式）。
