状态：完成

## 目标与边界

建立可测试的结构化读取通路，供后续关系图搜索、边详情及证据展示使用。不得把两个名称之间的共现、改写后的正文、昵称碰撞或词间空格当成关系。已有只有正文的库保持可读，不重解释旧记录，不要求用户重新迁移正式数据。来源标识用于确定同一条记录，不代表浏览权限。上游字段无法消歧或不能确定授权时，不生成可见边。

## 查证与接口（2026-11-23）

- 公开副本 HEAD 已核实为 `062d45cf8bd4272ac57d7ec03fcf405e5a458211`。`src/A_memorix/core/storage/metadata_schema.py:1302` 的实体保存 `hash/name`，`:1316` 的关系分别保存 `subject/predicate/object`，端点是名称而非实体哈希；`:1402`、`:1413` 分别关联段落—关系、段落—实体。`metadata_store.py:264` 的规范化仅为 `strip().lower()`；`:278` 按规范名生成实体哈希，`:430` 保留三元组原拼写；`source_paragraph` 是首次发现地，不是全部证据。`graph_admin_service.py:978` 按主体至客体查询有向边，同向可含多个谓词；`:1097` 说明结构边权不等于置信度。这里只参考数据语义，自行实现，不移植上游代码。
- 新的结构化材料单独附着完整 `MemorySource`，与文字原件同事务发布。实体保存名称，关系独立保存主体、谓词、客体和可解析的两个实体来源；段落证据另外保存引用和链接来源。只在同实例、同库角色且规范名称唯一时解析端点，重复名称、缺实体或无效字段保留未解析。不能利用获准子集消除全来源中的歧义。
- `MemoryIndex.read_graph(allowed_sources=...)` 是独立只读入口，必须显式给出获准原件集合；它不授予权限，也不把来源键当作权限。关系及两端实体均需获准且有效；证据须单独获准，关联表产生的证据还要求关联行获准。隐藏、源删除/停用、维护停用/移除、有效期先于结果及计数；无获准结构化材料时返回无覆盖，不返回隐藏项或未解析项的数量。空集合关闭此入口，不接入网页、聊天、模型或召回。
- 查询用 SQLite `mode=ro`，不创建表、不初始化记忆或写事件。旧库无结构化表时返回无覆盖；普通 UTF-8 文字包保持现有格式，不交换这份图材料，重新导入仅文字时仍为无覆盖。不会从旧正文回填。
- 只有调用方能确认关系原件本身及两端各有独立授权时，才可返回该边（获准段落可以为零）。如果关系唯一的可见依据是未获准的段落，调用方不得把关系源键加入获准集合；端点单独可见、知道关系键或知道段落关联都不授权该关系。以同一过滤结果生成搜索、计数或详情，不能暴露被排除的段落或条目存在。

## 最小反例

- 三元组 `（甲，认识，乙 丙）` 与 `（甲，认识 乙，丙）` 的空格拼接正文相同，但客体、谓词不同；必须保留独立字段。
- 同实例实体原件 `hash-a/name=Apple` 与 `hash-b/name= apple ` 的规范名称相同，而关系只有 `subject=APPLE`，没有实体哈希可选定端点。这种来源不能消歧：保留两个实体与未解析关系，不能择一；授权只含其中一个也不能据此补边。跨实例同名则用完整来源键区分。

## 子步骤

1. 从固定版本的公开定义和合成暂存行确认端点字段的真实语义，区分实体哈希、名称、谓词和段落引用。以完整来源键区分实例；不得仅以显示名称作为跨记录主键。记录查证位置。
2. 在现有记忆子系统内以最小改动保留这些独立字段及来源状态。提供非推测的只读查询，调用者必须明确给出获准读取的原件范围；先应用范围、删除及停用规则，再做聚合或计数。未解析或不可见的端点不进入结果。段落证据与语义边分开；不把边数、置信度和证据数混作一项。
3. 用新建的合成库覆盖迁移、关闭再打开、重复发布与旧版兼容。确认查询不会增删改原件、写时间线或改变召回。不得为了测试在正式库中创建表、重建索引或运行迁移工具。
