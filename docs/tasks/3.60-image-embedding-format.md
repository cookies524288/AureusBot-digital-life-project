# 3.60 图片嵌入前统一转 PNG，修复 GIF/WebP 导致的 image_embedding 连续失败

状态：完成
设计：D143（docs/10-decisions.md）

## 先读

- `aureus/organs/llm_adapter.py`：`EmbeddingOrgan._send` 的 `image_embedding` 分支、`_post_embeddings`、`_failure_reason`、`model_probe_inputs`、`_loopback_endpoint`。
- `tests/organs/test_llm_adapter.py`：`EmbeddingOrgan` 的假客户端/`httpx.MockTransport` 写法。
- D143 的核查证据：本机 chinese-clip 嵌入服务（127.0.0.1:9988）对 PNG/JPEG 返回 200，对合成 GIF/WebP 返回 500；账本 120 次 `image_embedding` 失败均为「服务商内部错误」；失控拦截暂停是症状。

## 目标和验收

1. `image_embedding` 发送前把 GIF/WebP 取第一帧并转成 PNG；其它 Pillow 能读的格式转 RGB PNG；PNG/JPEG 且模式为 RGB/RGBA/L 时原样发送，不无谓重编码。
2. 转换失败（损坏、无法识别、解压炸弹/超限）不发送，按「图片格式不支持」失败，交给器官顺延；不把坏图发给服务商。
3. 转换在 `EmbeddingOrgan` 内完成，所有图片嵌入共用；转换放到工作线程，不阻塞心跳。
4. 回环图片嵌入复用 `_post_embeddings(local=True)`，不走系统代理（D101/D128 的同一原则）。
5. 不改服务商配置、账本、预算、权限、急停和失控拦截阈值；修复后成功调用会让连续失败自然清零。
6. 不真实调用模型；测试用 Pillow 合成图片和 `httpx.MockTransport`。

## 改动一览

- `aureus/organs/llm_adapter.py`：
  - 新增私有 `_embedding_images(inputs: Sequence[bytes]) -> tuple[str, ...]`：在工作线程里把每张图片转成适合发送的字节并 base64 编码；单图转换用 `_embedding_image_bytes(value: bytes) -> bytes`。
  - `_embedding_image_bytes`：`Image.open`；GIF/WebP 或其他格式 `seek(0)` + `convert("RGB")` + 保存 PNG；PNG/JPEG 且 `mode in {"RGB","RGBA","L"}` 原样返回；`UnidentifiedImageError`/`OSError`/`ValueError`/`Image.DecompressionBombError` 抛 `_RouteFailureError("图片格式不支持")`。
  - `EmbeddingOrgan._send` 的 `image_embedding` 分支：`encoded = await asyncio.to_thread(_embedding_images, inputs)`；payload `input` 用 encoded；`local=_loopback_endpoint(route.provider.base_url) is not None` 传给 `_post_embeddings`。
- `tests/organs/test_llm_adapter.py`：新增/扩展图片嵌入格式测试。

## 接口

- 私有 `_embedding_image_bytes(value: bytes) -> bytes`；`_embedding_images(inputs: Sequence[bytes]) -> tuple[str, ...]`；无公开 API。
- 失败原因字符串「图片格式不支持」由 `_failure_reason` 原样带给 `OrganCallError`。

## 行为细则和边界情况

1. GIF/WebP（含动图）取第一帧；PNG/JPEG 的 RGB/RGBA/L 原样；P、CMYK、LA 等转 RGB PNG。
2. 多张图片按输入顺序转换，保持顺序。
3. 转换失败不发起 HTTP 请求；器官继续尝试下一条路线；全部失败时 `OrganCallError` 的 failures 里有「图片格式不支持」。
4. 转换在工作线程；`asyncio.timeout(provider.timeout_seconds)` 仍包住发送，转换耗时计入本次调用。
5. 回环地址的图片嵌入不走系统代理；非回环保持现有行为。
6. 账本 usage 仍按原始输入字节估算（图片嵌入本地免费，cost 0）；不改记账语义。
7. 不缩放图片；本机服务能处理 4096×4096 JPEG；超限由 Pillow/服务商报错，按失败处理。
8. 不真实调用模型；测试不访问 127.0.0.1:9988。
