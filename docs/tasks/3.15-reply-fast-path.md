## 目标和验收

把发言关键路径缩到 planner → replyer；其他器官并行或后置，不额外增加回复延迟。

验收：

1. 网关最多同时放行 `max_concurrent_organ_calls`（默认 5）个器官调用；第 6 个等待；配置范围 1–8，越界报错。
2. 预算到点后不再发起新调用；允许的超出范围是「至多 N-1 次在途调用」，测试用假账本证明；账本写入失败仍立即锁死网关；失控拦截计数在并发下不丢失。
3. 表情选择与 replyer 同时启动；正文先就绪、表情在宽限时间内完成则附带，超过宽限则只发文字并取消表情任务。
4. 回复分段和分段建议保持现状（默认开启），本任务不改其开关与调用时机。
5. 现有「网关串行」断言按 D117 改写，并注明变化原因。

## 接口

- `SafetyConfig.max_concurrent_organ_calls: int = Field(default=5, ge=1, le=8)`。
- `HeartbeatConfig.emoji_selection_grace_seconds: float = Field(default=0.8, ge=0, le=5)`：正文就绪后最多再等表情多久。
- 网关内部用 `asyncio.Semaphore` 取代 `asyncio.Lock`；`_call_serialized` 改名或保留均可，行为按 D117。

## 行为细则和边界情况

1. 并发许可在「检查 → 调用 → 记账」整段持有（与原来的锁范围一致），只是许可数从 1 变成 N；释放必须在记账之后，包括异常和取消路径。
2. 预算检查仍逐次读账本；D48 第 3 条（用量不可信时保守估算）不变。
3. 表情任务用 `asyncio.create_task` 启动，持有在 `_finish_reply` 的局部；正文就绪后 `asyncio.wait` 至多等 `emoji_selection_grace_seconds`，超时取消任务并返回文字。取消要等任务真正结束再返回，避免残留任务写状态。
4. 表情任务异常按现有 `select` 的吞错语义处理，只影响表情，不影响正文。
5. 分段与分段建议不动：仍按 `split_reply_enabled` 和现有 fast_model 调用执行。
6. 媒体识别、记忆召回不动；心跳中的学习、质检、工作记忆、日记不改为等待。
7. 不做：judge（另一个任务文档）、改变 planner 工具轮数、改变发送规则与打字延迟。
