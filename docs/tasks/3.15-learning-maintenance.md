# 3.15 · 黑话与表情资料维护

状态：实现中。属于[学习工作台](3.15-resource-console.md)，与记忆包互通及表达质检是三条不同的写入路径。先读[3.14 源码基线](3.14.md)、[已实现的表情操作](supplemental.md#emoji-maintenance-preview)和固定版 `062d45c` 的 `routers/jargon.py`、`resource/jargon/{JargonList,JargonDialogs}.tsx`、`src/emoji_system/emoji_manager.py`、`routers/emoji/routes.py`、`resource/emoji/EmojiCacheMaintenancePanel.tsx`。

1. **黑话定性不等于已有释义。** 在黑话页查看本会话/共享范围内的候选、已确认、非黑话；保留搜索、跳页和未完成请求时继续翻页。对照固定版 `batch/set-jargon`，单条或批量确认/否定操作使用服务端核定的条目键，在同一事务内复验、记录实际结果。不要把 `is_enabled`、`is_jargon`、授权范围、释义为空当作同一状态。维护者可进入条目核对证据、增改释义，再返回原列表。按现有 `match_jargons` 和真正的 replyer 请求验收：无义项、已否定、被移除、越权都不可用；添加有效义项/恢复资格后才可按本范围匹配。同词不同来源或不同义项不能互相覆盖。既有语言包往返要保留定性结果，不由包中的群名自动授权。
2. **表情登记容量与替换。** 已有上传/登记/审批、完整性预览、10 分钟维护和实际发送回执，勿另写一套。固定版上限默认为 64，满额时 `replace_an_emoji_by_llm` 只提议取消旧登记，不删媒体。Aureus 采用可独立配置且说清费用的替换步骤，未经显式开启不新增模型调用；缺模型、拒绝或过期选择不得改动候选。注册时以实际活跃登记数为准，替换前复核新、旧内容键、登记/审批和版本，在一个事务调整两个登记状态；取消、重复或并发不误减。正式库历史登记可能已超新限额，不在启动或读页面时追削旧登记。网页提供实际计数、上限、预览/确认和每张卡的审批，已被明确拒绝的图片不能因替换而复活。
3. **表情缓存与素材出入。** 区分缓存、用户素材与目录状态。只对本项目实际生成的缩略图缓存提供按页查看、预览清理、预热和实际结果；如没有持久缓存，明确显示且不把清除原图伪装成清缓存。固定版表情路由提供单张/批量上传，并非 A_Memorix 的 `images.json` 记忆包。可携带素材集应明示本项目格式、来源许可和已选成员范围，导入预检大小、格式和内容摘要，再确认登记；不接收任意路径或执行打包内容，重复导入不改审批或越过容量。避免将固定版不存在的接口或插件钩子写成已有兼容协议。

自检：用两个同名会话及两义项、无释义候选、被拒表情、已超额的旧库、并发登记、重复素材和损坏文件验证写入/实际读侧。在窄屏逐项验证页码、选择、筛选、取消和单卡结果。只用构造的图片、假器官和假时钟，不发 QQ 消息，不访问或回收正式目录。各小步单独合入，不涉及关系图新 UI。

黑话范围沿用 D100：可信学习来源用于管理筛选，不替代召回授权；没有独立授权限制的词条属于共享范围，导入包只按明确映射的会话参与召回。固定版的 `is_jargon` 单独维护，Aureus 用三态区分待定候选与明确否定。MaiBot v1 的布尔字段继续用于确认或否定；待定和同名同义条目的区分分别使用本项目可选扩展字段 `aureus_jargon_status` 和 `aureus_jargon_source`。不导出已移除黑话；包内目标不自动授权。
