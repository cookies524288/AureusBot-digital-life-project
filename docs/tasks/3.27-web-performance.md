# 3.27 网页端性能收尾：切页秒开

状态：待评审
设计：D129（docs/10-decisions.md）；排在所有功能任务之后执行

## 先读

- `aureus/web/static/index.html`：`showPage`、各页 `PAGES.*.load`、`api()`、`startPageEntrance`、导航点击。
- `aureus/web/static/resource-management.js`、`memory-*.js`、学习工作台内联加载逻辑。
- `aureus/web/server.py`、`timeline_api.py`、`inbox_api.py`、`resource_*`：慢接口与索引。
- 隔离实例：数据根 `E:/Temp/aureus-ui-review`，端口 18770；正式实例 28976 不动。

## 目标和验收

已访问过的页面切换时立即出现内容，不再每次都等接口；整体交互接近 MaiBot 的流畅度。

验收：

1. 记录优化前后的数据：每页从点击到可交互的耗时、主要接口耗时、重复请求次数（写入任务文档）。
2. 再次进入同一页面时先显示缓存内容（≤100ms 出现），后台刷新完成后静默更新；刷新失败保留旧内容并提示。
3. 同一页面的独立请求并行发出；同一请求在途不重复。
4. 导航悬停或空闲时预取目标页数据（可关闭）。
5. 学习工作台的内联资源只在进入学习页时加载；首次加载有进度提示，不阻塞其它页面。
6. 入场动画只在首次进入播放，或降低开销；切页无长任务（主线程 >50ms 的任务）。
7. 服务端慢接口按测量结果补索引或有界查询；不改变数据与权限语义。
8. 缓存按登录会话隔离，退出登录清空；不把私聊内容留在公共缓存。

## 改动一览

- `index.html`：页面缓存、请求去重、预取、按需加载、动画调整。
- 各页脚本：接入缓存读取与后台刷新。
- 服务端：按测量结果补索引/有界查询（必要时）。
- 测试：按维护者要求不跑 pytest；用隔离实例手测与浏览器 Performance 面板。

## 行为细则和边界情况

1. 缓存 TTL 按页面类型设置（列表类 10–30 秒，配置类可更长）；写操作后使对应缓存失效。
2. 缓存只存当前会话可见数据；切换账号/退出登录清空。
3. 预取失败静默；不影响当前页。
4. 不为了速度跳过权限检查或使用过期授权；撤权后下次刷新必须反映。
5. 不做：改变业务逻辑、减少数据字段、关闭安全检查。

## 测试

隔离实例手测：冷启动首访、二次切换、悬停预取、退出登录后缓存清空、慢接口下的表现；用 Performance 面板记录长任务与主线程占用；截图/数据写入任务文档。

## 优化前基线（2026-11-26）

### 测量环境

- 隔离实例：端口 18770，假器官。原数据根 `E:/Temp/aureus-ui-review` 的网页密码未知（`admin` 校验失败），为避免改动原隔离数据，复制到 `E:/Temp/aureus-ui-review-327`，只在副本里删除 `web_password.argon2`（恢复默认密码）并改成测试密码，端口仍为 18770。原 18770 数据根、正式实例 28976 均未修改。这是与任务文档「数据根 E:/Temp/aureus-ui-review」的偏差。
- 浏览器：应用内 Browser 面板，localhost:18770，无缓存冷启动后按顺序访问。计时用 `performance.now()`，从调用 `showPage`（与点击导航按钮走同一入口）到该页 `load` Promise 完成，再等两帧；接口耗时取 `PerformanceResourceTiming.duration`；长任务用 `PerformanceObserver({entryTypes:['longtask']})`。每页重复 3 次取中位数（首访只有一次，按单次记录）。
- 数据量：隔离库时间线 80 条、无 QQ 收件箱消息、记忆少量；因此本机接口都在 30ms 内，主要差距在「每次都重新请求 + 每次都播入场动画」。真实实例数据更大，差距会放大。

### 重复请求

- 单次切页内没有同一请求重复发出（0 次）。
- 跨页面往返重复：模型与器官共用 `/api/models`，每次进入各自重新请求；除私聊（历史缓存在 `state.loaded.chat`）和学习（工作台只挂载一次）外，每个页面每次进入都重新请求自己的主接口。冷启动后按顺序首访一轮 + 二次进入一轮，共产生 11 次本可避免的重复请求。
- 首页静态文件：`index.html` 传输 343 KB，DOMContentLoaded 44ms。

### 长任务与动画

- 本轮基线用 `PerformanceObserver` 记录，切页过程中没有 >50ms 的长任务；入场动画的文本节点扫描在当前小数据量下未形成长任务，但每次切页都会重新扫描并播放一遍。
- 学习工作台首次加载约 199ms，加载后页面切换不再下载工作台资源；它在窗口重新获得焦点时会刷新 4 个表达接口（React Query 默认行为），闲置时不轮询。

### 服务端

- 本机隔离库上接口都很快。另用 30 万条时间线的合成库测时间线查询：最近窗口、最近回复参考、回复上下文、按类型筛选都在 1ms 内，现有 `idx_timeline_timestamp` / `idx_timeline_event_type` 足够，不需要新增索引。
- 收件箱会话列表是真正的慢查询：50 万条收件箱消息、200 个会话时，`InboxStore.list_conversations` 约 1.9–3.1 秒（全量扫描 `inbox_messages` 统计未读和最后一条）。加覆盖索引 `(conversation_id, id, direction, visibility)` 后同一查询约 95ms（约 20 倍），语义不变。留到第 5 小步实施。

### 缓存过期后的后台刷新

- 时间线：离开 16 秒后再进入，缓存内容在 42.6ms 内同步出现（85 个列表节点），刷新在 98ms 完成并只发一次 `/api/timeline?hours=24&limit=100`。
- 模拟刷新失败（让 `/api/timeline` 返回 500）：85 个节点仍在，页面弹出「模拟刷新失败」提示，旧内容没有被清空。
- 平台页：缓存内容 0.7ms 出现，刷新 10.8ms 完成；隔离库没有 QQ 会话，列表本身为空。

### 并行、去重与预取

- 总览：`/api/overview` 与 `/api/timeline?hours=24&limit=3` 的请求开始时间相差 0.1ms，动态卡片先渲染，最近动态晚到不阻塞主卡片。
- 去重：并发调用两次 `api('/api/overview')`，网络记录只有 1 条，两个调用拿到同一个响应对象。
- 悬停预取：在时间线导航上触发 `pointerenter` 后进入，页面 0 次接口请求，首屏渲染 50.4ms；再次进入 0.3ms。
- 空闲预取：登录后按顺序补时间线、平台、人设、模型、密钥、Prompt、设置、观察；已在请求记录里看到这些页面在空闲时被取回。
- 预取开关：`localStorage['aureus-page-prefetch'] = 'off'` 或控制台 `__aureusSetPagePrefetch(false)` 可关闭；关掉后没有预取请求。

### 学习工作台与动画

- 进入学习页前没有 `/learning-workbench/workbench.js` 请求、没有 shadow root；进入后才加载，页面上有「正在加载学习工作台…」进度提示。
- 入场动画只在本次登录第一次进入某页时播放；`state.entranceSeen` 记录已播放页面，二次进入不再扫描文字。二次进入的 13 个页面均未记录到 >50ms 长任务。
- 第一次加载学习工作台时记录到 3 个长任务（81ms、66ms、54ms），是 1.69 MB 工作台 bundle 的解析执行成本；它只在进入学习页时发生，有进度提示，不影响其它页面，之后的切页不再出现。

### 会话隔离与写后失效

- 退出（`/api/logout` 后回到登录页）再登录，时间线、平台、人设、模型、密钥、Prompt、设置、观察都重新请求，说明上一会话的缓存没有带过来。
- Prompt 管理页二次进入 0 次请求（3ms）；点「保存」提交相同内容后，再进入发出一次 `/api/prompts`（18.1ms），说明写操作已让缓存失效。

### 服务端

- 用真实 `InboxStore` 建 30 万条收件箱消息、200 个会话：不加覆盖索引时 `list_conversations` 约 2751ms；加索引后约 110ms（约 25 倍）。查询计划显示 `SCAN m USING COVERING INDEX inbox_messages_conversation_visibility`。索引加在 `aureus/heartbeat/inbox_store.py` 的建表脚本里，因为 `inbox_messages` 表属于收件箱子系统；这是对任务文档「必要时改 `aureus/web/*.py`」的一处偏差，理由和测量都记在这里。
- 时间线 30 万条合成库的最近窗口、回复参考、回复上下文、按类型筛选都在 1ms 内，现有索引足够，没有改时间线。
