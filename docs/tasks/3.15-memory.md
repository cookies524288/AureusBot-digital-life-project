# 3.15 · 从平台历史提取增量事实

状态：待实现。对应总任务 4 的消息边界和 5；与 9 的滚动摘要完全独立。先读 `aureus/memory/{index,resources,history,consolidation}.py`、`aureus/heartbeat/{inbox_store,memory_consolidation}.py`、`aureus/attention/inbox.py`、`Summary prompt.txt` 及[固定版对照](3.15-parity.md)。

## 基线与发布顺序

1. **先保证平台可查。** 当前目录同时纳入 live 的 `message` 和迁入的 `mai_messages`/`messages`，`MemoryIndex.search` 的提取词命中还会返回证据原文。接入平台历史读取路径并覆盖存量、新收和已发消息，保留账号/会话/发送者/平台消息键、时间、来源可见性。不按昵称或时间猜路由。没有可靠归属的历史走已授权的未归类入口，不自动挂入某个群。既有时间线继续只追加，不通过清理历史改写时间线。
2. **隔离原文。** 停止把新消息正文写入长期索引、导出知识包或生成逐条 `experience`；旧消息在各记忆入口（目录、全文、提取词、向量重排候选、相关证据的隐式返回）均不能成为检索命中。不清空旧库、不新建无界正文副本。需要看原文时，显式查询平台历史并重新检查来源权限。清理只处理指定账号/会话、截止边界内的历史，提供预览/确认；事实与证据定位分开，清理后显示证据不可用，不用缓存正文复原。
3. **增量总结。** `utils` 不负责此任务。总结器官只从有权处理的同一会话窗口取新消息；之前同范围已采纳的净化摘要是只读参考。显式提供发言者、消息 ID 和真实图片组件目录；历史无图片目录时传空，不能编造图片证据。规划与管理预览只用合成资料。用模板的 `summary/entities/relations/facts` 结构，增量而非全量重写；多会话不能拼成一个人的画像，不让 bot 发言独自成为用户事实。模板沿用固定版可核验的措辞并登记来源，根目录用户原稿不打包。
4. **提交与召回。** 一次事务写增量与来源、更新对应窗口游标；同窗口并发/重放不得重复。已成功且明确“四空”的协议结果推进游标但不生成事实。模型失败、格式错误、引用本窗口之外的图片或虚构端点不得作为成功批处理。只从有来源、有效且获准使用的派生事实召回；模型输出不能写人格或自动给图授权。更正保留历史痕迹，不把已替代值与最新值并列供回复使用；无法确定更正对象时不做破坏性合并。

## 验收场景

- [ ] 用不同账号的同名会话和两个相似昵称验明：平台只返回授权对象的原消息，记忆搜索原句、导出知识包都不返原消息；非消息事实仍可查。
- [ ] 只上一轮提及的稳定事实不会重复新增；确认更正只呈现新结论，示例、猜测和机器人单方陈述不作用户事实。验证结构和证据约束的作用，不把提示词当作事实真实性的保证。
- [ ] 两个消息都有组件 `0` 时只能通过消息 ID 和组件路径的组合关联。无图、缺失、跨窗口和被清理的引用不串图。
- [ ] 区分合法无增量与错误响应；中断、重放与并发只提交一次；检查 `save_batch` 原有的逐项 experience 分支及错误降为 `[]` 的旧路径都不再漏过约束。
- [ ] 清理预览数量与确认范围一致；新来信不因旧确认而删除；没有测试操作正式库。新路径遵守既有开关、预算及可见性，不直接调用真实模型。

不做：覆盖正式库、修改旧时间线、把模型生成的画像当作身份事实、在看不到原文时虚构证据。

## 子步骤 1 · 平台历史读法

会话页从已保存的收发原件开始，再按时间线序号接上有完整回址的旧入站记录。收件箱序号和时间线序号不是同一个命名空间；跨到旧记录后须连同 `next_before_source` 传回独占游标。不用显示名或事件时间匹配，不把平台迟到事件挪进已经翻过的游标区间。同会话的同一平台消息键以收件箱原件为准，旧记录重投不重复展示。平台确认但没给有效消息键的旧外发无法补记；也不把仅生成或排队的回复当成已发。

已登录且改过初始密码的维护者可单独浏览「未归类历史」。旧时间线仅在本来对用户可见、且缺少可用回址时进入此入口；有明确其他账号的记录不降格为未归类。已迁入的 `mai_messages`/`messages` 从已有原件按导入序号读取，不使用全文索引，也不把原表主键或人物昵称当作平台消息键。旧迁移投影未保留缺失的真实会话、账号或可见性，接口明确留空，不读取原 MaiBot 库来猜配。没有补录已经不可得的发送回执或附件组件。
