# 3.15 · 从平台历史提取增量事实

状态：平台原文隔离、增量总结与历史清理已合入；派生事实检修按[生命周期任务](3.15-resource-lifecycle.md)继续。对应总任务 4 的消息边界和 5，与 9 的滚动摘要独立。来源、清理与实机验收分别见文末交付和[历史操作](3.15-history-actions.md)。先读 `aureus/memory/{index,resources,history,consolidation}.py`、`aureus/heartbeat/{inbox_store,memory_consolidation}.py`、`aureus/attention/inbox.py`、`Summary prompt.txt` 及[固定版对照](3.15-parity.md)。

## 基线与发布顺序

1. **先保证平台可查。** 当前目录同时纳入 live 的 `message` 和迁入的 `mai_messages`/`messages`，`MemoryIndex.search` 的提取词命中还会返回证据原文。接入平台历史读取路径并覆盖存量、新收和已发消息，保留账号/会话/发送者/平台消息键、时间、来源可见性。不按昵称或时间猜路由。没有可靠归属的历史走已授权的未归类入口，不自动挂入某个群。既有时间线继续只追加，不通过清理历史改写时间线。
2. **隔离原文。** 停止把新消息正文写入长期索引、导出知识包或生成逐条 `experience`；旧消息在各记忆入口（目录、全文、提取词、向量重排候选、相关证据的隐式返回）均不能成为检索命中。不清空旧库、不新建无界正文副本。需要看原文时，显式查询平台历史并重新检查来源权限。清理只处理指定账号/会话、截止边界内的历史，提供预览/确认；事实与证据定位分开，清理后显示证据不可用，不用缓存正文复原。
3. **增量总结。** `utils` 不负责此任务。总结器官只从有权处理的同一会话窗口取新消息；之前同范围已采纳的净化摘要是只读参考。显式提供发言者、消息 ID 和真实图片组件目录；历史无图片目录时传空，不能编造图片证据。规划与管理预览只用合成资料。用模板的 `summary/entities/relations/facts` 结构，增量而非全量重写；多会话不能拼成一个人的画像，不让 bot 发言独自成为用户事实。模板沿用固定版可核验的措辞并登记来源，根目录用户原稿不打包。
4. **提交与召回。** 一次事务写增量与来源、更新对应窗口游标；同窗口并发/重放不得重复。已成功且明确“四空”的协议结果推进游标但不生成事实。模型失败、格式错误、引用本窗口之外的图片或虚构端点不得作为成功批处理。只从有来源、有效且获准使用的派生事实召回；模型输出不能写人格或自动给图授权。更正保留历史痕迹，不把已替代值与最新值并列供回复使用；无法确定更正对象时不做破坏性合并。

## 验收场景

- [x] 用不同账号的同名会话和两个相似昵称验明：平台只返回授权对象的原消息，记忆搜索原句、导出知识包都不返原消息；非消息事实仍可查。`test_history_rechecks_complete_scope_and_visibility`、`test_same_window_once_and_image_not_interchangeable`、`test_platform_originals_do_not_enter_memory_catalog_search_or_exports`：通过，分别验证会话授权、相似昵称的消息定位、搜索及导出边界。
- [x] 只上一轮提及的稳定事实不会重复新增；确认更正只呈现新结论，示例、猜测和机器人单方陈述不作用户事实。验证结构和证据约束的作用，不把提示词当作事实真实性的保证。`test_correction_retains_history_and_rechecks_route_under_transaction`、`test_context_cannot_be_self_evidence`：通过，拒绝旧窗口来源和重复值，更正后旧值不再召回；六种不能独立作证的上下文均被拒绝。
- [x] 两个消息都有组件 `0` 时只能通过消息 ID 和组件路径的组合关联。无图、缺失、跨窗口和被清理的引用不串图。`test_same_window_once_and_image_not_interchangeable`、`test_text_only_message_cannot_borrow_image`：通过，错消息、错组件、窗外引用均被拒绝；无图原句可以作文字证据，但不能借图；删除原件后不再召回。
- [x] 区分合法无增量与错误响应；中断、重放与并发只提交一次；检查 `save_batch` 原有的逐项 experience 分支及错误降为 `[]` 的旧路径都不再漏过约束。`test_only_explicit_empty_advances_and_cancel_does_not_consume_window`、`test_same_window_once_and_image_not_interchangeable`、`test_failed_cursor_write_rolls_back_accepted_facts`、`test_legacy_extracted_terms_return_only_fact_and_evidence_pointer`、`test_sleep_consolidation_keeps_messages_out_of_legacy_sorting`：通过，只有合法四空推进空批次，竞争提交只成功一次，写游标失败时事实一并回滚，旧整理入口不从消息生成候选。
- [x] 清理预览数量与确认范围一致；新来信不因旧确认而删除；没有测试操作正式库。新路径遵守既有开关、预算及可见性，不直接调用真实模型。`test_confirmation_rechecks_auth_only_removes_fixed_scoped_originals`、`test_platform_summary_respects_gates`、`test_web_and_qq_consume_separate_originals_and_recall_only_same_scope`：通过，确认后迟到消息及其他账号原件保留；同一合成私聊仅在整理和提取均开启、网页通道已挂载且未透支时调用假器官；网页与 QQ 原件和游标按权限分别处理。

## 子步骤 1 · 平台历史读法

会话页从已保存的收发原件开始，再按时间线序号接上有完整回址的旧入站记录。收件箱序号和时间线序号不是同一个命名空间；跨到旧记录后须连同 `next_before_source` 传回独占游标。不用显示名或事件时间匹配，不把平台迟到事件挪进已经翻过的游标区间。同会话的同一平台消息键以收件箱原件为准，旧记录重投不重复展示。平台确认但没给有效消息键的旧外发无法补记；也不把仅生成或排队的回复当成已发。

已登录且改过初始密码的维护者可单独浏览「未归类历史」。旧时间线仅在本来对用户可见、且缺少可用回址时进入此入口；有明确其他账号的记录不降格为未归类。已迁入的 `mai_messages`/`messages` 从已有原件按导入序号读取，不使用全文索引，也不把原表主键或人物昵称当作平台消息键。旧迁移投影未保留缺失的真实会话、账号或可见性，接口明确留空，不读取原 MaiBot 库来猜配。没有补录已经不可得的发送回执或附件组件。

## 增量总结第一轮复审 · 待修改

`918aef0` 已实现事务游标、QQ 会话证据与图片复核，但不能按其当前协议交付。原稿允许自然的叙事性增量、一般的已确认知识、双方共同明确的事实和窗内最终更正；不能要求每条来源以「我」开头、需要逐字复写全条发言、每个事实固定以「昵称：」开头或摘要严格等于事实逐行拼接。保留有界且实际存在的来源和片段，而不是拒绝合法输入来防止污染。明确否认/纠错应按最后一次确认取最终值，不能把整句含「不是」的更正一律丢弃；引用片段与发言者自己新写的正文分开。旧值不和新值同时召回，撤权、无结构、越界证据和机器人独自发言仍须拒绝。按原稿的实体与关系形状核对预览和实际解析，若额外需要来源元数据，在同一格式内明确，不要让提示词和校验互相矛盾。

网页私聊也是当前会话来源：以自己通道、已验证用户和 `user_only` 精确建窗，原件定位与 QQ 分开，不能把不同通道或 QQ 私聊按可见性合批。正式送达的机器人消息可以作上下文，不能作用户事实；取消/失败和内部出箱草稿仍不入窗。不要为此让原始聊天重新进入长期索引。新增合成用例覆盖非第一人称的确认、自然叙事、多发言更正、同窗否定旧值、两条消息同位置的图片、独立网页与平台游标，并在包含平台桌面和入场水位的主线基线处理整合冲突。
