# 3.44 平台会话左侧列表与右侧窗口等高

状态：完成
设计：维护者 2026-11-26 指令

## 目标

平台会话页左侧的会话选择列表高度与右侧会话窗口一致，底部对齐，不留短一截。

## 实现

1. `aureus/web/static/index.html`：调整 `.inbox-layout` 网格与左右卡片高度（`align-items: stretch`、`height: 100%` 或 `min-height` 对齐），列表内部滚动。
2. 窄屏保持上下堆叠，不强制等高。

## 实现记录（2026-11-26）

- 根因：`.inbox-conversations` 的 `max-height:65dvh` 把左侧列表封顶在 585px（1280×900 实测），右侧会话卡片到 758.81px，底部短 173.81px。`#inbox-layout` 虽然已有 `align-items:stretch`，但左侧被 `max-height` 限制，所以两栏没有真正等高。
- `aureus/web/static/index.html`：
  - `.inbox-layout` 的 `align-items` 由 `start` 改为 `stretch`，与后面的 `#inbox-layout` 规则一致。
  - 去掉 `.inbox-conversations` 的 `max-height:65dvh`，改为 `min-height:0;overflow:auto`，列表在卡片内部滚动。
  - `#inbox-layout` 增加 `grid-template-rows:minmax(0,1fr)`：左右两栏共用同一行，行高等于页面剩余高度，长列表不会把行撑高。
  - `@media(max-width:680px)` 覆盖 `grid-template-rows:auto`，窄屏保持上下堆叠和原有的 30dvh 列表上限，不强制等高。
- 取舍：没有加 JS 高度计算，全部用网格/弹性布局；窄屏沿用原来的 `max-height:30dvh`，只在桌面取消 65dvh 上限。窄屏堆叠时列表轨道仍会分到少量剩余高度，列表卡片被 30dvh 封顶后留下空白（改动前也是这样），本次未改。
- 只改了 `index.html`；没有改后端、`frontend/`、`aureus/organs/`。
- 提交：`61406cc`（只含 `aureus/web/static/index.html`）。
