# 3.33 恢复切页过渡动效，不影响缓存

状态：完成
设计：D133、D129（docs/10-decisions.md）

## 先读

- `aureus/web/static/index.html`：`showPage`、`startPageEntrance`、`pageEntrance`、`state.entranceSeen`（性能收尾时加的「只首次播放」逻辑）、页面缓存与预取。

## 目标和验收

1. 每次切换页面都播放原来的入场动画（淡入 + 轻微上移），不再只在本次登录首次进入时播放。
2. 缓存内容立即出现，动画只是视觉过渡；不重新请求数据，不改变预取、缓存 TTL 与写后失效。
3. 减少动态偏好（`prefers-reduced-motion`）时仍然不播放动画。
4. 切页期间没有明显卡顿或长任务；窄屏与深浅主题正常。

## 改动一览

- `aureus/web/static/index.html`：去掉「已播放页面」跳过逻辑，恢复每次切页播放；必要时限制动画元素数量。

## 行为细则和边界情况

1. 动画只作用于当前页面容器与首屏可见元素，避免整页文字扫描造成长任务；可沿用现有 `startPageEntrance` 的可见性观察。
2. 缓存命中时先渲染内容，再启动动画；动画不得延迟内容可交互时间。
3. 快速连续切页时取消上一页动画，不叠加。
4. 不做：改变缓存、预取、页面数据加载逻辑。

## 实测与偏差

### 环境

- 原定 18770 隔离实例正被另一个子智能体使用（数据根 `E:/Temp/aureus-ui-review-327`，网页密码未知）。为避免互相干扰，复制 `E:/Temp/aureus-ui-review` 到 `E:/Temp/aureus-ui-review-333`，只在副本里删除网页密码哈希恢复默认密码并改成测试密码，端口改为 18773；原 18770 数据根与正式实例 28976 均未重启、未修改。这是与任务文档「端口 18770」的偏差。
- 手测用 headless Chrome + CDP（脚本 `E:/Temp/transition-qa/qa_transition.py`），1280×900；测缓存命中时关掉预取（`__aureusSetPagePrefetch(false)`），避免预取请求混入计数。截图存 `E:/Temp/ui-shots/`。

### 实现说明

- 去掉 `state.entranceSeen` 与「本次登录只播一次」的分支，`showPage` 每次都调用 `startPageEntrance`。
- 先调用页面的 `load`（缓存命中时同步渲染内容），再启动入场动画；异步读到的内容仍由原有的 `entrance.scan()` 补上。
- 扫描改为按元素树遍历：整棵不可见的子树直接跳过（滚动到页面底部的长列表不会先耗尽预算），复合控件和带直接文字的元素作为整体入场并跳过其子树；每次最多收集 120 个目标、检查 4000 个元素。可见性仍交给原来的 `IntersectionObserver` 做错峰。
- 与原来的差异：入场只作用于首屏可见元素，滚动后才出现的元素不再补动画；这是任务「动画只作用于当前页面容器与首屏可见元素」的要求。
