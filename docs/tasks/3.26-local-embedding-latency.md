# 3.26 本地嵌入直连并复用连接，降低测速延迟

## 目标和验收

本地（回环、免费、OpenAI 兼容）嵌入模型的测速延迟与直连一致（毫秒级），不再包含客户端创建和 litellm 开销。

验收：

1. 回环且免费的 OpenAI 兼容嵌入服务商直接走 HTTP `/embeddings`，不经 litellm；远程嵌入与其它协议不变。
2. 嵌入请求复用同一个 `httpx.AsyncClient`（连接池），不再每次新建；进程退出或器官关闭时关闭客户端，不产生未关闭连接告警。
3. 测速延迟只统计实际请求（发出到响应），不含器官构造、密钥解析、客户端创建；同一模型连续测速的延迟稳定在毫秒级（本地假服务）。
4. 安全网关的预算、权限与用量记账不变；本地嵌入仍按现有规则豁免预算。
5. 失败路径（连不上、非 2xx、返回格式异常）与现有行为一致。

## 改动一览

## 行为细则和边界情况

1. 判定「本地」沿用 `local_expression_endpoint` 的严格规则：回环地址、无用户信息/查询/片段、无价格；不解析 DNS、不走代理。
2. 共享客户端按事件循环惰性创建；关闭时释放。若器官没有关闭钩子，在进程退出路径补一个。
3. 计时：在 `client.post` 前取时间，收到完整响应后结束；器官构造在计时之外。
4. 图片嵌入同样走直连（本地 chinese-clip 等），避免每次新建客户端。
5. 不做：改变嵌入模型选择、改变向量空间、改变测速的输入内容。
