# 路线图 3.6b · 设置逐项恢复默认

状态：实现中

先读 D91、D89、3.6a、网页配置接口与设置表单、安装时生成的配置和运行时加载入口。

## 子步骤

1. 按已有网页设置表单列出有项目默认值的可编辑参数，覆盖基础、高级、模型和器官等配置。记录默认来源、用户覆盖位置、加载时机。Prompt 交由 3.6a，生化参数交由 3.8，集成时一同验收。
2. 每项提供可键盘操作的“恢复默认”按钮，调用与编辑相同权限的后端。只删除该键的覆盖，重新读取当前版本默认。保留同组其他设置、未知键及用户数据。后续开发仅修改工程默认来源。检查新安装、旧配置、保存另一个字段是否意外把默认值固化为用户覆盖。
3. 用临时数据根目录从真实入口核对逐项修改、恢复和重启。显式写入的旧配置保留，来源无法判明的旧值按显式覆盖处理。

## 网页参数盘点

| 页面与实际表单 | 有默认值的可恢复项 | 默认来源、覆盖和加载时机 |
|---|---|---|
| 设置 `cfRow` | `RuntimeConfig` 的网页可编辑标量。包括通用、心跳与回复、身体、激素、心情、人际、同理心、判断、反馈、日程、主动联系、兴趣、探索、记忆、日记、人设成长、时间、快照、安全、网页各节。字段按后端 schema 逐项渲染，恢复权限沿用字段编辑权限。 | `aureus/common/config.py` 的配置模型声明默认值。`config/aureus.toml` 保留显式键，`load_settings` 启动时读取，网页从同一配置模型取当前文件值。生理变量的只读范围与展示由 3.8 交付。 |
| 设置 · 界面字体 | 界面字体。 | 网页默认字体为像素字体，浏览器 `localStorage` 的 `aureus-font` 存覆盖，打开页面时读取。 |
| 模型 · API 供应商 `openProviderEditor` | 请求地址、超时、失败重试次数。地址缺省时由协议客户端决定，并沿用修改地址的密码确认。 | `aureus/organs/model_config.py` 的 `ProviderConfig`，覆盖写到 `config/models.toml` 对应 `[[providers]]`。启动时 `load_models_config` 读取，网页保存后 `ModelRuntime` 热更新。 |
| 模型 · 模型 `openModelEditor` | 类型、视觉、输入价、输出价、缓存命中输入价、温度、回复 token 上限、支持的思考等级。 | `ModelConfig`，覆盖写到对应 `[[models]]`。温度和 token 上限继续按调用协议处理空值，缓存价空值沿用输入价。加载和热更新同上。 |
| 器官详情 `openOrganEditor` | 模型顺序表、思考等级、温度、回复 token 上限。 | `OrganConfig`，覆盖写到对应 `[organs.<器官名>]`。温度和 token 上限空值继承模型设置。加载和热更新同上。器官策略有代码默认，当前网页表单只展示和编辑模型顺序。 |

运行设置的格式版本、网页开关、监听端口和远程开放开关沿用文件编辑限制。供应商名称与协议、模型名称与标识符及供应商是条目定义必填项。添加表单的初选协议和生成名称只是录入辅助。身份与人设、账号、凭据及其引用、历史和运行命令沿用原界面。Prompt 由 3.6a 交付。

`aureus init` 只建目录，不写运行配置和模型配置。运行配置示例只供查阅和手动覆盖，模型示例中的供应商、模型和路由都是示例条目。网页新建条目时，从开发默认继承可选字段；旧文件里已写下的值按显式覆盖处理，即使恰好等于旧默认值。

## 自检

- [ ] 各页有默认的可编辑设置逐项有恢复入口，盘点能对应到实际按钮。身份正文、账号、凭据、历史记录与运行命令不参与通用重置。
- [ ] 两项自定义只恢复其中一项，验证磁盘、返回值、重启后的实际加载值及另一项的值。
- [ ] 改动一个开发默认并重新加载，未覆盖和已恢复的项跟随更新，其余显式自定义保留；重复恢复同一项有效。
- [ ] 用浏览器验证编辑、恢复、刷新、权限和错误显示；专项检查通过。
