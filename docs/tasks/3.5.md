## 交付

1. 明确读取 3.2 产物，按实例和来源键发布历史消息、段落、episode、事实、证据、关联以及照片描述等可用记忆。保留原文、说话人、时间和时间精度、溯源指针及状态。对缺失、失活、矛盾、删除与过期记录区分归档和有效召回。组装证据链时处理孤立引用，逐表对账。媒体文件与原始附件按可验证引用归档至私有目的目录，保留找不到文件的准确诊断，导入不执行文件内容。
2. 迁入的资料和日后积累的资料属于一个记忆库。按人物、时间、查询词和相关性召回，允许一次查询找到来自群聊、私聊和无会话号的经历。检索和刷新在真实调用链工作，沿用时钟与容量预算。已有时间线仍只追加，不伪造过去发生在 Aureus 的事件。
3. 对照 MaiBot 启发式记忆注入和显式 query_memory 两条路径，将适量的有出处材料送达 Planner 或 Replyer。验证 Replyer 实际收到符合当前查询的材料，不能依赖上游关闭的 retro prompt。保留原库与核心事实，可由原数据重建使用的全文或向量派生索引。涉及外部嵌入与模型调用的验证使用本地模拟。
4. 在独立工作树先做可独立验证的记忆存储、状态过滤、检索和证据格式。3.2 接口就绪后用正式包及暂存表走通发布。按积累量触发整理，避免心跳同步扫描全库。

## 实现对照

- A_Memorix 2.0.0 的 `metadata_fact.py::list_current_person_fact_claims` 按有效状态和左闭右开时间段取当前事实。适配点为 `memory/history.py::search_history`，用 Aureus 时钟判断有效期。原件可按来源读回，全文索引是可重建的 SQLite 派生表。
- MaiBot 1.3.15 中 `heuristic_injector.py::build_injection_message` 和 `query_memory.py::handle_tool` 均调用 `MemoryService.search`。Aureus 启发式入口独立开关默认关闭，开启后用本轮回忆提示构造词项，搜索走后台线程。显式查询仍采用 Planner 建议，Replyer 优先使用显式结果。两条入口沿用 D80 的条数和 900 字预算。
- 从安装版 `MemoryService.get_person_profile` 追到 `person_profile_service.py::query_person_profile`：非空人工正文优先于自动结果，自动快照仍保留。该服务的别名覆盖行存在即采用人工列表，空列表也有意义；`person_profile_active_persons` 只记录已开启范围的活跃人物。自动快照按 `profile_version` 选最新版并检查有效期。两类人工覆盖应由 3.2 以业务行导出，均按 `person_id` 对账；其他人的画像归 3.3 整合。
- `publish-memory` 读取 3.2 已校验的 `sources` 与 `source_rows`，逐表核对已导出条数。已有实例绑定主库、记忆库和源时区指纹。由明确指定的 `--target-home` 决定运行库，原件和索引一起发布，时间线不追加历史事件。
- 对照 MaiBot 的 `database_model.py`，消息以 `mai_messages.timestamp` 为发生时间，单独保存可空的 `received_at`。以 `platform` 和 `user_id` 对应人物，以 `platform` 和 `message_id` 解析回复来源。正文优先取 `raw_content` 的文本组件，缺少原文时使用 `processed_plain_text`。消息原始组件、原有聊天流与完整原值可按来源键追溯到 3.2 私有暂存快照。
- 对照 `metadata_schema.py`、`metadata_fact.py` 与 `episode_service.py`，按 `episode_paragraphs`、`paragraph_relations`、`fact_evidence` 对应段落和关系，保留已删除及孤立指针。图片观察沿 `image_observations.occurrence_id` 查找出现记录，通过 `asset_id` 查找资产，以 `chat_id` 和 `message_id` 对应唯一的主库消息。D92 允许缺失证据的有效正文参与召回，同时保留缺失引用诊断与已知来源。失活链接和已替换、已删除的图片观察可作为归档读取。
- 对照 MaiBot 的 `MessageUtils.from_db_record_msg_to_MaiSeq` 和 A_Memorix 的 `ImageAssetStore`，用 MessagePack 解码消息组件，按 `images.image_hash` 或 `image_assets.content_hash` 核验指定的 `full_path` 或 `storage_key`，按 SHA-256 写入目标附件目录。对于 `images.no_file_flag` 已设置的行，报告 `attachment_marked_missing` 并保留可用描述。内嵌文件按已有字节归档，外部 URL 和平台文件 ID 只存引用。找不到文件、缺少根目录、越界和哈希不符各有诊断。安装版 `format_migration.py` 用于旧派生格式升级，本步骤以 3.2 现有业务行重建全文索引。

## 发布

```powershell
uv run aureus migrate-maibot publish-memory <暂存库> --instance <实例> --source-timezone <源时区> --target-home <独立目标>
```

先将主库和记忆库用 3.2 CLI 导入同一暂存库。源时区用于解释不带时区的 MaiBot 时间。可用 `--main-media-root` 和 `--memory-media-root` 指向已授权的本地源附件目录。逐表报告只显示数量，附件的具体未解析引用保留在目标记忆原件。横跨历史与新经历的排序先看命中的词数，再看时间。心跳按 `index_batch` 增量推进其时间线索引。
