## 脚本加载顺序实验（未合入）

[原始记录](timeline-defer-experiment.json)：基线仍为 `e19c411`，另两组从 `2edb930` 导出相同产品静态文件（与 `91ac346` 的 `aureus/web/static` 一致）。实验组只把独立 `/assets/timeline-live.js` 移到 `<head>` 并用 `defer`，将首次 `enter()` 放到 `DOMContentLoaded`，让它在实时函数声明可用后启动。无拼接、无预加载，资源路由未改。24 轮按六种顺序轮换，每组 24 个冷样本，无脚本异常。

模块请求开始中位从 23.75 ms 提前到 14.65 ms，响应结束从 60.10 ms 提前到 41.75 ms；但实验组与未改候选的**配对差值中位**，`DOMContentLoaded` 仅 −1.20 ms（−44.80 至 +62.90），总览响应仅 −2.40 ms（−44.60 至 +62.90）。对 3.64 基线的配对中位仍是 +2.05 ms 和 +0.50 ms。提前拿到模块不等于提前看到总览；没有足够证据表明这一改动有稳定收益，保留产品原来的顺序。

## 本地复跑

需要已安装 Chrome、仓库的离线 Python 环境，以及已有的 3.64 回环夹具 `build/ui364/`（`audit_preview.py`、`ui364_asgi.py`、`fake_preview.py`，不随产品发布）。在主仓库目录运行；输出必须是新文件。将 Chrome 路径按本机安装位置调整。

```powershell
& .\.venv\Scripts\python.exe -I -B -X utf8 docs/tasks/evidence/3.66/browser_ab.py --candidate 91ac346 --fixture build/ui364 --chrome 'C:/Program Files/Google/Chrome/Application/chrome.exe' --output build/366-c4-replay.json
& .\.venv\Scripts\python.exe -I -B -X utf8 docs/tasks/evidence/3.66/browser_ab.py --candidate 2edb930 --fixture build/ui364 --chrome 'C:/Program Files/Google/Chrome/Application/chrome.exe' --output build/366-c4-defer-replay.json --defer-timeline
```

`browser_ab.py` 启动独立浏览器和夹具，`browser_ab.js` 记录页面指标并验证节点和游标。脚本只使用合成数据与临时资料目录，不读取用户数据、密钥或已登录浏览器；浏览器外部请求被禁用或定向到不可达的本地代理。复跑会得到新的计时值，不会重写此处的原始 JSON。
