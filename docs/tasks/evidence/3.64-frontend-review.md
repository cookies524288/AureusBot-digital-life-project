## 三、缓存与性能

- 用 HTTPX 0.28.1 的进程内传输调用独立静态路由，未启动 Aureus；工作台静态入口复用产品注册函数，鉴权依赖使用合成就绪状态，不代表完整服务中间件的表现。
- 在这台机器的候选副本上，`workbench.js` 为 **1,686,944 B**，`workbench.css` 为 **296,446 B**。分别带上第一次响应的校验标记或最后修改时间再次请求，仍是 `200`，两份正文共 **1,983,390 B**，不是免传正文的 `304`。
- 现有路由和 `tests/web/test_learning_assets.py` 明确要求 `Cache-Control: no-store`。同时宿主脚本有「已挂载就返回」和「正在加载时共享请求」两道判断，因此不能说每次切页都重传这 1.98 MB。本轮未改静态资源策略，也没有给敏感或实时数据加持久缓存。
- 宿主逻辑补测（Node VM，非浏览器）：在两版内容相同的 `resource-management.js` 中执行实际学习工作台加载函数与重试监听器，合成 `fetch`、模块导入和页面节点。两个同时进入的调用共享同一进行中的任务，只请求 1 次 CSS、导入 1 次 JS；同一文档随后再进 5 次，新增 CSS 请求和 JS 导入均为 0，挂载节点未被替换。首个 CSS 请求报错时显示重试，点已绑定的重试后才发第二次 CSS 并导入 JS。未执行工作台包、未测其数据请求、浏览器磁盘缓存或加载耗时。
- 复核 `30d4678` 和 `e19c411` 的 80 个发布静态文件，只有 `index.html` 改动，其他 79 个在两份预览中的原始字节相同。按 Git 中统一 LF 换行的正文计，入口从 420,383 B 到 429,099 B，增加 8,716 B；没有把 Windows 检出换行或压缩前文本字节当作浏览器传输量。

### 采样口径（流程）

本轮按下面的口径执行了冷打开、重开和文档内切页；后台恢复与减少动画没有执行，慢响应只做了 P 场景的 A/B。

- **页面显示的判据**：首页须出现数据填入的运行状态，而非只看到页头；时间线须读到指定记录；学习须从主导航进入，等 `#learning-workbench-host` 内的 Shadow DOM 显示一条合成表达记录，不以“加载中”消失或脚本下载完成代替可读。交互取点击至目标内容出现在画面上的时间。打开页面的首屏绘制（FCP）和最大内容绘制（LCP）只记在该次整页导航，不能复用于文档内切页；取不到记「缺失」，不是 0ms。
- **实际输入与可见性**：在 375px 和 820/821px 两侧，将长标题、末尾标记、未读数与「关闭／返回」一起检查；控件滚入视口后，点其可见中心并确认命中的是该控件或其子元素，再用 Tab 和 Enter/空格复测。放大文字至 200% 并检查右侧操作是否仍可达。后台恢复必须观察浏览器实际发出的隐藏/显示事件；在页面脚本里直接改 `document.hidden` 只算模拟测试。
- **对照**：固定浏览器版本、窗口、缩放/设备像素比、字体、主题、样本及预取设置。每种情形两边各至少 5 次，奇数轮先原版、偶数轮先候选。冷打开使用没有这两端口缓存的新隔离会话；同一文档切回、同一会话重新打开文档、后台恢复、确定性慢响应分别成组。没有实际观测到页面隐藏及恢复的样本不计入前台恢复。只用审查自己的标签页，不清个人浏览器的缓存。
- **每次留存**：版本与页面、样本和顺序、有效/失败及原因、首屏和目标内容时刻、应用请求数、工作台 CSS/JS 请求数、浏览器报告的传输字节。区分成功、零请求、请求被取消、超时和未返回；合成延迟单列。每组同时展示成功数/尝试数、中位数与最小–最大值。未打开页面时不生成测量行，统计启动失败也不等于一次慢加载。
