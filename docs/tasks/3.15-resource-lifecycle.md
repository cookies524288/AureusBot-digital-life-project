# 3.15 · 事实、画像、关系与纠错的管理

状态：待评审。对应[管理工作台](3.15-resource-console.md)。先读 D99、D100、D103、[总结协议](3.15-memory.md)、[展示授权](3.15-graph.md)；在固定版 `knowledge-base/tabs/`、`routers/memory.py` 和内置 A_Memorix 服务之间对照查询、详情、纠错预览、应用和撤销的调用。

1. **查询和证据。** 记忆查询按事实、画像、情景等展示已有迁入资料与新生成的事实，统一用不可变来源键，区分事实/证据定位。总结事实由 `memory/summary_store.py` 按完整会话与可见性存储，读取时复验授权、存续状态、是否已被替代以及平台/网页原件，不将原文复制进资料或索引。用来源显示区分「不可见」「没有证据」「已更正」；本来无权知道存在的对象只能当作不存在。切检修保留页码、筛选和草稿。
2. **实际召回。** D100 允许跨会话内部记住有来源的正常事实，不是扩大网页浏览权。对能验证来源和当前有效性的派生事实，同一路规范化候选进入 planner 的 `query_memory` 与 replyer 的已选材料，沿用既有防泄漏提示，不回填原文、旧值或私有图详情。明确的来源授权撤回、移除、过期和事实替代即时生效。无真实来源的泛化叙述不直接作为事实；默认不开新图展示。
3. **非图形维护。** 在同一检修工作区对可信键编辑事实状态、画像正文/别名/证据，管理关系的冻结、保护、可逆移除/恢复，支持情景定位和可撤销的纠错。先生成带原件版本的预览，确认时在同一事务复查来源和权限；过期预览或恢复时的新冲突不能覆盖新值。原件和审计留痕、派生读侧一致。调优显示实际影响以及已有配置/检索器的作用域，不做空按钮或永久删除。

自检：同名不同人不合并、无权不能按编号枚举；私聊 A 的获准派生事实可进入群 B 的合成请求但不会附 A 的正文；更正、回收、恢复及撤权影响网页、内部召回和授权导出。关系图新 UI 不在本任务范围内，不读正式库、不做真实外发或模型调用。

## 连续撤销与旧预览

同一来源只允许撤销最近仍生效的操作，并复核该操作应用后的原件和覆盖。撤销较新操作后，若原件和覆盖也都匹配，下一条才可撤销；即使两次操作得出相同值，也不能越过中间操作。应用和撤销都会在同一事务内作废该来源其余未执行的预览，值改回也不恢复。画像按可信来源组作废；旧别名入口改动则同时阻止覆盖该别名的待撤销计划。其他来源的计划不受影响。
