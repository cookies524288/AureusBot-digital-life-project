## 目标和验收

1. at 段指向 bot 的消息算提及；正文包含身份全名或任一昵称也算提及（大小写不敏感；英文按词边界，中文按子串）。
2. QQ 消息保存到收件箱前写入 `mentioned`，时间线元数据和提示词里的「点名你」对名字提及同样生效。
3. 提及消息立即唤醒心跳，并进入优先未读；不要求发送者是绑定用户或特别关心。
4. 提及不抢占当前会话；绑定用户和特别关心来信仍抢占（D95）。
5. 停机期间收到的提及在重启后按优先未读补收。
6. 规划器仍按 D95 决定回不回；不保证一定发言。
7. 预算、权限、急停、回复决策、收件箱权限不变。

## 接口

- `mentions_bot(perception: Perception, names: Sequence[str]) -> bool`：先看 `perception.mentioned`；否则对 `perception.content` 做大小写不敏感匹配。ASCII 名字用 `(?<![a-z0-9])name(?![a-z0-9])`；非 ASCII 用子串。空名字跳过。
- `Heartbeat.bot_names() -> tuple[str, ...]`：`(facts.name, *facts.alias_names)`。
- `QQChannel(..., bot_names: Callable[[], Sequence[str]] = lambda: ())`。
- `InboxStore.list_mentioned_unread(conversation, *, after_id: int | None = None, limit: int = 50) -> list[InboxMessage]`：`mentioned = 1`、`trust != UNVERIFIED`、未读、按 id。
- `InboxAttention.is_priority(perception) -> bool`：已验证的用户/特别关心，或 `perception.mentioned`。
- `InboxAttention.preempts(perception) -> bool`：只有已验证的用户/特别关心。

## 行为细则和边界情况

1. at 段已经由 `read_message_segments` 解析；名字匹配只在 `mentioned` 为 False 时补充，避免重复。
2. 名字匹配使用当前身份的 `facts.name` 和 `facts.alias_names`；身份改动后下一次消息立即使用新名字。
3. 空字符串、纯空白、与全名相同的昵称不参与匹配（与 `describe_aliases` 的清理规则一致）。
4. ASCII 名字按词边界，避免 `Aureus` 命中 `AureusBot`；中文按子串，短昵称可能误命中，文档写明。
5. QQ 客户端显示的昵称不在 `identity.toml` 里；要它也触发，把它加进 `alias_names`。
6. 提及消息在 `priority_messages` 里与用户/特别关心一起返回，但 `preempts` 为 False：不中断当前会话，等当前会话结束再处理。
7. 重启后 `priority_messages` 会补收未读提及；已经处理过的消息按时间线去重。
8. 提及的队列优先级：`_take_in_perceptions` 把 `is_priority` 的 CONTACT 升级为 `Priority.SPECIAL`；只影响排队顺序，不改变用户/特别关心的抢占。
9. 不真实调用模型；测试用假器官和手动时钟。
