# 3.49 修复网页重启后回不来、启动器不接管已运行实例

状态：完成
设计：维护者 2026-11-26 指令

## 问题

在网页里点「重启」后页面进不去；再次双击 `Aureus.exe` 也不进入正在运行的进程，而是显示「Aureus 启动失败：另一个 Aureus 实例正在运行」。

## 目标

本阶段只做启动器与重启后端（网页重连遮罩拆到 [3.50](3.50-web-restart-overlay.md)）：
1. 已有实例在运行时，双击 `Aureus.exe` 直接打开该实例的网页（接管/附着），不显示启动失败页。
2. 重启流程完成后，新进程正常持有单实例锁与端口；只有确实无法启动或连接时才显示失败页。

## 先读

- `scripts/WindowsLauncher.cs`、`scripts/build-launcher.ps1`：启动器如何启动内核、失败页如何出现。
- `aureus/cli/windows_launcher.py`、`aureus/cli/debug_restart.py`：单实例锁、重启身份校验。
- 网页「重启」入口（`index.html` 与对应接口）与 `/api/status`。
- 日志：`aureus_home/data/logs/aureus.log` 的重启前后行（只看错误与状态）。

## 实现方向

1. **启动器附着**：启动前检测已运行实例（单实例锁或端口探测）；若在运行，直接用默认浏览器打开其网页并退出，不启动第二个内核；失败页只在探测到无实例且启动失败时显示。
2. **锁与端口**：复用现有单实例锁与 `[web] port`，不新增端口配置；不绕过锁。
3. **重启后端**：核对网页重启入口触发的进程替换，确保新进程接管后锁与端口正常，不残留旧进程。
4. 不改内核启动参数、数据目录与安全设置；本阶段不改 `index.html`。

## 验收

- 网页点重启后自动恢复；双击启动器时若已有实例则打开网页；两个实例不会同时运行；无实例时启动器正常启动；失败页只在真实失败时出现。

## 实测记录

隔离实例：数据根 `E:/Temp/aureus-349`，端口 18771，假器官，独立密码；没有碰正式实例（28976）。手测脚本放在 `E:/Temp/aureus-349-harness/`（harness3/4/5、timeout_test、failure_test），不进仓库。

- **附着**：用 `scripts/build-launcher.ps1` 从同一份源码构建 `Aureus-349-test.exe`，在项目根目录运行（能定位 `.venv`）。实例运行时再启动一个启动器，第二个启动器进程保持运行、`MainWindowTitle` 为空（没有失败对话框），端口只有一个监听者；Python 层同时打印 `AUREUS_WEB_ATTACH=<owner> <url>` 后退出 0。
- **同时双击**：两个启动器几乎同时启动，最终只有一个监听者，两个启动器都存活，没有失败对话框。
- **重启窗口**：先启动实例，再让它以退出码 75 结束（重启），同时启动一个新的普通启动器和一个 `--restarted` 启动器；普通启动器接手启动、`--restarted` 启动器附着，最终只有一个监听者。对应 `aureus/cli/windows_launcher.py` 中 30 秒的等待循环。
- **网页重启**：经 `/api/login` 登录后 `POST /api/restart`，2.1 秒后 `/api/status` 的 `restart_instance` 变为新值，旧监听进程已退出、新监听进程接管 18771，首页返回 200；随后 `/api/shutdown` 让启动器和内核正常退出（退出码 0）。
- **真实失败**：先占住 18771 再启动启动器，内核绑定端口失败，启动器约 3.9 秒后以退出码 1 结束（失败页路径）；释放端口后能正常启动。
- **优雅关闭超时**：用临时 FastAPI 应用挂一个 300 秒的请求，调用 `WebServer.request_stop()` 后 10.2 秒返回（uvicorn 取消挂住的请求），不再无限等待。
- **根目录 `Aureus.exe`**：C# 源码没有改动；正式实例正在运行，根目录 exe 被系统占用，无法覆盖。用同一脚本构建的临时 exe 完成了上面的双击实测，测完已删除。启动器逻辑在 Python 侧，现有根目录 exe 下次启动就会加载新代码，不需要重建二进制。
