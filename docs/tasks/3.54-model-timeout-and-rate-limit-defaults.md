## 目标和验收

1. 服务商默认超时 120 秒；显式配置的超时继续生效。
2. 判断超时默认 120 秒；显式配置继续生效。
3. 失控拦截的每分钟频率限制默认不限：不写 `max_calls_per_minute` 与 `model_test_calls_per_minute` 时不拒绝任何调用；显式写上限时仍按器官分别统计，模型测速使用自己的上限。
4. 连续失败暂停与 `model_test` 豁免不变；预算、记账、权限、急停、并发许可不变。
5. 网页模型测速和供应商网络测速的请求超时按服务商超时与探测项数推算；普通接口仍是 10 秒。
6. 示例配置、06/15 号文档、设置页说明与 D135 一致。

## 接口

- `SafetyConfig.max_calls_per_minute: int | None = None`，`ge=1`；`None` 表示不限。
- `SafetyConfig.model_test_calls_per_minute: int | None = None`，`ge=1`；`None` 表示不限。
- `JudgeConfig.timeout_seconds: float = 120.0`，`gt=0`。
- `RunawayGuard._max_calls_per_minute(organ_id) -> int | None`：`model_test` 返回 `model_test_calls_per_minute`，其它器官返回 `max_calls_per_minute`。
- `api(path, method, body, headers, signal, detached, timeoutMs = API_TIMEOUT_MS)`；`apiRequest` 同样接收 `timeoutMs`。
- 前端 `probeRequestTimeoutMs(model)`：按 `model.kind`、`vision`、`reasoning_levels` 与服务商 `timeout_seconds` 计算。

## 配置

- `[safety] max_calls_per_minute`：不写表示不限（默认）；写了必须是 ≥1 的整数。
- `[safety] model_test_calls_per_minute`：同上。
- `[judge] timeout_seconds`：默认 120，必须大于 0。
- 服务商 `timeout_seconds`：默认 120，必须大于 0；显式值优先。

## 行为细则和边界情况

1. 不限流时不记录调用次数，避免内存随调用增长；显式设上限后按原来的 1 分钟窗口统计。
2. 模型测试只受自己的上限；只设回复上限时，模型测试仍不限。
3. 失败暂停照旧；`model_test` 的失败不累计，成功会清零。
4. 前端推算超时：llm 的探测项数 = 2（text、tools）+ 视觉 + 思考等级数；嵌入、图片嵌入、转写各 1 项。文本探测可能先流式（首包最多 20 秒）再非流式，所以按「所有项各一次完整超时 + 文本额外一次」估算，再加 30 秒余量。这个值只用于网页等待，不改变后端超时。
5. 供应商网络测速用「服务商超时 + 30 秒」。
6. 网页超时仍会中止请求并提示；切页取消、去重和缓存逻辑不变。
7. 不改用户已显式写入的超时值；示例配置只改注释和示例默认值。
8. 不真实调用模型；测试用假客户端、假时钟和 `httpx.MockTransport`。
