# 05 · 人际与跨平台身份

> 目标：它和每个人都有真实的一对一关系，不管对方用哪个平台。

---

## 1. 三个概念

| 概念 | 是什么 | 例子 |
|---|---|---|
| 人 | 一个真实的人，在 AureusBot 里有唯一的编号 | 小王 |
| 账号 | 某个平台上的一个身份：平台 + 平台给的用户 ID | QQ 上的某个用户、微信上的某个 ID |
| 关系 | 它对这个人的印象和相处历史 | 认识半年、很熟、信任度高、喜欢聊游戏 |

一个人可以有多个账号；关系属于"人"，不属于账号。

---

## 2. 识别规则

- **只认账号 ID，不认昵称。** 昵称谁都能改，群里有人改成用户的昵称也没用。
- **新账号就是新认识的人。** 第一次出现的账号，默认建一个新的人物档案。
- **跨平台关联必须验证。** 对方说"我就是 QQ 上的小王"，不能直接信。

---

## 3. 跨平台关联

**方式一：验证码**

1. 对方在已经关联的账号上（比如 QQ）向它要一个一次性验证码；
2. 再在新平台（比如微信）上把验证码发给它；
3. 对上了，就把新账号关联到同一个人。

**方式二：用户确认**

用户在观察台把两个账号合并成同一个人。

**规则**：

- 不允许只凭对方自称就合并；
- 合并可以撤销，合错了能拆开；
- 合并、拆分都记入时间线。

---

## 4. 用户

- 用户的账号写在身份配置里，只有用户能改；
- 网页通道需要登录，登录的就是用户；
- 任何人自称用户一律不认；
- 只有来自已验证用户账号的指令，才算用户的指令。

---

## 5. 关系印象

**档案里有什么**：

- 怎么称呼对方；怎么认识的、什么时候认识的；
- 熟悉度、信任度、好感；
- 互动频率和最近一次互动；
- 关系摘要、重要事件、对方的偏好；
- 它对对方的承诺（同时记在日程里）。

**印象怎么形成**：

- 来自真实互动的积累：反馈层的观察、睡眠整理时的总结；不由单条消息决定；
- **熟悉度**按真实的互动量计算；
- **信任度** = 用户设定的基础值 + 互动历史（比如对方说话算不算数）。器官可以提出调整建议，但由规则限幅采纳。
- **好感** `affinity`（0 到 100，满分 100）：它有多喜欢对方，决定同理心的强弱（D44）。没有档案的对象按陌生人的默认值算。来源是用户设定的初值、互动量、互动好坏；越高越难涨、越低越难跌，永远到不了 0 和 100（D66）。

动物也可以有档案，比如用户的宠物：没有账号，由用户在观察台建档，或者在聊天里被提到时按名字关联（需要用户确认）。

---

## 6. 信息边界

这是"像一个靠得住的人"的基础：不把甲的秘密告诉乙。

- **每条时间线记录和记忆都带可见范围**：
  - 私聊：只有对方和它知道；
  - 群聊：这个群里的人知道；
  - 用户的私事：默认不对任何人透露。
- **群聊与私聊共用一份记忆。** D89 延续 D61、D80 的统一检索。规划器和回复器可依说话人、时间和内容选取跨通道经历。消息发送仍经过既有安全网关。
- **例外需要用户授权**，比如用户同意它把某件事告诉某个朋友。
- **可见范围从第一天起就记录。** 早期记下来几乎没成本，事后补会非常麻烦。

---

## 7. 同一个它

它在不同场合可以调整说话方式：群聊里活泼一点，私聊里细腻一点。但记忆、关系、身体状态始终是同一份。

---

## 8. 分阶段实现

| 阶段 | 内容 |
|---|---|
| Phase 0 | 时间线记录可见范围 |
| Phase 1 | 按账号建档；识别用户；组装上下文时按可见范围过滤 |
| Phase 2 | 关系印象随互动更新；好感（供同理心使用，D44） |
| Phase 3 | 跨平台关联（验证码、用户确认）；信息边界完整版 |
